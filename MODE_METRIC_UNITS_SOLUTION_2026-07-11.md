# Решение: KPI-паспорт — единый канал единиц и формулировок для всех режимов

**Дата:** 2026-07-11 · **Этап:** 2 (утверждённый дизайн) · **Статус:** утверждено Антоном, реализация не начата
**Основание:** `MODE_METRIC_UNITS_AUDIT_2026-07-11.md` (Этап 1 — карта дефектов, 5 типов)
**Родственные INV:** INV-31 (физединицы не маскировать под валюту — это его системное расширение),
INV-01 (расширение реестра = schema change → propagation-план ниже), INV-33 (живой прогон до выпуска),
INV-50 (нет данных — нет утверждения), INV-30 (Manager: один выбор режима).

---

## Принцип (канон)

DRY: знание «в чём измеряется результат» должно иметь ЕДИНСТВЕННОЕ авторитетное представление.
Сейчас оно размазано по ~10 файлам в 2 языках → дрейф и рубли в режиме упаковок.
Решение: **KPI-паспорт (display-контекст)** — единственный канал, через который ЛЮБОЙ слой
(UI, инсайты, PPTX, HTML) получает единицы, названия метрик и формулировки. Прямые литералы
«₽ / ROI / упак» вне белого списка — запрещены и ловятся гейтом.

## Утверждённые продуктовые развилки (решения Антона, 2026-07-11)

1. **Обучающий контент** (глоссарий/тултипы/HTML-справка): добавить к денежным примерам
   по примеру для count и effectiveness. НЕ полная параметризация под режим, НЕ игнор.
2. **Count без ценности единицы (vpcu):** честная деградация — вердикты «убыточен/окупается»
   исчезают, остаются относительные сравнения («лучший CPU 80 ₽/лид, худший 420 ₽/лид»)
   + мягкая подсказка «задайте ценность лида — появится анализ окупаемости».
   Ценность НЕ обязательная, дефолт 1 ₽ отвергнут (опасные ложные вердикты).

## Архитектура — 7 компонентов

### 1. Расширение SSOT-реестра единиц (`kpi_registry.py`) — закрывает ось B
Каждому KPI добавить:
- `unit_forms: (one, few, many)` — «упаковка / упаковки / упаковок» (русская плюрализация)
- `unit_axis` — «Упаковки» (оси, карточки)
- `unit_per` — «₽/упак.» (CPU-подписи)
- `unit_compact` — «упак.» («5,8 млн упак.»)
Для monetary — валютные формы. Для `count_custom` — дефолт «ед.» + **project-level override**
(пользователь вводит своё слово в UI, хранится в project.json как `custom_unit_forms`).
Плюс `currency_symbol` в паспорте (дефолт ₽) — задел мультивалютности, без UI сейчас.
**Масштабируемость:** новый KPI = одна запись реестра; кастомная метрика = пользовательский ввод.

### 2. Один физический словарь — `kpi_display_registry.json`
Данные (единицы, подписи, шаблоны фраз) — в одном JSON. Python читает напрямую,
фронт импортирует (Vite JSON-import). Убивает класс ошибок «дрейф зеркал» (доказан багом Тип 1).
Логика (плюрализация, инверсия CPU) остаётся кодом в 2 языках; паритет держит **contract-тест**:
Python генерирует golden-матрицу «(kpi_type × mode) → все подписи/фразы», vitest сверяет с JS.

### 3. Семантическое разделение форматтеров (затраты ⊥ результат)
- `formatSpend(n)` — всегда ₽ (бюджеты/затраты — деньги в любом режиме)
- `formatKpiValue(n, ctx)` — значение результата: «5,8 млрд ₽» / «5,8 млн упак.» / «12 400 лидов»
- `formatChannelMetric(n, ctx)` — ROI «1.50×» / CPU «80 ₽/лид» / Доля «25%»
`formatMoney` → deprecated alias; новые вызовы ловит линт-гейт. Семантика в имени = меньше ошибок выбора.

### 4. Фразовый каталог для заготовленных суждений
~70 денежных шаблонов (insights-rules.js; decomposer/channel_action/optimizer/inverse;
aurora_pptx/builder.py; aurora_html/sections.py) переводятся на центральные phrase builders:
- Python: расширенный `utils/kpi_labels.py` (единственный поставщик фраз для PPTX/HTML/движков)
- JS: расширенный `kpi-aware-formatting.js` (единственный поставщик для insights-rules.js)
Каждая фраза = функция(данные, паспорт) с 3 ветками (monetary/count/effectiveness) В ОДНОМ месте.
Самодельные f-строки с «₽/ROI» в генераторах — запрещены.

### 5. Пороги и вердикты (Тип 5) — мост «виртуальный ROI»
- count + vpcu задан: `virtual_roi = ratio(ед/₽) × vpcu(₽/ед)` → размерность ₽/₽ →
  существующие пороги 0.5/0.8/1.0 корректны БЕЗ изменения.
- count без vpcu: вердикты окупаемости невозможны → деградация (решение Антона выше).
- effectiveness: только доли, никакой окупаемости.
Единая точка: `channel_verdict(ratio, паспорт) → enum + фраза` в decomposer.py; фронт-зеркало симметрично.

### 6. Три контура защиты от регрессии («на будущие периоды»)
a. **Contract-тест зеркал** (п.2) — дрейф JS↔Python = красный тест.
b. **Унит-линт:** тест гоняет генерацию инсайтов/PPTX-текстов/HTML на 3 фикстурах
   (monetary / count-лиды / effectiveness), ассертит отсутствие запрещённых токенов:
   «₽» у значения результата в count; «ROI» во фразах канала при count; «окупается/убыточен»
   при effectiveness или count-без-vpcu. Плюс статический гейт в lefthook: литерал `₽`
   в .svelte/.js вне белого списка форматтеров = отказ коммита.
c. **Кодификация:** новый INV в ENGINEERING_INVARIANTS (расширение INV-31: «любой user-visible
   текст с единицами — только через KPI-паспорт») + ADR в `aurora-meta/ADRs/`.

### 7. Порядок работ — трассирующая пуля
- **Фаза 0 — фундамент:** реестр (+unit-поля) → `kpi_display_registry.json` → contract-тест. + ADR.
- **Фаза 1 — ядро:** фикс `deriveLabels` (баг Тип 1: «Продажи, ₽» в effectiveness, «упак» для
  всех count) + новые форматтеры (Тип 3) + подключение project-override для count_custom.
- **Фаза 2 — tracer-bullet «лиды»:** протащить режим лидов насквозь: UI-карточки/оси → инсайты →
  PPTX → HTML, живой прогон на фикстуре. Вскроет то, что карта Этапа 1 не заметила.
- **Фаза 3 — тираж:** остальные count-типы + effectiveness (почти бесплатно — всё из реестра);
  вердикты/пороги (Тип 5) + деградация без vpcu.
- **Фаза 4 — защита и полировка:** унит-линт + golden-тесты; обучающий контент (примеры count/
  effectiveness в глоссарий/тултипы/справку); живой прогон 3 режимов (INV-33); INV + ADR финализация.

## Критерии приёмки
1. Три фикстуры (выручка / лиды / эффективность): во ВСЕХ поверхностях (UI, инсайты, PPTX, HTML)
   единицы и метрики соответствуют режиму; «₽» остаётся только у затрат/бюджетов.
2. count_custom с пользовательской единицей («визиты») корректно подписан везде.
3. count без vpcu: ни одного слова об окупаемости; есть подсказка про ценность единицы.
4. Contract-тест + унит-линт + lefthook-гейт зелёные и включены в CI-прогон.
5. Живой прогон 3 режимов на реальном/демо датасете (INV-33) — findings triaged.
6. ADR записан в aurora-meta; INV добавлен в ENGINEERING_INVARIANTS.

## Отвергнутые альтернативы
- **Точечные правки найденных строк** — не масштабируется, разъедется через 2 релиза.
- **Полная i18n-система (gettext-каталоги)** — лишний слой для 1 языка / 1 продукта.
- **Ручные зеркала + только contract-тест (без общего JSON)** — дешевле сейчас, но каждая новая
  единица требует синхронной правки в 2 языках — именно это уже породило баг Тип 1.
- **vpcu обязательной / дефолт 1 ₽** — отвергнуто Антоном (ложные вердикты хуже отсутствия вердикта).
