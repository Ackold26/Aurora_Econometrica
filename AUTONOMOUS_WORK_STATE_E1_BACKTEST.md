## Цель E1 (из ROADMAP, дословно)
Витрина «модель vs факт»: rolling-origin валидация (обучение на [1..k] → предсказание
[k+1..k+h] против факта; k скользит). Метрики: **coverage 90%-интервала (главная!)**,
MAPE holdout, сравнение с наивным (модель обязана бить наивный — иначе честно сказать).
Доставка сразу все слои: endpoint + Rust + карточка UI («Проверка на истории: 7 из 8
кварталов в интервале») + слайд PPTX + narrative. Триггер: кнопка «Проверить модель на
истории» (авто при переобучении — см. решение D-1 ниже).
**Критерий готовности:** на Кагоцеле витрина показывает честный holdout-результат;
coverage сверен канарейкой с пересчётом; слайд в отчёте; никакого in-sample вранья.
**Осторожно:** короткие ряды → при N<3 окон «истории недостаточно для проверки».

## RAG-канон (поднят 2026-07-03, батч E1-0)
- **Gelman, Bayesian Workflow §9.4:** cross-validation predictive checking обнаруживает
  меньшие расхождения, чем posterior predictive (in-sample) — канон: доверие модели
  проверяется ТОЛЬКО out-of-sample.
- **McElreath, Statistical Rethinking §7.5:** «fit will always favor more complex models» —
  in-sample fit не годится как мера доверия.
- **Robyn (Meta 2024, arXiv 2403.14674):** out-of-sample validation — индустриальный
  стандарт MMM (ts_validation, NRMSE на test).
- **Hernan/Robins, Fine Point 18.2:** overfitting и cross-validation.
- Термин «rolling origin» — Hyndman (FPP, tscv); книги нет в корпусе — в докстринге
  упоминать как общепринятый термин без псевдоцитаты (verify_external_citation).

## Дизайн-решения (приняты самой, батч E1-0)
- **D-1 Авто-триггер при переобучении — НЕ делать сейчас** (только кнопка + хранение
  результата с пометкой устаревания). Почему: bayesian rolling из N окон = N×34с и больше
  на слабом CPU — авто-запуск удорожает каждое обучение в ~5×, бьёт по E5 «≤30 мин до
  инсайта». Пометка «результат устарел (модель переобучена)» — честная замена;
  авто-связка = E3 (дрейф). Трудозатраты↔эффект: кнопка покрывает ценность слайда целиком.
- **D-2 Окна = кварталы без нахлёста** (h = квартал в терминах гранулярности: M→3, W→13,
  D→90, Q→1? — уточнить при реализации по числу точек). k скользит с шагом h назад от
  конца; min_train = max(12, 2×каналы+4) точек И порог OLS/bayesian тренера.
  N<3 окон → честный отказ «истории недостаточно» (status='insufficient').
- **D-3 Две coverage-метрики из одного прогона:** per-period coverage 90% PI (канон,
  главная) + per-window «квартальный тотал в 90% HDI суммы» (коммуникация «7 из 8
  кварталов»). В UI/слайде ведёт per-window (человеческий язык), per-period — рядом.
- **D-4 Наивные бенчмарки:** naive-last (random walk) + seasonal-naive (если n_train ≥
  сезон и сезонность детектирована). Сравнение с ЛУЧШИМ из наивных (строже к модели —
  честнее). MAPE_model vs MAPE_naive → в вердикт (worse_than_naive — честно).
- **D-5 PI per-period:** bayesian → predictions_ci_low/high из predict_scenario (90% HDI);
  OLS → conformal вокруг точки с confidence=0.9 (единый уровень с HDI; проверить
  фактический уровень auto_intervals тестом, не верить сигнатуре).
- **D-6 Гранулярность из detect_granularity** по датам данных; при confidence<0.6 —
  дефолт M + пометка в результате.
- **D-7 Хранение:** `models/backtest.json` в project_dir (atomic write); PPTX/narrative
  читают его; при отсутствии — слайд НЕ рисуется (никаких wireframe-дефолтов — урок B1
  «замаскированная дефолтом честность»).
- **D-8 run_backtest (старый) НЕ удалять** — хирургия; новый `run_rolling_backtest` рядом,
  общие куски — в приватные хелперы. Врущую строку докстринга про endpoint поправить.
- **D-9 Скорость:** режим окна наследует режим модели (bayesian→bayesian, OLS→OLS).
  Кнопка в UI показывает честную оценку времени. Преждевременных оптимизаций (сокращение
  draws) не делать до зонда реального времени на Kagocel.
