# Правка CPD-88 — Aurora AI Econometrica (2026-08-15)

## Суть дефекта
Форма обратной связи не работала НИ У ОДНОГО продукта линейки и ни разу. Поле «Категория» на
стороне Google-формы — выпадающий список с ответами по-русски («Проблемы» / «Предложения» /
«Вопросы»), а программа слала внутренние значения переключателя латиницей (`problem` /
`suggestion` / `question`). Сервис проверяет значение выбора и отвергает запрос целиком — 400.
Два других поля формы свободные, поэтому отказ выглядел общей поломкой, а не проблемой одного
поля. Реестр: `aurora-meta/CROSS_PRODUCT_DEFECT_REGISTRY.md`, раздел CPD-88.

## Что изменено

### `src-tauri/src/commands/feedback.rs`
- Добавлена таблица соответствий `CATEGORY_MAP: &[(&str, &str)]` (строки 16–32) — переводит
  значение переключателя в ответ, реально существующий в выпадающем списке формы.
- Добавлена функция `pub fn form_category(ui_value: &str) -> Option<&'static str>` (строки 34–43).
- `submit_feedback` (строки ~70–83): перед отправкой переводит `category` через `form_category`;
  если значение не распознано — отправка НЕ выполняется, возвращается `[FB-001]` с внятным текстом
  «Не удалось распознать выбранную тему обращения. Выберите тему заново и повторите.» вместо кода
  ошибки без причины. В форму (`entry.1292211421`) теперь уходит переведённое значение, не сырое.
- Добавлены юнит-тесты `every_ui_choice_maps_to_a_form_answer` и
  `unknown_choice_is_refused_before_sending` (по образцу эталона).

`CATEGORY_MAP` и `form_category` сделаны `pub` (в эталоне DocMaster — приватные): нужно, чтобы
интеграционный сторож (см. ниже, отдельный файл в `src-tauri/tests/`) мог сверяться с ЖИВОЙ
таблицей перевода через линковку с `aurora_econometrica_lib`, а не с её текстовой копией.
Текстовая копия давала бы ложное чувство защиты — её можно обмануть, не трогая сам код перевода.

### `src-tauri/tests/guard_cpd88_feedback_category_map.rs` (новый файл)
Сторож на СТЫК, а не на последствие — главное отличие от «каждая сторона по отдельности выглядит
исправной», из-за чего дефект и не был пойман раньше. Пять тестов:
1. `settings_choices_and_category_map_do_not_drift_apart` — главная проверка: извлекает каждое
   значение `<option value="…">` из блока `<select bind:value={fbCategory}>` в
   `src/routes/settings/+page.svelte` (читается как текст через `CARGO_MANIFEST_DIR`, идиома —
   как в `guard_no_regressed_cpd77_cpd79.rs`) и требует, чтобы КАЖДОЕ имело перевод в живом
   `form_category` (линк с крейтом, не текстовая копия таблицы). Расхождение — падение с полным
   списком забытых значений.
2. `category_map_has_no_orphaned_entries_missing_from_settings` — проверка обратного дрейфа:
   пара в `CATEGORY_MAP` без темы в разметке (мёртвый код после удаления темы из интерфейса).
3–5. Самопроверка разбора разметки (`extract_settings_category_values`): порядок опций читается
   верно, разбор останавливается на `</select>` (не залезает в чужой `<select>` ниже по файлу),
   и — специально под ось мутации — значение без пары в таблице всё равно извлекается (иначе
   главный тест не смог бы его назвать).

### `src/routes/settings/+page.svelte`
Не изменён по итогу (правка отменена после мутационного прогона, см. ниже). Показ ошибки в
интерфейсе уже был готов: `submitFeedback()` (строки 289–303) перехватывает исключение из
`invoke('submit_feedback', …)`, кладёт `String(err)` в `fbError`, `fbStatus = 'error'`; блок
`{#if fbStatus === 'error'}<p class="fb-error">{fbError}</p>{/if}` (строки 819–821) уже выводит
это сообщение человеку. Поскольку `Err(String)` из Rust-команды доходит до JS как строка целиком,
новое сообщение `[FB-001] Не удалось распознать выбранную тему обращения…` показывается без
доработок — минимальное вмешательство, форму и её вид переделывать не пришлось.

## Отличия от эталона Docs Lab (`d9b02ef`)
1. **Видимость `CATEGORY_MAP`/`form_category`**: в эталоне — приватные, сторож живёт в том же
   файле как `#[cfg(test)] mod tests` с `include_str!`. У нас — `pub`, сторож вынесен в отдельный
   интеграционный тест по прямому указанию задачи («следуй идиоме `guard_no_regressed_cpd77_cpd79.rs`»,
   а этот сторож — отдельный файл в `src-tauri/tests/`, линкующийся с lib-крейтом).
2. **Обратная проверка на осиротевшие пары** (`category_map_has_no_orphaned_entries_missing_from_settings`)
   — в эталоне такого теста нет. Добавлена как естественное расширение проверки стыка: если тема
   уйдёт из интерфейса, а перевод останется — не баг сейчас, но стоит заметить явно, а не молчать.
3. **Самопроверка разбора разметки** (3 доп. теста) — в эталоне разбор в 6 строк внутри одного
   теста, отдельно не проверялся. У нас разбор вынесен в функцию `extract_settings_category_values`
   и используется в двух главных тестах — самопроверка нужна, чтобы падение главного теста всегда
   означало реальный дрейф, а не сломанный парсер.
4. **Комментарий на месте перевода**: в эталоне ссылка на дату находки без номера CPD (запись
   предшествовала заведению номера в реестре). У нас — прямая ссылка «🔴 CPD-88 … эталон правки
   `d9b02ef`» для трассируемости назад к реестру.

Отличий в логике перевода/отказа нет — решение взято целиком: таблица соответствий, функция
перевода, отказ от отправки нераспознанного значения с внятным сообщением человеку.
