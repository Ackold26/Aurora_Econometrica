## Legal Center

**(А) icacls** — 1 место, БЕЗ обёртки: `src-tauri/src/session/manager.rs:54-71`, функция `SessionManager::new()`. Вызывается безусловно при **каждом старте** приложения (создание `SessionManager` — часть инициализации). `/inheritance:r /grant:r <домен\\пользователь>:(OI)(CI)F` на каталог `%LOCALAPPDATA%\AIAgency\sessions`. Структура блока идентична Эконометрике до правки — та же логика USERDOMAIN/COMPUTERNAME, тот же `creation_flags(0x0800_0000)`.

**(Б) netstat/taskkill** — ОДНО место, и это живой путь, не миграционный: `src-tauri/src/commands/bridge.rs:139-213`.
- `pid_listening_on(port)` (строка 143) — `cmd`-независимый, но эквивалентный вызов: `Command::new("netstat").args(["-ano","-p","TCP"])`, парсинг вывода на PID слушателя порта.
- `stop_gateway(client, port)` (строка 179) — берёт PID через `pid_listening_on`, затем `taskkill /F /PID <pid>`.
- Вызывается из `ensure_gateway_running()` (строка 332, вызов `stop_gateway` на строке 364) — **живая ветка**, срабатывает, когда нужен резидентный режим (Cloud.ru DeepSeek), а уже запущенный общий шлюз `aurora-llm` поднят без резидентного ключа. Не миграция, не единоразовый запуск — обычный рабочий сценарий переключения режима.
- Прочие `taskkill`-вхождения в Legal (`lib.rs:1737`, `claude.rs:1044`, `pptx_processor.rs:239`) убивают процессы по **уже известному** PID (из `child.id()` текущей сессии) — это не паттерн CPD-77, PID не добывается разведкой через `netstat`/`cmd`.

**Файл состояния с PID** — у Legal его нет ни для одного процесса, порождённого продуктом самим (единственная точка кандидата — общий шлюз `aurora-llm`, который **не принадлежит продукту**: это отдельный, отсоединённый процесс, разделяемый несколькими продуктами Aurora на машине). Это ровно тот случай, который эталон Docs Lab явно исключил из своей правки: «`commands/bridge.rs` НЕ тронут: шлюз общий и отсоединённый, продукт даже собственный порождённый процесс не хранит, аналога файла состояния нет. Нужно отдельное решение, а не догадка.» Legal — архитектурный близнец этого исключённого случая, только он сам его и содержит (у Docs Lab bridge.rs тоже есть, но чинился отдельно от sidecar'ов).

**Функция «процесс наш» (`is_our_process_and_user`)** — не найдена ни разу (`rg -n is_our_process` — пусто). Это отдельная работа, если для (Б) в Legal решат делать полноценный state-file+verify паттерн, а не просто убрать `netstat`.

Ожидаемо: у Legal нет файлов `*_sidecar.rs` того же имени, а `session/manager.rs` не совпадает по контексту достаточно для 3-строчного диапазона патча (используется прямой `LOCALAPPDATA::join("AIAgency").join("sessions")`, а не через общий модуль).

## Оценка трудоёмкости

- **Legal, Creative Hub, Oracle — правка (А) icacls механическая по образцу**, но НЕ копи-патч: во всех трёх один и тот же блок кода в `SessionManager::new()` (тот же алгоритм построения qualified-имени, тот же `/inheritance:r /grant:r`, тот же `creation_flags`), но эталонный `git apply` не проходит ни на одном дереве — различается способ получения `sessions_root` (Legal/Oracle: прямой `LOCALAPPDATA::join`; Creative Hub: `durable_store::app_state_dir`) и отсутствуют файлы `*_sidecar.rs`, которых сам патч тоже касается. Удаление блока icacls по аналогии с Эконометрикой — работа на несколько минут на дерево, ручная, не автоматическая.
- **Creative Hub и Oracle по (Б) — работы НЕТ**: паттерн netstat/taskkill-по-порту в них структурно отсутствует, чинить нечего.
- **Legal по (Б) — единственный сложный случай из трёх**: `commands/bridge.rs` — тот же класс проблемы, что Docs Lab сознательно вынес за скобки своей правки («нужно отдельное решение, а не догадка»). Гейт: у общего/отсоединённого шлюза `aurora-llm` нет собственного файла состояния с PID — заводить его означало бы либо (a) писать PID шлюза в state-файл при спавне (но шлюз общий между продуктами — какой продукт «владелец» файла?), либо (b) явно признать, что для ЭТОГО единственного случая `netstat` — обоснованно оставленное исключение (как `legacy_zombie_by_port_scan` в Docs Lab для миграционного пути), задокументировав решение в коде. Это архитектурное решение, не механическая правка — требует отдельной сессии/согласования, а не может быть закрыто вместе с (А).
