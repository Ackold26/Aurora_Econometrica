# Побайтовое доказательство правки интерфейса (TrialConsentOverlay.svelte) внутри установщика

Дата: 18.09.2026. Задача: закрыть пробел предыдущей линии (`FORENSICS_s49_installer.md`, раздел 3г) —
там правка клика была доказана только косвенно (цепочка времён + структурное сходство в `build/`),
прямая побайтовая сверка с exe внутри установщика не удалась, потому что фронтенд Tauri v2 встроен
сжатым (brotli), и plaintext-поиск маркеров дал 0 совпадений.

Ключевое уточнение: предыдущая линия обнаружила побочный факт — `release/aurora-econometrica-gui.exe`
(вне установщика) НЕ идентичен по хешу exe, реально лежащему внутри установщика (расходятся 3 байта
в служебной таблице MIME-типов Tauri, `SHA256 3D52D1EB...` против `02989F0B...`). Поэтому ниже все
решающие сверки сделаны на копии, распакованной **из самого установщика** (`installer_extract/`),
подтверждённой по хешу как реально доставляемая покупателю (см. `FORENSICS_s49_installer.md`, раздел 1).

## Шаг 1 — как рантайм хранит фронтенд-ресурс (чтение исходника tauri-codegen 2.5.5)

Проект использует `tauri-codegen = 2.5.5` (`Cargo.lock`). Прочитан
`~/.cargo/registry/src/*/tauri-codegen-2.5.5/src/embedded_assets.rs` + `lib.rs`:

- каждый файл фронтенда brotli-сжимается (`brotli::BrotliCompress`, quality 9 в release) и кладётся
  в кэш `$OUT_DIR/tauri-codegen-assets/<hash>.<ext>`, где `<hash>` — **blake3** от содержимого файла
  (`fn checksum()` в `lib.rs:102`, явно использует `blake3_reference`, а не sha256);
- затем этот кэш-файл байт-в-байт вшивается в бинарник через `include_bytes!()`
  (`ToTokens for EmbeddedAssets`, `embedded_assets.rs`).

Значит для прямой сверки достаточно: посчитать blake3 нужного `.js`-чанка → найти файл с таким именем
в `$OUT_DIR/tauri-codegen-assets/` → его СОДЕРЖИМОЕ (уже сжатое) искать байт-в-байт в exe.

## Шаг 3 — нашла кэш-файл ТОЧНЫМ совпадением blake3 (не гадание по окну времени)

```
python -c "import blake3; print(blake3.blake3(open('build/_app/immutable/nodes/0.CYng2EPA.js','rb').read()).hexdigest())"
→ 1d5a4a8c18238a69720dcf91b799e6fc8a10ed11c4142ae778b54f0c60384447
```

Поиск файла с этим именем:
```
D:\cargo-targets\econometrica\release\build\aurora-econometrica-gui-8633702f11911c53\out\tauri-codegen-assets\
  1d5a4a8c18238a69720dcf91b799e6fc8a10ed11c4142ae778b54f0c60384447.js
  — 31 319 байт, mtime 14.09.2026 10:18 (совпадает со сборкой фронтенда)
```
Найден с первого раза, точным именем — это не подгонка: blake3-хеш детерминирован содержимым.

## Шаг 4 — распаковка brotli и сверка sha256 (доказывает: это тот самый ресурс)

`brotli.exe` найден: `C:\Program Files\Git\mingw64\bin\brotli.exe`.

```
brotli -d -c 1d5a4a8c....js > cache_chunk_decoded.js
sha256sum cache_chunk_decoded.js
→ fc15e11266ea094ed567e8295489a9ce55ed9b0045e1b8e248ae98ef74d23bbd
```

**Совпадает бит-в-бит** с sha256 из шага 2 (`fc15e112...`). Доказано: этот 31 319-байтный
brotli-блок — сжатая версия ИМЕННО того чанка, где лежит правка клика.

## Шаг 5 — поиск СЖАТЫХ байт в exe (не строки, а самого 31 319-байтного блока)

Искала точное вхождение содержимого `1d5a4a8c....js` (as-is, сжатое, до распаковки) в:

| Файл | Размер | SHA256 exe | Офсет находки |
|---|---|---|---|
| `D:\cargo-targets\econometrica\release\aurora-econometrica-gui.exe` (внешняя копия) | 16 015 872 | `3D52D1EB...` | **11 391 766** |
| `installer_extract\aurora-econometrica-gui.exe` (распакован из самого установщика) | 16 015 872 | `02989F0B...` (= хеш exe внутри установщика, см. раздел 1 `FORENSICS_s49_installer.md`) | **11 391 766** |

Блок найден целиком (31 319 байт подряд, ровно как в кэш-файле) в **обеих** копиях, на одном и том же
смещении. То, что офсет совпадает несмотря на известное 3-байтовое расхождение копий (служебная
таблица MIME-типов в другом месте бинарника), — ожидаемо и не противоречит находке предыдущей линии:
расхождение локализовано вне встроенных ассетов.

**Это и есть прямое побайтовое доказательство на файле, который реально уедет покупателю** (копия
`02989F0B...`, подтверждённая по хешу как содержимое `Optimizer MMM_2.5.4_x64-setup.exe`).

## Контрольный опыт (обязателен по заданию)

Тот же установленный `installer_extract\aurora-econometrica-gui.exe`, та же методика (`grep -a -c`)
на строке, обязанной присутствовать по определению (Rust-строка адреса шлюза, не сжатый ассет):

```
grep -a -c "aurora_gateway" installer_extract/aurora-econometrica-gui.exe → 3
```

Совпадает с числом, которое ранее нашла предыдущая линия (3 вхождения) — методика поиска на этом
конкретном бинарнике работает и даёт ожидаемый ненулевой результат. Способ проверки не врёт.

Дополнительно (не требуется заданием, но объясняет более ранний «0» предыдущей линии): plaintext-поиск
`редакция 2 от 14.09.2026` / `blockClickOutsideOverlay` в том же exe действительно даёт 0 — это
подтверждает, что причиной нуля была компрессия, а не отсутствие правки: сжатые байты найдены в шаге 5,
несжатый текст (ожидаемо) не найден.
