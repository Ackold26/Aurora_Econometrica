# Handoff блока: хвост находок аудита P0.9 + CPD-40 (SEC-1 и политика кэша входа)

Ветка `feat/econ-canon-p0`, дерево `Dev/Aurora_Econometrica_canon`.
База блока: `3223480`. Записи: `19a4e67` (хвост аудита), `a2532ee` (CPD-40).
Вход аудита — `Projects/audit_s5.diff` (1386 строк).

## 1. Цель блока

Две части. **Первая** — разобрать четыре оставшиеся находки внешнего аудита блока P0.9
(1 High + 3 Medium), три из которых касались гейта «файл-результат не несёт текста отказа», а
одна — раскладки выгрузок по входящим других кабинетов. **Вторая** — закрыть блокирующую клетку
реестра CPD-40 (обход контроля отзыва лицензии и кэширование неверифицированного ответа входа).

## 2. Ключевые инварианты

- **Признак успеха честен так же, как число (INV-50).** Отказ обязан быть виден, но не имеет
  права отменять сделанную работу: занятый файл сообщается событием, ответ советника остаётся.
- **Файл-результат не несёт текста отказа** (CPD-32) — и гейт стоит на КАЖДОМ пути записи.
- **Продукт не создаёт у клиента сущностей, которых в его сборке нет** — раскладка выгрузок
  ограничена кабинетами, видимыми в этой сборке.
- **Направление «выдать наружу» ничего не удаляет в приёмнике** (CPD-39, прежний блок) — и
  дополнение этого блока: **раскладка не воскрешает удалённое пользователем**.
- **Мягкий режим проверки подписи не решает, дать ли доступ** — он решает, что останется на диске.
- **Не обещать в комментариях больше, чем даёт защита:** A-1 не закрыт, локальные часы
  принадлежат пользователю, и это сказано прямо в коде.
- **Каждый сторож проверен мутацией**, включая связь «функция зовётся оттуда, откуда должна».

## 3. Осознанные компромиссы

- **Гейт отказа не срабатывает, если маркер назван в самом вопросе.** Плата: настоящий обрыв
  канала в разговоре ПРО ошибки не будет распознан и ляжет файлом. Причина: обратная ошибка
  дороже — она теряет сделанную работу и вдобавок говорит клиенту неправду.
- **Раскладка помнит разложенное только в пределах сессии** (в памяти, не на диске). После
  перезапуска продукта каждый файл разложится ещё раз. Причина: дисковое состояние здесь дороже
  дефекта, который оно лечит.
- **`copy_dir_into` возвращает имена незаписанных файлов, а не отказ.** Структурный отказ
  (нет каталога, нет прав) по-прежнему отказ.
- **Кэш без подтверждённой подписи живёт сутки.** Следствие: все существующие кэши у клиентов
  после обновления становятся суточными, пока не перезапишутся первым же успешным входом.
- **Режим `Hard` написан, но выключен.** Включение — отдельным выпуском после телеметрии.
- **Часть A-1 CPD-40 не закрыта** — сторона подписывателя, переход обязан быть аддитивным.

## 4. Зоны неуверенности (с них начинать)

1. **Порядок двух проверок статуса в `check_auth`.** Проверка подписи и запись кэша — два
   последовательных блока `if auth_response.status == "ok"`. Между ними ничего не меняет
   `auth_response`, но структура приглашает будущего автора вставить туда правку.
2. **`policy` инициализируется `Unverified` и переопределяется только на пути `status == "ok"`.**
   Для не-`ok` ответов она не используется вовсе, но значение по умолчанию читается как
   «кэшировать коротко» — если завтра кэшировать начнут не только `ok`, умолчание сработает
   молча и не в ту сторону.
3. **Ключ раскладки — имя файла плюс время изменения в СЕКУНДАХ.** Файл, перезаписанный в ту же
   секунду с тем же именем, вторично не разложится.
4. **`route_targets_for` берёт видимые кабинеты из статического списка**
   (`get_cabinet_definitions`), а продукт в бою может строить список динамически из content-pack.
   Для фильтра это безопасно (белый список продукта уже, чем оба списка), но расхождение стоит
   держать в уме.
5. **Гейт отказа сверяет маркер с вопросом по подстроке.** Длинный вопрос, случайно содержащий
   «error:» (например, вставленный клиентом кусок журнала), отключит распознавание отказа для
   всего ответа на этот вопрос.
6. **Клиентский текст про занятый файл перечисляет ИМЕНА файлов.** При большом числе занятых
   файлов сообщение станет длинным; ограничения нет.
