# Аудит B — пульс (внешний аудитор, чистый контекст)

## Задача своими словами
Проверяю запись `a2532ee` (закрытие CPD-40): в приложение добавлена проверка подписи Ed25519 ответа
сервера входа (`crypto/auth_sig.rs`), а в `commands/online_auth.rs` исход этой проверки решает,
писать ли кэш сессии на диск и на какой срок (неделя при верной подписи, сутки при отсутствии
подписи, не писать при неверной). Моя цель — найти пути, которыми подложный ответ всё же осядет
на диске или переживёт сессию; расхождение между подписанным payload и вычисляемой политикой;
поломку совместимости старых кэшей; и нечестные обещания в комментариях (INV-50).

## План
1. Прочитать `auth_sig.rs` целиком (канонизация, разбор ключа, проверка).
2. Прочитать `online_auth.rs` (check_auth, CachePolicy, cache_policy, cache_ttl_secs, save_cache, read_fresh_cache).
3. Найти ВСЕ места записи/чтения кэша сессии в дереве (grep по save_cache / session_cache.json / write).
4. Сверить payload подписи с полями, из которых берётся политика; проверить статусы != ok.
5. Совместимость: разбор старых кэшей без `sig_verified`.
6. Critical/High — подтвердить прогоном `cargo test --lib online_auth`.
