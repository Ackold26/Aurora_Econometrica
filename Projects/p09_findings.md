# P0.9 — колонка Эконометрики в реестре кросс-продуктных дефектов

> Рабочий файл сессии 2026-08-03 (четвёртая, автономный режим `Opus 5 · high`).
> Источник истины по формулировкам — `aurora-meta/CROSS_PRODUCT_DEFECT_REGISTRY.md`.
> Здесь — зонды, доказательства и предлагаемые статусы ДО записи в канон.

## 🔴 Первое, что вскрыл вход: план ошибался в объёме

Промт называл **12 клеток** (CPD-08, 10, 11, 15, 16, 17, 22, 25, 36, 39, 40). Счётчик
`registry-count.py --details` на 2026-08-03 15:26 даёт **21 незакрытую блокирующую клетку**:
CPD-08, 10, 11, 12, 13, 15, 16, 18, 20, 22, 23, 24, 32, 34, 35, 36, 37, 38, 39, 40, 41.

Причина расхождения: реестр вырос с 41 до 42 записей, и соседние линии завели записи,
где колонка Эконометрики проставлена ❓ автоматически (никто не смотрел).

## 🔴 Второе: два блокирующих статуса реестра УСТАРЕЛИ на четверо суток

Правило 5 реестра («починил клетку → обнови в том же ходе») нарушено не нами, но следствие
наше: канон утверждает, что у Эконометрики живут дефекты, закрытые нашей же работой.

## Верифицированные лично клетки

### CPD-08 — предлагается ⚪ НЕ ПРИМЕНИМО
**Находка агента опровергнута личной проверкой.** Агент нашёл в `pptx_processor.rs:826-886`
дефектный детектор (линейная регрессия по индексу категории) и прогнал арифметику: на ряду
[100,10,8,6,5] четыре ложных «high», включая лидера — совпало с контролем реестра.
**Но путь недостижим:** единственный вызов `compute_analytics` (`lib.rs:1060`) стоит под
`if cabinet_id == "media-analyst" && is_slash_command` (`lib.rs:1023`), а
`filter_by_product("econometrica")` отдаёт `Some(&["econometrist"])` (`cabinet.rs:121`) —
кабинета-жертвы в сборке Эконометрики нет. Тот же аргумент уже принят каноном для CPD-17.
⚠️ Основание продуктовое, не вечное: если Эконометрика начнёт шипать `media-analyst`,
клетка возвращается. Записать основание явно.

### CPD-10 — предлагается 🔴 ПОДТВЕРЖДЁН
`claude.rs:46-70` `classify_stderr` знает четыре категории (`RateLimit`, `Overloaded`,
`AuthError`, `NetworkError`); паттернов исчерпания подписочной квоты («usage limit») и
протухшего входа («not logged in», «claude login») нет ни одного. Кода CL-010 в `errors.rs`
нет (`grep CL0(09|10|11)|UsageLimit` = 0). При `None` наружу уходит **сырая английская строка
CLI** (`:434-440`) событием `claude-stream-*` с типом `error`.
Путь живой: облачная редакция шипует кабинет-советник `econometrist` (`cabinet.rs:121`).
⚠️ В локальной редакции (`--no-default-features`) кабинет пуст — там клетка неприменима.

### CPD-12 — предлагается 🟡 ЧАСТИЧНО
Клиентской механики выбора лицензии нет: `license.rs` хранит ровно одну лицензию
(`LicenseFile.license_id: String`, не вектор), `online_auth.rs:39-51` шлёт единственный
`product: "econometrica"` — фильтрация по продукту на входе запроса, а не выбором из набора.
Серверная половина (Deno-функция `/auth`) физически вне этого репозитория — статически ни
подтвердить, ни опровергнуть нельзя. Решающий зонд требует стенда с ≥2 лицензиями на одном
отпечатке.

### CPD-16 — 🔴 ПОДТВЕРЖДЁН, и он шире записи
- **Основное дерево `Dev/Aurora_Econometrica/sidecar/econometrica/`: 12+ каталогов реальных
  клиентских данных** («кагоцел-рф-ммх-1105-26», «кагоцел-рф--данные-для-эконометрики-…»).
  Бандл забирает их глобом `"../sidecar/econometrica/**/*"` (`tauri.conf.json:35`) —
  данные одного клиента уехали бы ВСЕМ получателям сборки.
- **Дерево канона чисто по клиентским данным**, но несёт балласт: `dist/` **938 МБ**
  (дубль PyInstaller-сборки, рантайм его не резолвит — спавн идёт по
  `sidecar/econometrica/econometrica-sidecar.exe`, `econ_sidecar.rs:272`).
  `_internal/` 911 МБ рядом с `.exe` — законный рантайм onedir, его трогать нельзя.
🔴 **Прямой блокер P0.10.** Перед сборкой: собирать из дерева канона, `dist/` удалить
**в корзину** (не `rm -rf`), после сборки сверить размер установщика с прошлым выпуском.

### CPD-20 — 🟡 ЛАТЕНТНО, подтверждено
`.github/workflows/ci.yml:140` — задание выпуска отключено `if: false`; внутри блок
«Compute SHA256 checksums» на `shell: pwsh` без проверки `$LASTEXITCODE`. Пока задание
выключено, клиентского следствия нет. При включении — тот же дефект, что у CH/LG/DM.

### CPD-22 — требует решения (основание клетки отменено нашей же работой)
Запись обосновывала статус тем, что `methodology_cert.py` — **мёртвый код**. В P0.7 модуль
подключён, сертификат доезжает до клиента. Зонд по клиентским поверхностям:
`verify.auroraai.pro` встречается **только в докстроках самого модуля и в тесте**
(`methodology_cert.py:6,75,104`, `test_methodology_cert.py:93`) — в HTML/PPTX/Svelte
клиентских текстах адреса нет ни одного. То есть **клиенту несуществующий сервис не
обещан**; остаётся внутренняя документация, указывающая на 404.

### CPD-40 — 🔴 ПОДТВЕРЖДЁН
`online_auth.rs:138,223,242` — `cached_at` хранится в обёртке кэша и **не входит в
подписываемый набор**; поля `sig_verified` нет вовсе (грep = 0), то есть часть A-3
(неверифицированный ответ входа кэшируется) не закрыта. Частичное усиление есть: ответ с
`cached_at` в будущем отвергается (`:238-245`) — это ловит перевод часов назад, но не
правку метки на текущее время.

### CPD-41 — 🔴 ПОДТВЕРЖДЁН ДОСЛОВНО
`src/lib/components/ChatPanel.svelte:374-375`:
`await invoke('save_chat_message', {...}); } catch { /* non-critical */ }` — форма совпадает
с записью реестра посимвольно.

### CPD-11 — 🟡 ОТДЕЛЬНАЯ ОСЬ, подтверждено счётом
40 мест `read_excel` в живом коде движка (без `dist/`, `_internal/`, тестов). `keep_links`
параметром pandas не закрывается — запись это уже фиксирует.

## Клетки, разведанные агентами и принятые мной

### CPD-13 — 🟡 класс жив, но последствие не блокирующее
ПДн-фильтра, описанного записью, у Эконометрики нет вовсе (⚪ по букве). **Но тот же корень
найден живым:** в `content-packs/classifier-data.json` семь кириллических образцов
перехвата обычной речи (`^хай\b`, `^пока\b`, `^спс\b`, `^ку\b`, `^здоров[а]?\b`, …)
компилируются в `chat-classifier.js:34-43` и **не срабатывают никогда**.
Проверено лично прогоном в Node: `^хай\b` на «хай» → `false`, `^hi\b` на «hi» → `true`.
Латинские соседи работают и маскируют мёртвых. Лечение (lookaround) проверено там же → `true`.
Последствие — не утечка, а лишний платный вызов на «спасибо». Фоновое, чинится за 20 минут.

### CPD-15 — ✅ эталонный исход (в), с двумя мелкими оговорками
`claude.rs:246-289` — упрочнённый helper изоляции; `--safe-mode` в аргументах нет вовсе
(`:310-315`), `current_dir(work_dir)` стоит ДО манипуляций окружением (`:378`), значит барьер
`work_dir/CLAUDE.md` не снимается. Оговорки (обе уже в бэклоге реестра, не новые):
имя временного файла фиксированное (`:272`) и отказ изоляции «в открытую» — при `None`
`env_remove` уже выполнен, а свой путь не поставлен (`:384` против `:393`).

### CPD-23 — 🟢 покрыто структурно
13 сторожей паритета: `test_mqs_tier_single_source.py`, `test_mqs_tier_rust_single_source.py`,
`test_inverse_cpp_ssot.py` + 10 сторожей интерфейса. Три исторических инцидента ровно этого
корня закрыты регрессией. ⚠️ Полная инвентаризация непокрытых величин не проводилась.

### CPD-24 — ⚪ не применимо
Механики потери разметки нет: справка в PDF рендерится браузером (`build_help_pdf.py`),
надстрочные знаки везде — литеральные символы Юникода («R²»), не теги. Конвейера docx нет.

### CPD-32 — 🔴 ПОДТВЕРЖДЁН ЛИЧНО
`claude.rs:560` `final_text = result_text.unwrap_or(delta_text)` → `auto_save_response`;
единственный гейт перед записью — `final_text.trim().is_empty()` (`:583`). Любой непустой
текст, включая сообщение об обрыве канала, сохраняется как результат и **размножается в три
формата** (`:598-600`). Защиты по содержимому нет (`MIN_MEANINGFUL` = 0 совпадений).

### CPD-36 — ⚪ не применимо
Писателя CSV с данными клиента нет; единственная выгрузка — XLSX через `rust_xlsxwriter`,
где тип ячейки кодируется явно, а не угадывается по первому символу. Пользовательские имена
идут через `ws.write(...)` строкой; два `Formula::new` (`report.rs:1225,1230`) собираются
программно из номеров строк, без клиентских данных.

### CPD-37 — 🟡 СПЯЩИЙ (не «неприменимо»)
Дефект в коде есть дословно: `lib.rs:3174,3182,3190` результаты отброшены, а
`emit_wf_status(..., "done")` (`:3192`) вызывается безусловно; `campaign.rs:474` кладёт имя
в список «скопировано» без проверки `fs::copy`. Для сравнения — одиночный запрос отказ
пробрасывает (`lib.rs:1455-1456`). **Путь спящий:** экран кампаний гейтится `$isCreativeHub`,
у Эконометрики `productType='econometrica'`. Значок ❓/🟡, не ⚪ — по прецеденту CPD-19 MR:
основание временное, команды скомпилированы в общий бинарь.

### CPD-38 — ⚪ не применимо
Ни одна команда не принимает единственный аргумент-структуру с обязательными полями: либо
именованные примитивы (`econ_optimize` — 15 параметров, сверено 1:1 с вызовом в
`OptimizeStep.svelte:1350-1368`), либо `serde_json::Value`, у которого обязательных полей нет.

### CPD-39 — 🔴 ПОДТВЕРЖДЁН ЛИЧНО, самая острая находка прохода
**Продукт стирает у клиента ранее выданные файлы в рутинном сценарии.** Цепочка проверена
по коду целиком:
1. `manager.rs:237` — `open_session` создаёт `work_dir/exports` ПУСТЫМ;
   `:256` — с Рабочего стола восстанавливается **только `inbox`**;
2. `manager.rs:302` — `sync_exports` зовёт `sync_dir_to(work_dir/exports → Рабочий стол/exports)`;
3. `manager.rs:546` — ранний возврат только если источника НЕТ; пустой существующий каталог
   его не даёт; `:558-565` — из приёмника удаляется всё, чего нет в источнике.
Вызывается после каждого ответа модели (`lib.rs:1455` — в основном потоке через `?`,
`lib.rs:1212` — в потоковой ветке). **Сторожей ноль** (`grep` по тестам пуст).
Путь не гейтится ничем: облачная редакция шипует советника `econometrist`, чат — рутинное
действие.
