# Обещания в колоде: из сноски в раздел (2026-08-16)

## Что было

`sidecar/econometrica/aurora_pptx/builder.py`, метод `s11_sources` (слайд SOURCES + MQS),
правая колонка. Блок E4 «сбывшиеся рекомендации» рисовался кеглем 10 (заголовок,
жирный) / 9,5 (примеры), вперемешку с прочими оговорками (надёжность модели,
preflight, provenance mismatch, калибровка, thinness caveat) — визуально неотличимо
от рядовой сноски:

```python
# E4 (2026-07-03): сбывшиеся рекомендации — петля доверия в отчёте.
if self.promises_summary:
    _ps = self.promises_summary
    self._text(..., font=self.sans, size=10, bold=True, ...)   # заголовок
    for _ex in (_ps.get("examples") or []):
        self._text(..., font=self.sans, size=9.5, ...)          # примеры
```

В HTML-отчёте (`aurora_html/sections.py::render_trust_loop`) под тот же E4 уже
выделен полноценный блок с крупным заголовком `<h3 class="trust-h">` и hero-строкой
`Сбылось N · не сбылось M` — часть раздела «ДОВЕРИЕ К МОДЕЛИ» (петля доверия),
куда также входят E1 (проверка на истории) и E3 (что изменилось с прошлого квартала).

## Что стало

Новый условный слайд `s10d_promises` в `builder.py` — третий вставной слайд честности
в секции «Главное» сразу после SCQAR, в том же ряду, что и `s10b_backtest`/
`s10c_generation_compare` (порядок в build(): backtest → gen_compare → **promises**
→ forecast). Это буквально повторяет структуру HTML `render_trust_loop`, где все три
блока (backtest, gen_compare, promises) — один раздел «Петля доверия»; в PPTX это
исторически 3 отдельных вставных слайда, и обещания встали четвёртым в тот же ряд.

Композиция слайда — по образцу `s10b_backtest`: левая колонка — герой-цифра
(44pt serif, было максимум 10pt) `"{kept} из {total}"` + счётчики «Сбылось: N» /
«Не сбылось: M»; правая колонка — до 2 примеров (ограничение задаёт
`narrative_adapter.py:1323` — `_checked[:2]`), каждый 13pt (было 9,5pt) с подписью
«сбылось»/«не сбылось» 11pt bold; внизу — сноска метода 9pt (тот же приём, что и у
backtest/gen_compare). Условие показа не изменилось (`self.promises_summary` — он
уже гарантированно непустой, если задан: `narrative_adapter.py` кладёт его в data
только когда есть хотя бы одно сверенное `kept`/`missed`-обещание, wireframe-режима
нет по построению).

Заголовок слайда честно отражает исход: «все N сбылись» / «N из N не сбылось» /
«сбылось K, не сбылось M» — без псевдоточности.

Механика нумерации (расширена по образцу forecast):
- `self._page_shift` теперь суммирует 4 булевых флага (backtest, gen_compare,
  **promises_summary**, forecast), не 3.
- `s_forecast_plan.slide_num` и TOC-подстрока «в том числе «Прогноз...»» (`s03_toc`)
  пересчитаны с учётом promises — иначе номер страницы прогноза разошёлся бы с
  фактическим слайдом, если promises идёт перед ним в деке.
- TOC-раздел «Главное» (5 пунктов) не получает отдельной подстроки под promises —
  как и у backtest/gen_compare (только forecast имеет TOC-подстроку, это
  сознательный прецедент из P-2 fix 2026-07-16, не трогала).

Старая сноска в `s11_sources` удалена целиком, заменена комментарием-указателем на
новое место (`builder.py`, комментарий над блоком «INV-50 F-DELIVERABLE-1»).

## Решение о форме — почему так, а не иначе

Рассматривала два варианта:
1. **Укрупнить блок на месте** (в правой колонке s11_sources, просто увеличить кегль).
   Отверг: не решает главную проблему — обещания остаются визуально «одной из
   оговорок» среди надёжности/preflight/калибровки, а не самостоятельным доказательством
   ценности продукта (у нас единственных есть проверяемые обещания — конкурентное
   отличие, по словам постановки).
2. **Новый вставной условный слайд в зоне честности «Главное»** — выбрала этот.
   Обоснование: (а) прямое указание постановки «повтори приём условного слайда, как
   «Проверка на истории»»; (б) HTML-эталон буквально держит backtest/gen_compare/
   promises в одном разделе — переносит структурное решение продукта в PPTX без
   изобретения нового приёма; (в) `_page_shift`/TOC-механика уже спроектирована
   расширяемой (форекаст добавлялся тем же способом 2026-07-10), новый флаг
   встраивается в ту же формулу без ломки остального.

Кегль: hero-цифра 44pt (совпадает с backtest), примеры 13pt (крупнее заголовка
блока в остальных вставных слайдах — 9pt category label, но крупнее соседних
табличных строк 9-11pt) — не мельче содержательных блоков колоды.

## Мутация (обязательный шаг, прогнана вручную и откачена)

Физически сломала условие показа прямо в `builder.py::build()`:

```python
# было
if self.promises_summary:
    self.s10d_promises()
# стало (временно)
if True:  # MUTATION-TEST-TEMP
    self.promises_summary = self.promises_summary or {"kept": 0, "missed": 0, "examples": []}
    self.s10d_promises()
```

Мутировала именно то место, где значение реально управляет отображением
(гейт в `build()`), а не соседнюю чистую функцию форматирования. Прогон
`test_promises_slide.py`:

```
FAILED test_no_promises_no_stray_footnote_text — «Проверка рекомендаций» нашлась
       в колоде без promises_summary
FAILED test_promises_slide_added — колода с promises_summary НЕ получила лишний
       слайд (13 vs ожидали 14) — потому что базовая колода уже печатала его
FAILED test_mutation_gate_promises_condition_is_load_bearing — n_mut == n_ref
       (обе колоды получили слайд одинаково) — гейт сработал правильно
3 failed, 6 passed
```

Откатила правку, прогнала снова — 9 passed. Мутация доказывает: тесты реально
проверяют условие показа, а не «слайд существует вообще».
