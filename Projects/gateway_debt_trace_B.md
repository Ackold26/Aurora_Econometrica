## Уточнение 2. Маскирует ли клиент коды 408/425/429/500/502/503/504 под обрыв связи

**Да. Установлено, одной строкой:**

    Decision::Retry => Err(CloudError::Connection(format!("сервис ответил {status}"))),
    // client.rs:1020

Список кодов, попадающих в `Decision::Retry`:

    pub fn decide_by_status(status: u16) -> Decision {
        match status {
            408 | 425 | 429 | 500 | 502 | 503 | 504 => Decision::Retry,
            _ => Decision::Fail,
        }
    }
    // protocol.rs:583-588

То есть **осмысленный ответ сервера и настоящий разрыв соединения — один и тот же вариант ошибки**
`CloudError::Connection`, а значит:
1. один и тот же текст для человека (`client.rs:151-155`) — «Связь с сервером потеряна… работа на
   сервере продолжается»;
2. одно и то же поведение — шесть повторов и 67 с ожидания (`client.rs:922`);
3. настоящая причина («сервис ответил 429») остаётся внутри строки для журнала и до человека не
   доходит никогда.

Последствие называю прямо: если узел отвечает на исчерпание квоты работ кодом 429, покупатель
увидит ровно ту ложь, которую видел на показе, — «связь потеряна, работа продолжается» — при том,
что связь была, а работы не было. Каким кодом узел отвечает на квоту — серверная сторона, здесь
**не установлено**.

## Общий слой: почему тот же класс бьёт Smart Analytica

Механизм «клиент сам отменяет здоровую работу» лежит в интерфейсе и общий по линейке:
- `ChatPanel.svelte:892-907` — предохранительный таймер: по сроку зовёт `invoke('cancel_claude')`,
  а это настоящая отмена задания НА СЕРВЕРЕ (`gateway_executor.rs:157` → `work.cancelled()` →
  `stop_job`, `client.rs:454`);
- сроки `psy.js:171-175`: по умолчанию 90 с, `media-analyst` 600 с, `econometrist` 900 с;
- снимается таймер по событию init (`ChatPanel.svelte:517-521`), которое продукт шлёт **сам себе**
  сразу после старта (`gateway_executor.rs:789-796`);
- конвейерный вход идёт с `suppress_done = true` (`:1257`) → init не шлётся → таймер остаётся
  взведённым и по сроку кабинета отменяет уже принятое задание.

Класс дефекта формулирую так: **признак живости сервера берётся не от сервера, а от собственного
синтетического события.** Отсюда обе крайности: в Эконометрике сторож гаснет в первые миллисекунды
(окно может висеть без присмотра сколько угодно), в конвейерном пути сторож рубит живую работу —
ровно почерк Smart Analytica «202, тишина, отмена клиентом». Конкретные три минуты — из её
собственного `psy.js`, в этом дереве **не установлены**.
