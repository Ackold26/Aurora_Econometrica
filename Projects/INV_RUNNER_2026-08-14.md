# Исполнимая проверка инвариантов Aurora AI — первый инструмент (2026-08-14)

## Зачем

Замер на день постановки задачи: инвариантов в `ENGINEERING_INVARIANTS.md` — 106,
конкретную команду проверки несут 10 из них, инструментов проверки в
`aurora-meta/tools/` не было вообще. 96 правил могли сработать только через
внимание человека в нужный момент — а такая система отказывает систематически.
Повод: правило про докачку при обрыве (INV-71) прожило полтора месяца и не
доехало до соседнего файла того же продукта.

Результат: `aurora-meta/tools/check_invariants.py` — 7 машинных проверок,
8 продуктовых деревьев, таблица «правило × продукт» с тремя состояниями
(пройдено / нарушено / неприменимо), код возврата 0/1 для гейта в конце сессии.

## Семь проверок

1. **Загрузка без `.timeout()` (INV-71).** `reqwest::Client::new/builder` в
   охватывающей его функции содержит маркер записи файла (`File::create`,
   `write_all(`) без `.timeout(`/`.connect_timeout(`/`.read_timeout(` в той же
   функции. Раздельная пара `connect_timeout`+`read_timeout` признана
   равноценной защитой намеренно: у Econometrica `resilient_client()` стоит
   именно так — единый `.timeout()` обрывал бы докачку крупного файла по
   кускам на живом соединении (задокументированный инцидент 26.07.2026).
2. **Инсталлятор без Range-докачки/повтора (INV-71).** Область — только
   `commands/updater.rs` (загрузчик .exe, сотни МБ, ровно тот класс из истории
   INV-71). `content_updater.rs` (загрузка content-pack) сознательно не входит:
   в нескольких продуктах там прямым текстом стоит «Докачки по HTTP Range здесь
   нет намеренно» — design decision для меньших пакетов, не дефект.
3. **Порождение `icacls /grant:r` (CPD-77).**
4. **Разведка процессов `netstat`/`findstr`/`tasklist` (CPD-77/79).**
5. **Проглоченный отказ копирования перед `close_session` (CPD-81).** Область —
   тела функций `persist_step_exports`/`forward_exports_to_inbox` в
   `commands/campaign.rs`: `let _ = std::fs::copy(...)` сразу за которым —
   безусловный `.push(name)`. Это точный признак из карточки CPD-81 в реестре
   (не «файл где-то рядом с close_session» — `close_session` живёт в `lib.rs`,
   а не в `campaign.rs`, так что дословная формулировка задачи потребовала бы
   межфайлового сопоставления; вместо этого проверка целится в само место
   дефекта, ровно там, где Creative Hub его закрыл 14.08, коммит `c6ce875`).
6. **Длинное тире U+2014 в `content-packs/*.json`.** Буквально верхний уровень,
   без рекурсии — причина ниже.
7. **Версия разошлась между `tauri.conf.json`/`Cargo.toml`/`package.json`
   (CPD-85).**

Все проверки над Rust-исходниками работают после отбрасывания комментариев —
приём (посимвольный разбор, строковые литералы сохраняются дословно, номер
строки не съезжает) перенесён из живого сторожа продукта,
`Aurora_Econometrica_thinwt/src-tauri/tests/guard_no_regressed_cpd77_cpd79.rs`,
с python-портом.

## Три бага инструмента, найденные до того, как он успел соврать

Первый прогон дал 350 МБ вывода и почти сплошной FAIL — сам инструмент был
неисправен, а не линейка. Разобраны и исправлены до публикации результата:

- **Char-литералы ломали разбор комментариев на весь остаток файла.**
  `ROSST_AI_Legal_commercial/src-tauri/src/commands/updater.rs` содержит
  собственный тест, разбирающий кавычки: `ch == '"' || ch == '\''`. Кавычка
  ВНУТРИ символьного литерала `'"'` принималась портом за старт обычной строки
  и уводила разбор до первой случайной `"` дальше по файлу — все `///`-комментарии
  после этой точки переставали отбрасываться. Найдено бинарным поиском по
  строкам файла (1914 строк, точка обрыва — строка 391). Добавлена обработка
  символьных литералов (`'x'`, `'\n'`, `'"'`, `` '`' ``, `\u{...}`), лайфтаймы
  не задеты.
- **Окно поиска `.timeout()` смотрело в обе стороны от вызова клиента** и
  ловило несвязанный код ДО него (в `brand.rs` локальная запись `brand.json`
  случалась строкой раньше best-effort POST без ответа-файла) — сузила до
  «вперёд, не дальше конца охватывающей функции» через брекет-разбор границ.
- **Em-dash-проверка утонула в архиве данных Oracle.** `content-packs/` там
  содержит `audience-presets-archive/` — 306 файлов, 3,2 ГБ дампов синтетических
  аудиторий (данные, не клиентский текст). Рекурсивный обход утопил бы отчёт;
  сужено до буквального `content-packs/*.json` без рекурсии.
- **icacls/netstat ловили строковые массивы внутри собственных сторожей
  продукта.** У Creative Hub и Smart Analytica в `session/mod.rs` живёт тест
  `no_external_permission_tools_at_startup` с массивом `["icacls", "/grant:r",
  "netstat"]` — это ДАННЫЕ сторожа, проверяющего отсутствие вызова, а не сам
  вызов. Аналогично у Legal Center в `commands/updater.rs::mod tests` —
  meta-тест, сверяющий текст сгенерированного NSIS-макроса на слово
  `tasklist.exe`. Добавлено исключение тел `#[cfg(test)] mod ... {}` из
  сканирования icacls/netstat.

параллельно шла работа других агентов над теми же классами дефектов, поэтому

## Что найдено (без починки, по прямому указанию)

- **CPD-81 живёт в 7 продуктах из 8** — только Creative Hub закрыл его 14.08.2026.
  Одна и та же проглоченная ошибка копирования перед `close_session` открыта у
  Econometrica, Oracle, Media Radar, PR Studio, Docs Lab, Legal Center, Smart
  Analytica — самое серьёзное из найденного, класс «потеря данных клиента молча».
- **Инсталлятор пяти продуктов (Media Radar, PR Studio, Docs Lab, Legal Center,
  Smart Analytica) не умеет Range-докачку и не повторяет попытку** — обрыв
  сети на скачивании сотен МБ означает начать заново с нуля, вручную. Только
  у Econometrica, Creative Hub и Oracle это решено.
- **`icacls /grant:r` ещё жив в Oracle, Media Radar, PR Studio** — тот самый
  вызов, который 11.08.2026 антивирус распознал как поведение шифровальщика.
- **`netstat`/`findstr` ещё живы в Docs Lab и Legal Center** (в исполняемом
  коде, не в тестах — `parser_sidecar.rs`, `rag_sidecar.rs`, `commands/bridge.rs`).
- **U+2014 в клиентском тексте — Oracle (73 места, почти все в
  `audience-presets.json`), PR Studio, Docs Lab, Legal Center.**
- **PR Studio: версия разошлась** — `package.json` = 0.7.5 против 0.8.5 в
  `tauri.conf.json` и `Cargo.toml`.

## Чего скрипт не умеет (честно, для следующего шага)

- Не проверяет `.part`-докачку буквально (нет ли `remove` перед повтором) —
  только присутствие маркеров Range/retry в файле; тонкую логику самого
  повтора инструмент не разбирает.
- Проверка 5 (CPD-81) целится ровно в форму дефекта у campaign.rs — тот же
  класс в других местах (например, `whisper_model.rs::rename` при откате
  модели) не покрыт: сознательно, чтобы не плодить шум по неродственным
  случаям без отдельной проверки состоятельности каждого.
- Не различает 5 продуктов Aurora Econometrica от 7 Aurora AI по семантике
  правил — набор проверок общий для всех восьми; правила, применимые только
  к одному семейству, потребуют отдельного условия в скрипте.
- Не помечает сами инварианты в `ENGINEERING_INVARIANTS.md` как «проверяется
  скриптом» — по прямому указанию, это отдельный шаг не мой.
- `aurora-econometrica-brand-tracker` (без git) и `aurora-llm`/`brand-hub`
  (без `src-tauri`) не включены в перечень продуктов — инструмент рассчитан
  на Tauri-приложения с идентичной структурой `commands/`.
