# Программа живого прогона на чистой машине — Эконометрика (15.08.2026)

Список того, что **невозможно доказать дёшево**: ни тестами, ни зондом по коду, ни dev-прогоном
через мост. Всё, что можно было закрыть дешёвыми слоями, уже закрыто и сюда не вошло.

**Машина:** без прав администратора, **без установленного Claude Code**, с антивирусом.
**Что взять:** установщик (см. §0.1) и этот файл.

---

## §0. Подготовка — сделать ДО установки, иначе проверять будет не с чем

### 0.1. Собрать свежий установщик 🔴 обязательно

У клиентов сейчас **2.4.9**, а `master` ушёл вперёд на **19 записей**. Прогон старого установщика
проверит вчерашний день. Нужна сборка с текущего `master` (версию поднимать не обязательно —
достаточно пометить сборку как испытательную).

🔴 **Сборка требует доступа к приватному `aurora-platform-core`** — впервые: подключено общее ядро
`aurora_core`. На машине владельца доступ настроен, на новой машине сборки его придётся дать.
**Клиента это не касается** — он получает готовый файл и Cargo не запускает.

### 0.2. Испортить права каталога данных — до установки

```
icacls "%LOCALAPPDATA%\com.aurora.econometrica" /inheritance:r /grant:r "%USERNAME%:(OI)(CI)F"
```
Без этого шага главную проверку §2.1 не с чем будет сравнить: программа чинит права молча, и на
здоровой машине результат неотличим от бездействия.

### 0.3. Записать исходное состояние
* Есть ли на машине `claude` в `PATH` (ожидаемо — нет).
* Полный путь установки: интересует случай `C:\Program Files` и коротких имён (`PROGRA~1`).

## §1. То, ради чего чистая машина нужна прежде всего

### 1.1. 🔴 Продукт без Claude Code — что видит клиент
**Почему дёшево нельзя:** на машине разработки Claude Code стоит всегда; dev-прогон этот путь не
проходит вовсе.
**Что делать:** открыть кабинет-советник и запустить любую команду.
**Ожидаемо:** внятное объяснение, что работа идёт через Claude Code клиента и его нет — не код
ошибки и не пустой экран. В сборке есть строка «Облачный режим не входит в эту сборку — работа
идёт через ваш Claude Code»: она должна дойти до человека, а не остаться в журнале.
**Провал:** «CLI не найден», предложение поставить пакет командной строкой, зависание.

### 1.2. 🔴 Антивирус против новой конструкции снятия движка
**Почему дёшево нельзя:** поведенческий вердикт антивируса — эмпирический факт. Kaspersky снимал
нашу оболочку 10 и 11.08; после этого разведка процессов убрана целиком, но **против правки
антивирус не гонялся ни разу**.
**Что делать:** установить при включённом антивирусе, поработать 15–20 минут, перезапустить дважды.
**Ожидаемо:** ни одного срабатывания, оболочка на диске цела.
**Провал:** файл исчез, карантин, `PDM:Trojan.Win32.Generic`.

### 1.3. 🔴 Снятие настоящего зависшего движка
**Почему дёшево нельзя:** сценарий «падение → перезапуск → номер процесса достался другому» руками
не воспроизводится, тестами закрыт только разбор.
**Что делать:** запустить расчёт, снять оболочку через диспетчер задач (не закрывая окно движка),
запустить программу заново.
**Ожидаемо:** движок опознан своим и снят; в журнале — по какому признаку опознан.
**Провал:** снят посторонний процесс; либо свой не снят и порт занят навсегда.
**Отдельно:** если на машине есть свой Python/Jupyter — запустить его и убедиться, что **он
не тронут**. Это ровно тот дефект (CPD-79), что уехал клиентам в 2.4.8.

### 1.4. Установка без прав администратора
**Ожидаемо:** ставится в пользовательский каталог, работает, обновление проходит.
**Провал:** запрос прав, отказ записи, молчаливая установка «в никуда».

## §2. Проверка правок, которые нельзя увидеть в dev

### 2.1. 🔴 Починка прав каталога (хвост CPD-77)
Сравнить с §0.2:
```
icacls "%LOCALAPPDATA%\com.aurora.econometrica"
```
**Ожидаемо:** после первого запуска наследование восстановлено, SYSTEM и «Администраторы» на месте.
**Провал:** права остались урезанными (правка не сработала) либо список прав переписан целиком
(вернулся дефект `/grant:r`).

### 2.2. Форма обратной связи (CPD-88) — единственная настоящая проверка
**Почему дёшево нельзя:** отправка идёт на живую форму; в тестах и в dev я её сознательно не
дёргала, чтобы не сорить.
**Что делать:** «Настройки» → обратная связь → выбрать каждую из трёх тем и отправить.
**Ожидаемо:** три отзыва дошли, тема видна правильно. До сегодняшнего дня **не доходил ни один и ни
у одного продукта линейки**.
**Провал:** `FB-001`, «сервер вернул 400».

### 2.3. Звука в программе больше нет
**Что делать:** пройти путь, где звук раньше был (отправка сообщения, завершение расчёта).
**Ожидаемо:** тишина; переключателя в настройках нет.
**Особый случай:** если на машине была прежняя версия с включённым звуком — убедиться, что после
обновления звука тоже нет (прежнее состояние жило в памяти браузера).

### 2.4. Версия приложения (CPD-85)
**Ожидаемо:** в «Настройках» — версия установленной сборки; **ложного «вы устарели» нет**.
**Провал:** требование обновиться сразу после установки свежей сборки.

### 2.5. Частичная потеря результатов шага
**Почему дёшево нельзя:** нужен сценарий, где файл занят другим процессом.
**Что делать:** запустить сценарий, во время шага открыть файл выгрузки в Word/Excel и держать.
**Ожидаемо:** шаг завершается, и человек **видит предупреждение** «часть результатов шага не
сохранена» с именами файлов.
**Провал:** шаг рапортует «Готово» молча — это ровно тот дефект, ради которого правка делалась.

## §3. Расчётная часть — в dev недоступна целиком

**Почему:** движок в dev не поднимается (окружение Python без зависимостей расчёта). Значит **весь
MMM-путь дешёвыми слоями не проверен**.

Пройти полный путь на реальных данных: импорт → валидация → модель → декомпозиция → оптимизация →
планирование → отчёт.

Смотреть по дороге:
* числа и единицы (рубли, проценты, доли) — нет ли расхождения между экраном и отчётом;
* формулировки: **«правдоподобный диапазон»**, не «доверительный интервал»;
* выгрузки складываются в папку результатов и **не затираются** при повторном прогоне;
* повторный запуск того же сценария не плодит копий и не теряет прежние файлы.

## §4. Состав поставки — зонд прямо на машине (30 секунд)

```
grep -c -a "content-packs" "<путь>\Aurora AI Econometrica.exe"   # КОНТРОЛЬ, обязан быть > 0
grep -c -a "Облачный режим не входит" "<путь>\...exe"            # обычная поставка: 1
grep -c -a "gateway_executor" "<путь>\...exe"                    # тонкая поставка: > 0
```
🔴 **Контрольная строка обязательна:** если она ноль — зонд промахнулся мимо файла, и все остальные
нули ничего не значат. Я на этом уже спотыкалась сегодня.

## §6. Что вернуть мне после прогона

Достаточно коротко, по пунктам: **что сработало, что нет, и дословно — любое сообщение об ошибке**
(код вида `FB-001`, `TC-GW-…`, `CL-…` важнее описания словами). Если антивирус сработал — время
события и вердикт целиком.
