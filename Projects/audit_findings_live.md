- **monetary/effectiveness регрессия:** для non-count `_contrib_scale` возвращает `(1e6, money_unit)` — прежнее поведение. `_fmt_contrib(v,1e6)` даёт «1.3»/«9.9»/«10» — идентично старому `_fmt_mln(v/1e6)`. Прогнано (Сценарий C): 9.95M→«9.9», 9.99M→«10.0», 10.4M→«10», 0.5M→«0.5». Денежный сценарий не сломан.
- **Обратное домножение `tc_raw=total_contrib_mln*1e6`:** float round-trip /1e6→*1e6 на реальных величинах вкладов (миллионы-десятки млн) даёт погрешность <1e-6 отн. — ниже порога отображения (.1f/.0f). Прогнано (Сценарий B): 7 037 034 → total_contrib_mln 7.037034 → tc_raw 7037034.0 → «7.0». Потери нет.
- **Граничные count:** весь столбец 0 → scale=1.0, итог «0» (Сценарий D, корректно). Малый count 5000 в изоляции → «5 000 лид.» (полное число, не «0.0 млн»). Отрицательный вклад: `abs()` в scale-выборе + `_fmt_contrib` знак сохраняет (`{x:.1f}`). max по `abs(float(v or 0))` — None-safe.
- **insights-rules.js:1566 (зона 2 handoff):** инсайт «Топ-3 драйверов» показывает ПОЛНОЕ число + единица («вклад 1 300 000 лид.»), таблица — масштабированное («1.3 млн лид.»). Не дефект (родственно принятому компромиссу handoff).
