## Почему удаление безопасно

Удаление ветки в git не удаляет записи — оно убирает лишь указатель. Записи остаются
достижимыми, пока на них указывает хоть что-нибудь. Здесь на них указывает сразу три вещи:

1. **Текущая линия** — гейт полноты доказывает достижимость каждой записи из `feat/econ-canon-p0`.
2. **Метки-архивы** — на вершину каждой ветки поставлена метка `archive/<имя>-2026-08-04`,
   и все они отправлены на `origin` (54 ссылки `archive/*` в облаке). Метка держит записи
   независимо от ветки.
3. **Файл-архив** — `D:\Docs\Aurora_Ai\Dev\_branch_archive_2026-08-04\econometrica-all-refs-2026-08-04.bundle`
   (27 МБ, 285 ссылок, проверен `git bundle verify` — «records a complete history»).
   Разворачивается в любой каталог командой `git clone <файл> <куда>`.

Плюс отдельно: метка `pre-merge-2026-08-04` и ветка `backup/pre-merge-2026-08-04` на записи
`ed73f21`, из которой собран выпуск 2.4.4 у клиентов — точка отката всей работы.

## Как удалить, если решишь

По одной, с проверкой перед каждой:

```
# проверка, что ветка действительно внутри (обязана напечатать 0)
git log --oneline origin/<ветка> ^feat/econ-canon-p0 | wc -l
# и что метка-архив на месте
git ls-remote --tags origin | grep "archive/<имя>-2026-08-04"
# только потом
git push origin --delete <ветка>
```

🔴 **Сама не удаляю ни одной** — это решение владельца. Ветки не мешают: они не влияют ни на
сборку, ни на выпуск, ни на работу продукта.

### Разбор двух реализаций `adstock='auto'` — рекомендация

Обе правят `sidecar/econometrica/engines/modeler.py`, обе резолвят «auto» BIC-селектором ДО
`enforce_jax_for_weibull` и обе откатываются на `geometric` при ошибке. Сигнатура селектора —
`select_adstock(file_path, kpi_column, media_columns, date_column=None)`; вызов корректен у обеих.

| | `agent-a0107fe0` (инлайн, +40 строк) | `agent-a56a322e` (функция, +91 строка) |
|---|---|---|
| Где живёт | прямо в теле `train_model` | отдельная `_resolve_auto_adstock()` с докстрингом |
| **Откуда берёт каналы** | **все ключи `adstock_config`** | **только `media_cols`** |
| Аргументы селектора | позиционные | именованные |
| Ранний выход | нет | `if not auto_channels: return` |
| Тест | 195 строк, гоняет `train_model` целиком | 186 строк, вызывает функцию с моками |

🔴 **Различие не стилистическое, а по существу — во второй строке таблицы.** Первая реализация
перебирает все ключи конфигурации: если туда попал ключ, не являющийся медиаканалом, он уедет в
селектор. Вторая берёт список из `media_cols` — источника истины о том, что вообще является
медиаканалом.

**Рекомендую вторую (`agent-a56a322e`)** — по четырём причинам: безопасный источник списка каналов;
именованные аргументы не сломаются при изменении порядка параметров селектора; вынесенная функция
тестируется изолированно и быстро, а не через полный прогон обучения; ранний выход не дёргает
селектор впустую. Плата — файл длиннее на полсотни строк, из которых больше половины докстринг.

Решение за владельцем; сама не применяю ни одну.
