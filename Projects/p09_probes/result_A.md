**Вывод зонда:**

Сам механизм CPD-12 (выбор `.find()` первой из НЕСКОЛЬКИХ лицензий на одном отпечатке, покрывающих ОДИН

которая физически не входит в этот репозиторий (в `supabase/functions/` здесь есть только `content/index.ts`,
никакой auth-EF). Поэтому от чтения кода EC нельзя ни подтвердить, ни опровергнуть, использует ли ИМЕННО
econometrica-ветка серверного SQL тот же дефектный `.find()`-паттерн, что легал-раг у CH, или он у Econometrica
фильтрует сразу по `product` в SQL (как у CH-фикса) — сервер общий инфраструктурный компонент, вне зоны
доступа этого зонда.

**Адрес:** `src-tauri/src/commands/online_auth.rs:39-51,63-79` (детект продукта + payload запроса, механики

**Разбор:** статически EC чист ровно так же, как OR (идентичный вывод «.find()/first()/[0] по лицензиям
нет»). Но само подтверждение или закрытие дефекта требует live-прогона: завести на одном fingerprint ≥2

## CPD-13 — предлагаемый статус: 🟡 (механика ПДн-guard из записи отсутствует; НО тот же корневой дефект найден живьём в другом месте)

**Зонд (часть 2 — есть ли где-то ещё в EC живой `\b`+кириллица, «третья реализация класса»):**

**Живой прогон (Node.js v24, эмпирика, не гипотеза):**
```
хай    -> re.test("хай")=false | re.test("хай как дела")=false
хелло  -> false | false
здоров -> false | false
ку     -> false | false
пока   -> false | false
спс    -> false | false
hi     -> true  | true   (ASCII-контроль — работает)
```
Все 6 кириллических small-talk паттернов из живой конфигурации **никогда не матчат** свои же
целевые слова — ровно механизм CPD-13 (`\b` после кириллической буквы не срабатывает, т.к. по обе
стороны позиции — «не-\w» по ASCII-определению). ASCII-паттерн `hi\b` в той же структуре работает
и маскирует, что кириллические соседи мертвы — дословно совпадает с формулировкой реестра
(«цифровые/ASCII-паттерны в том же фильтре работают»).

**Адрес:** `content-packs/classifier-data.json` (паттерны `patterns.greeting.regexes`,

(компиляция), файл целиком (small-talk перехват).

**Разбор:** по БУКВЕ записи (ПДн-guard) — ⚪ неприменимо, такого фильтра у EC нет. По СУТИ класса
(«`\b` мёртв для кириллицы в JS/Deno regex, компилируется и выглядит рабочим») — 🟡/фактически 🔴-по-факту:
дефект реально существует и подтверждён живым прогоном, но последствие — НЕ утечка ПДн и не блокирующая
