## Разведка (готова, два субагента avsurface + uacsurface)
Полные факты — в предыдущих сообщениях чата. Кратко, самое подозрительное по убыванию:
1. Обфускация строк (`obfstr`) — сильнейший статический AV-триггер, давала НУЛЕВУЮ защиту
   (Supabase anon-ключ публичен по конструкции, URL всё равно видны в трафике).
2. download_update → apply_update через `-Verb RunAs` — классический dropper-паттерн. НЕ ТРОГАЕМ
   в этом релизе (функционал автообновления, менять поведение = риск сломать апдейт у клиентов).
3. Отсутствие цифровой подписи. Инфраструктура готова (`scripts/build/sign_installer.ps1`,
   DryRun с мая, ждёт сертификат ООО), НЕ подключена в CI. Отдельный трек, не блокирует 2.4.6.
4. `taskkill /IM "python.exe" ... WINDOWTITLE eq econometrica*` в NSIS-хуках — мёртвый код
   (WINDOWTITLE фильтр не совпадает у безоконного CREATE_NO_WINDOW процесса) + AV-сигнал + риск
   зацепить чужой python пользователя. УБРАН.
5. Правила брандмауэра `netsh advfirewall` (loopback-scoped) — заведены под корпоративный RDP без
   интерактивного админа (комментарий в файле + история апреля). НЕ ТРОГАЕМ — зондом на живой
   машине не проверить, а промах ломает движок именно на той машине, ради которой правила есть.
6. Пустые VERSIONINFO движка (econometrica-sidecar.exe, PyInstaller 67 МБ) — безымянный файл для
   антивирусов. ДОБАВЛЕНЫ метаданные версии.

## Решения владельца (зафиксированы, не переоткрывать)
- Права администратора (installMode currentUser) — ОТЛОЖЕНО, отдельный трек, НЕ в этом блоке.
- Публиковать 2.4.6 сразу после сборки, без промежуточной проверки антивирусом на живой машине.
- obfstr снять — подтверждено: не защищал ИС (движок/vault защищены другими слоями, obfstr трогал
  только публичный ключ + URL). Защита движка (PyArmor/Nuitka/Cython) — отдельный трек ПОСЛЕ
  решения антивирусной задачи подписью (обфускация Python вместе с обфускацией строк дала бы
  ДВОЙНОЙ AV-триггер — конфликт целей, делать одновременно нельзя).
- XOR-маска ключа подписи (content_sig.rs, CONTENT_MASKED_KEY) — ОСТАВЛЕНА. Реальная (хоть и
  слабая) защита от подмены ключа для поддельных лицензий; слабее как AV-триггер, чем `obfstr`.
- IP узла А может смениться без обновления клиентов: программа ходит на ДОМЕН rag.auroraai.pro
  (резолвится в 37.27.218.187), не на хардкоженный IP — единственный хардкод IP в коде живёт
  только в #[test]-секциях rag_client.rs, в клиентскую сборку не попадает. При смене IP —
  обновить DNS A-запись (снизить TTL заранее), клиентов трогать не нужно.
