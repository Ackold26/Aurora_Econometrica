# Аудит B — находки (запись a2532ee, CPD-40, мягкая проверка подписи ответа входа)

Прогон: `cargo test --lib online_auth` → **15 passed, 0 failed, 1 ignored** (сетевой).
Живые кэши осмотрены: `.thin` — подпись 88 символов есть, поля `sig_verified` нет;
`.local` — подписи нет вовсе (законный путь Unverified подтверждён боем).

## B-1 · High · `online_auth.rs:284-312` (`read_fresh_cache`), доверие держится на самом кэше
Подпись проверяется ТОЛЬКО на сетевом пути (`check_auth:478`). При чтении кэша она не
перепроверяется: срок доверия берётся из поля `sig_verified`, лежащего в том же файле.
**Сценарий:** пишем `%APPDATA%\com.aurora.econometrica\session_cache.json` =
`{"response":{"status":"ok","cabinets":[все кабинеты],"expires_at":"2099-…"},"cached_at":<сейчас>,"sig_verified":true}`
→ неделя полного доступа офлайн; обновляя `cached_at` раз в неделю — бессрочно, без сервера и
без правки часов.
**Почему сторожа не ловят:** `authorize:598 → load_cache:319 → read_fresh_cache` не зовёт
`verify_auth_signature`; сторож связи `check_auth_verifies_the_signature…:826` разбирает исходник
только внутри `check_auth`. Более того, **зелёный тест уже доказывает подделываемость**:
`two_day_old_cache_survives_only_with_a_verified_signature:766` вручную пишет кэш с
`sig_verified: true`, где `response.signature` пуста (`sample_response:660`), — и `load_cache`
его принимает.
Это ШИРЕ авторской оговорки A-1 (`cached_at` + часы): здесь часы не нужны.
**Следствие для INV-50:** `auth_sig.rs:10-11` — «an attacker cannot fabricate a valid response on
the wire OR in session_cache.json» — вторая половина фразы неверна.

## B-2 · Medium · `online_auth.rs:470-477` vs `save_cache:270` — доверие шире подписанного
Подпись покрывает 6 полей (`AUTHSIG-v1|status|fp|product|cabinets|content_version|expires_at`),
а на диск кладётся ВЕСЬ ответ, и `Verified` даёт недельное доверие в том числе неподписанным
`update_url`, `content_pack_url/checksum`, `frontend_url/checksum`, `vault_versions`,
`app_min_version`. Посредник может взять законно подписанный ответ и дописать свои URL —
подпись останется валидной, политика будет `Verified`.
Компенсирующий контроль: внешний бандл проверяется отдельной подписью манифеста
(`lib.rs:2766` → `crypto::content_sig::verify_manifest`), поэтому это не прямой RCE, но
«подтверждённый» ответ шире того, что реально подтверждено.
Сама политика при этом вычислена корректно — из `req.fingerprint_hash` / `req.product`
(запрос, не ответ) — привязка к машине честная, замечаний по пункту 2 задания нет.

## B-3 · Medium · `cache_policy:173` — рациональному посреднику выгодно НЕ подписывать
Отсутствие подписи мягче неверной: подделка без поля `signature` → `Unverified` → кэш пишется на
сутки и доступ выдаётся. Отсечён только неумелый вариант с мусорной подписью.
**Ответ на вопрос «даёт ли мягкий режим хоть что-то»:** даёт, но узко — срок жизни СЕТЕВОЙ
подделки 7 суток → 1 сутки. Против локального форжа файла (B-1) и против посредника, который
просто не подписывает, — ноль. Пока `AUTH_SIG_ENFORCEMENT = Soft`, честная формулировка —
«сокращает срок жизни подделки», а не «подделка не проходит».

## B-4 · Low · честный подписанный кэш деградирует до суток без нужды
Живой `.thin`: подпись есть и (по зонду `live_auth_signature_probe`) сходится, но `sig_verified`
в файле нет → сутки. Заявленная совместимость соблюдена, но причина устранима: перепроверка
подписи при чтении закрыла бы и B-1, и эту потерю офлайна разом.

## B-5 · Low · подписанный `expires_at` нигде не применяется
grep по `src-tauri/src`: в онлайн-пути `expires_at` только прокидывается в `OnlineAuthStatus:558`
и в билет `build_cloud_ticket:359`; сравнения с текущим временем нет (есть только в офлайновом
`license.rs:143`). Истёкшая лицензия внутри свежего кэша даёт доступ до истечения TTL.
Не регресс правки — но объясняет, почему подпись `expires_at` не даёт контроля отзыва у клиента.

## B-6 · Info · второй путь появления файла кэша
`data_migration.rs:21-29` копирует `session_cache.json` из старого identifier'а вместе с
`sig_verified` как есть. Для Econometrica не срабатывает (пары в `IDENTIFIER_MIGRATIONS:11` нет).
Новой подделки не создаёт — переносит существующий файл.

## B-7 · Info · запись кэша не атомарна
`save_cache:278` — `fs::write` без temp+rename. При гонке двух экземпляров возможен обрыв →
битый JSON → отказ (`cache_corrupted_graceful_none`), то есть риск потери офлайна, не обхода.

## Проверено, замечаний нет
- `save_cache` вызывается ровно из одного места (`online_auth.rs:519`) под веткой политики.
- Ответы со статусом != `ok` не кэшируются вовсе (вся запись внутри `if status == "ok"`).
- `cached_at > now` отвергается (`:294`); повторный вход перезаписывает кэш целиком.
- Старый кэш без `sig_verified` читается (`#[serde(default)]`), разбор не падает —
  тест `legacy_cache_without_the_field_is_read_as_unverified:793` зелёный, на живом `.thin`
  подтверждено: поля нет, файл валиден. Офлайн отнимается ровно как заявлено (суточный).
- Кабинеты нигде больше durable не хранятся: гейт `lib.rs:613`, `get_allowed_cabinets:2239`
  каждый раз идут через `authorize` → кэш и есть единственный носитель гранта между запусками.
