## 2. Как справка доставляется и отображается

**Механизм показа — открытие во ВНЕШНЕМ приложении, не в окне программы.**
`src-tauri/src/lib.rs:2078` `fn open_help(cabinet_id, app_handle)`:
1. сперва ищет файл в content-pack (`%LOCALAPPDATA%/<id>/content-packs/help/<id>.html`) — путь существует в коде (`commands/content_pack.rs:69 help_file_path`), но реальной папки `help/` в content-packs сейчас нет → эта ветка сейчас всегда промахивается (задел на будущее, не используется);

3. dev-фолбэк — читает прямо из `src-tauri/help-econometrica/` в исходниках.
Файл открывается через `tauri_plugin_opener::open_path` — **в системном браузере по умолчанию**, а не во встроенном webview.

## 4. Чего не хватает из 4 требуемых тем (с доказательством)

### 4.1 Макроэкономика — уровень vs изменение

**Есть**: код реально распознаёт макро-факторы по имени столбца — `sidecar/econometrica/utils/column_detection.py:288-314`:
```
_sep_pattern(r'cpi'), _sep_pattern(r'inflation'), _sep_pattern(r'fx_(?:rate|usd|eur|cny)'),
_sep_pattern(r'exchange_rate'), _sep_pattern(r'usd_rub'), _sep_pattern(r'key_rate'),
_sep_pattern(r'инфляция'), _sep_pattern(r'курс_(?:рубля|доллара|евро|юаня)')
```
**В справке**: единственное упоминание — `data-preparation.html:279` — одна строка примера в таксономии:
```
Примеры: сезонность, погода, праздники, макроэкономика (доходы, инфляция), тренд категории, заболеваемость (для фармы)
```
Ни одно конкретное имя столбца (`macro_cpi`, `key_rate`, `usd_rub`, `fx_rate`…) в тексте справки не названо, кроме одного случая `macro_cpi` в примере готового файла (`data-preparation.html:591-599`) — но и там без объяснения принципа.

**Предупреждение «подавать изменение, а не уровень» — отсутствует полностью.** Проверено прицельно:
```
grep -il "первую разность\|темп роста\|прирост\|дифференц\|stationarity\|стационарн" *.html
→ econometrica.html, glossary.html, interpretation.html, whats-new.html
```
— во всех четырёх совпадениях речь о другом (прирост KPI по итогу оптимизации, стационарность в общих терминах модели, «темп» не встречается в смысле темпа роста макропоказателя). Ни одного места, предупреждающего, что **уровень** курса/ставки/ИПЦ коллинеарен тренду продаж и заберёт вклад медиа, а **изменение** — правильная форма подачи. Есть только общее правило про мультиколлинеарность (`data-preparation.html:628`: «Мультиколлинеарность (r > 0.8)… Частый случай — показы + клики») — макро в этот пример не попадает.

Вывод: гэп подтверждён на 100% — тема присутствует в модели кодом, отсутствует в тексте справки как явное предупреждение.

## 8. Риски перестройки — что может сломаться молча

1. **PDF-сборка перестанет собираться или соберётся с потерями** — `build_help_pdf.py` жёстко завязан на 15 конкретных имён файлов и знает про каждый персональные особенности (тёмная тема, `--purple/--teal`, разрез install.html). Переименование без параллельной правки скрипта — тихий провал `help-pdf-consistency` в lefthook (это хотя бы явный, не тихий, сбой — но легко пропустить, если хук временно отключат «чтобы не мешал»).
2. **`sync_help_lists.py` потеряет якорь** для `AUTO_BRAND_HINTS`/`AUTO_PERF_HINTS`/`AUTO_STRONG_PERF_HINTS`, если содержимое `methodology.html` разъедется по новым файлам без переноса маркеров — тогда список hint-слов брендовых/перформанс-каналов перестанет обновляться автоматически, но заметно это будет не сразу (маркеры просто останутся в старом, уже не читаемом файле).
3. **`open_help` в Rust — простой path-lookup по `cabinet_id`** (`src-tauri/src/lib.rs:2078`), без поддержки якорей (`#step-2`) — сейчас открывает файл целиком через внешний браузер. Если структура рассчитывает на переход сразу к «своему» разделу внутри страницы, а не на отдельный файл на шаг, придётся либо резать на отдельные файлы (как предложено выше), либо научить `open_help`/фронтенд передавать якорь и открывать во встроенном webview, а не во внешнем браузере — это уже архитектурное решение, не только текстовое.
4. **`econ-nav.js` (`PAGES` массив)** захардкожен в самом справочнике — если новые файлы не добавить туда, у них не будет ни навбара, ни попадания в поиск по `keywords`. Дублируется в `src-tauri/help/econ-nav.js` (соседняя папка, другой продукт) — не перепутать, править только `help-econometrica/econ-nav.js`.
5. **Глоссарий и FAQ ссылаются на текущие имена файлов по `href`** (`data-preparation.html:673`: `<a href="pipeline.html">`, аналогично в других местах) — переименование файлов без grep по всем 15 HTML на предмет `href="<старое-имя>.html"` оставит битые внутренние ссылки молча (браузер не покажет ошибку сборки, просто 404 при клике).
6. **Три файла (`pipeline.html`, `econometrica.html`, часть `features.html`) содержат частично разный текст об одних и тех же шагах** — при слиянии в один источник по шагу есть риск потерять более точные детали одного из дублей (например, у `econometrica.html` формулировки для Планирования полнее, чем у `pipeline.html`) — нужна ручная сверка построчно, не автосклейка.
7. **`whats-new.html` заголовок «в 2.4»** при текущей версии продукта 2.5.1 (по памяти сессии) — файл, похоже, не обновлялся к релизу; не входит в 4 требуемые темы, но при трогании соседних файлов легко забыть, что этот тоже отстал.

## 10. Главная неожиданность

**Пасха отсутствует не только в справке, но и в самом продукте — во фронтенд-панели управления праздниками.** Бэкенд (`holiday_calendar_ru.py`) считает и подставляет в модель 13 праздников, включая Пасху по александрийской пасхалии с окном −7…+3 и явным учётом пересечения с майскими. Но UI-компонент, которым клиент видит и включает/выключает праздники (`HolidayControlsPanel.svelte` через `HOLIDAY_CALENDAR_RU` из `src/lib/holiday-calendar.js`), содержит только 12 записей — Пасхи там нет вообще, клиент не может её увидеть или отключить отдельно, хотя она молча участвует в его модели. Комментарий в самом файле списка (`holiday-calendar.js:1-10`) прямо фиксирует это как известный факт: «12 праздников hardcoded... opt-out был отложен до v2.2.0» — то есть Пасха добавлена в бэкенд позже фиксации фронтенд-списка, и синхронизацию, judging by комментарий, отложили, а не забыли, но по факту она осталась не сделана. Это не вопрос текста справки — это функциональный дефект продукта (клиент не управляет одним из 13 факторов своей же модели), обнаруженный только потому, что для описания темы «Праздники» в справке пришлось идти проверять реальный список по коду, а не по документации.
