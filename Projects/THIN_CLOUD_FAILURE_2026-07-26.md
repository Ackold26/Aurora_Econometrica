## Диагноз (факты, не гипотезы)

| Ось | Факт | Источник |
|---|---|---|
| Файл на сервере | `econometrist.vault` = 34 165 байт, версия `c3` текущая | Storage list + `content_versions` |
| Лицензия | активна до 2026-10-18, продукт econometrica, кабинет econometrist | таблица `licenses` |
| EF `/content` | 200 OK, тело целиком, 3.2 с (с моего канала через VPN, выход США) | живой curl |
| EF `/app-update` | **401 `UNAUTHORIZED_NO_AUTH_HEADER`** — клиент не шлёт anon-ключ | живой curl + `updater.rs:62-77` |
| Канал клиента | `error decoding response body` на vault (34 КБ!) и иногда на auth; обрывы ровно на 120 с = общий таймаут | журнал клиента |
| Загрузчик vault | один выстрел, без повторов и докачки, общий таймаут 120 с | `content_updater.rs:276-303` |
| Ошибка пользователю | `001] Failed to read vault: <путь>` — техническая строка | `vault.rs:136` |

**Корень 1 (сеть клиента + хрупкий загрузчик).** 34 КБ не доходят при работающем auth — это обрыв TLS/тела промежуточным узлом (профиль давления на Cloudflare-сегмент из РФ; `*.supabase.co` живёт за Cloudflare). Такой обрыв — норма нестабильного канала, лечится повтором и докачкой, а не таймаутом (записано в [[feedback_resume_for_large_file_downloads]], кодифицировано INV-71 — но применено только к загрузчику больших моделей, до vault-канала не доехало).

**Корень 2 (наш баг).** `/app-update` требует заголовки `apikey` + `Authorization: Bearer <anon>`; в Oracle/Creative/Legal/DocMaster/PR Master они добавлены (Oracle `updater.rs:65,72-73`, порт CH `d88e3b2`), в **Econometrica и Parser — нет**. Канал обновлений через Supabase у них мёртв всегда, спасает только запасной GitHub Pages.

**Корень 3 (архитектурный).** У тонкого клиента нет офлайн-пути доставки vault: не скачался — продукт не открывается вовсе, кэша нет, ручного импорта нет, сообщение пользователю не объясняет причину.
