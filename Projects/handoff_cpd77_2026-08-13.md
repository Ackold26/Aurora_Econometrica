# Передача внешнему аудитору — блок CPD-77 (антивирусная поверхность), 13.08.2026

> ⚠️ Канонический `Projects/handoff.md` в этом дереве принадлежит ДРУГОМУ блоку (CPD-69/70,
> ночная сессия 13.08) — он не перезаписан намеренно. Этот файл — передача по блоку CPD-77.

## 1. Цель блока

11.08.2026 Kaspersky снял с диска у клиента исполняемый файл Эконометрики во время работы
(`PDM:Trojan.Win32.Generic` — поведенческая эвристика). Блок должен был найти в коде действия,
которые поведенческая защита читает как вредоносные, убрать те из них, что не дают пользы, и
установить, затронуты ли остальные продукты линейки. Дополнительно — закрыть дыру в гейте выпуска,
где часть записей реестра дефектов не имела класса и молча не считалась.

## 2. Ключевые инварианты

- **Снятие процесса не должно трогать чужое.** Проверка «процесс принадлежит текущему пользователю
  И имеет ожидаемое имя образа» (`is_our_process_and_user`) сохранена во всех правках без изменений.
  Менялся только ИСТОЧНИК идентификатора: вместо разбора вывода `netstat` — чтение из файла
  состояния, который приложение само пишет при запуске.
- **Миграция со старых версий должна продолжать работать.** Путь, вызываемый когда файла состояния
  ещё нет (`legacy_zombie_by_port_scan` / `legacy_cleanup_once`), сохранён вместе с `netstat` —
  там идентификатор взять неоткуда.
- **Затирание файлов нулями перед удалением не трогать.** По форме похоже на вредоносное поведение,
  но это спроектированная защита данных клиента (NIST SP 800-88), усиленная прошлым аудитом.
- **Класс записи реестра берётся из закрытого списка ADR-047 дословно**, иначе счётчик её не видит.

## 3. Осознанные компромиссы

1. **Права каталогов у существующих клиентов не восстанавливаются.** Убранный вызов `icacls` уже
   вычистил SYSTEM и Администраторов у всех, кто запускал продукт; новая версия им прав не вернёт.
   Причина: восстановление требует системного вызова `SetNamedSecurityInfoW` — это новый `unsafe`-код,
   и делать его «заодно» с текущей правкой значило бы вносить непроверенный риск. Отложено осознанно.
2. **`wait_or_kill` удалён вместе с вызовом, которому служил.** Инфраструктура срока ожидания
   внешней утилиты (запись `61f65e5` от 12.08) обслуживала только `icacls`; компилятор подтверждает,
   что больше нигде не используется. НО оставшийся `netstat` в миграционном пути вызывается
   блокирующим `.output()` без таймаута — защита снята, риск остался. Перенос утилиты в общий модуль
   `proc.rs` вынесен отдельной задачей.
3. **Обфускация строк (`obfstr`, по 6 вызовов во всех продуктах) не тронута.** Это третий признак
   того же семейства, но статический, а не поведенческий, и его снятие требует другой проверки —
   побайтовой сверки значений строк. Вынесено отдельным пунктом в CPD-77.
4. **Три продукта не правились: PR Studio, AI Agency, Media Radar.** У первых двух нет версионных
   меток продукта и `master` не двигался с июня; у Media Radar в конфиге `1.0.0` при клиентской
   `1.3.5` и всего четыре метки, все `1.0.0`. Куда положить правку — из репозиториев не выводится,
   а вслепую она уедет в мёртвую ветку и создаст ложное ощущение закрытого дефекта.
5. **Правки лежат в отдельных ветках, не в выпускных.** `cpd77-docslab-fix` и `cpd77-sa-fix` созданы
   от выпускных точек; слияние — решение владельца.
6. **Класс CPD-77 обоснован порчей прав, а не антивирусом.** Причинность «эти два действия вызвали
   вердикт» НЕ доказана: целевого опыта «убрали — перестало срабатывать» не было. Доказана только
   необратимая порча прав, измеренная на живой машине. Заголовок и класс намеренно опираются на неё.

## 4. Зоны неуверенности

1. **Достаточность правки против антивируса не проверена вовсе.** Мы убрали два действия из
   нескольких подозреваемых (в коде остаются: шифрование своих файлов, сбор аппаратного отпечатка
   через WMI, спавн дочернего движка, тихая фоновая докачка, повышение прав в обновлении).
   Поведенческая защита копит оценку по совокупности — снижение может оказаться недостаточным.
   Живой опыт на машине с Kaspersky не проводился.
2. **Правки в сайдкарах не покрыты тестами ни до, ни после.** В `parser_sidecar.rs` и
   `rag_sidecar.rs` тестов нет вообще; зелёный прогон говорит лишь, что ничего соседнего не сломано.
   Логика «взять pid из состояния → проверить владельца → снять» проверена только компиляцией и
   чтением кода.
3. **Риск переиспользования идентификатора процесса.** Раньше pid приходил из `netstat`, то есть
   заведомо принадлежал держателю порта. Теперь он читается из файла состояния и может оказаться
   устаревшим: система могла выдать этот номер другому процессу. Защита — проверка владельца и
   имени образа — остаётся, но она слабее, чем «этот процесс держит наш порт». Оценка риска
   (совпадение номера И пользователя И имени образа) сделана рассуждением, не измерением.
4. **Патч Smart Analytica перенесён из Docs Lab.** Исходные файлы различались, `git apply --check`
   прошёл чисто, тесты зелёные — но построчной сверки смысла для чужого продукта я не делала.
5. **Классификация десяти записей реестра сделана исполнителем, проверена мной выборочно.** Лично
   разобраны два спорных случая (CPD-56, CPD-59); остальные восемь приняты по таблице обоснований
   без чтения полного текста каждой записи.
