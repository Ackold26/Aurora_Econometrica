# Инвентаризация англицизмов на экранах — Aurora AI Econometrica (s48)

Дата: 2026-09-14. Только инвентаризация и предложения, код не менялся.

## Методология и важная оговорка по охвату

Продукт делит кодовую базу с Aurora Creative Hub (`New_AI_Agency`-семейство). В `CommandPalette.svelte:41-48`
прямо сказано: экраны `/workflow`, `/data-chat`, `/brands`, `/brand/[id]` — возможности Creative Hub,
и в редакции Econometrica они гейтятся флагом `$isCreativeHub` и **недостижимы через палитру команд**
(хотя маршруты физически не удалены и открываются по прямому URL). Экран `/campaign` использует тот же
флаг. Поэтому находки в этих экранах вынесены в отдельный низкоприоритетный раздел в конце — реальный
пользователь MMM Optimizer их не видит штатным образом.

Реальная поверхность экранов Econometrica: `/`, `/cabinet`, `/pipeline/*` (7 шагов: Импорт → Валидация →
Модель → Декомпозиция → Оптимизация → Отчёт, плюс мастер сценариев планирования), `/causal`, `/settings`,
онбординг (`FirstRunTour`, `IntroTutorial`, `OnboardingOverlay`), глоссарий (`GlossaryPanel`).

Собственный канон продукта уже существует и с ним нужно сверяться: `src/lib/glossary.js` (452 строки,
45 терминов, показывается пользователю по Ctrl+K и как всплывающие определения) и
`src/lib/data/tooltip-texts.js` (169 строк, тексты всех подсказок). Оба файла — источник эталонного
перевода: там термины даны по формуле «русское название (Англ. термин)», например «Остаточный эффект
(Adstock, Carryover)», «MCMC (Алгоритм байесовского расчёта)», «Подбор под цель (обратная оптимизация)».
Большинство находок ниже — это **не отсутствие решения**, а **расхождение уже принятого решения с
конкретным экраном**, где кто-то написал сырой английский термин, не заглянув в глоссарий.

Метод поиска: полнотекстовый обход `src/**/*.svelte`, `*.js` (i18n, glossary, tooltip-texts) по списку
подозрительных слов + вручную просмотрены все строки, где английское слово стоит рядом с кириллицей
(445 строк после фильтра, из них ~280 — не комментарии разработчика). Также точечно прочитаны экраны,
которые в списке не всплыли автоматически (NavRail, GlossaryPanel, FirstRunTour, IntroTutorial, causal/*) —
для контроля, что список подозрительных слов не пропустил целый непереведённый экран (пропустил — экран
«Причинность», см. ниже).

### Функциональная прореха (не терминология) — про `target_accept`

`ConvergenceDashboard.svelte:300,302,308` советует пользователю «повысьте target_accept до 0.99», но
в `ConfigPanel.svelte` (блок `custom-mcmc-grid`, Эксперт-режим настройки MCMC) есть только три поля —
`Chains`, `Draws`, `Tune` (строки 738-763). Поля `target_accept` в интерфейсе НЕТ ни в каком виде: ни
как отдельное числовое поле, ни как ползунок, ни спрятанным в «Настройки выборки». Совет ссылается на
параметр сэмплера PyMC, значение которого пользователь физически не может изменить через Aurora —
единственный canal — если бы кто-то напрямую редактировал pickle/конфиг за пределами интерфейса. Из
кода `ConfigPanel.svelte:$derived` видно, что `mcmcTargetAccept` читается из результата уже выполненного
расчёта (`diagnostics?.metrics?.mcmc?.target_accept`), то есть значение приходит с бэкенда, но обратной
дороги (поле ввода → бэкенд) нет. Рекомендацию либо нужно убрать из текста совета, либо — что вероятнее
осмысленно — добавить это поле в Эксперт-режим `ConfigPanel`, раз бэкенд его уже поддерживает и он влияет
на исход не меньше, чем tune/draws/chains. Терминологической правки здесь не делала (не входит в мандат
этой задачи), только диагностирую разрыв.

**Подробнее, что именно советуется и почему это невыполнимо** (по прямому запросу владельца):
- **`ConvergenceDashboard.svelte:300`** — при 1-3 дивергенциях и `target_accept < 0.99`: «альтернативно
  - повысьте target_accept до 0.99 (медленнее, но устранит остатки)». Условие срабатывает, когда прогрев
  уже большой (`Tune` не < 4000), то есть это единственная предлагаемая альтернатива в этой ветке.
- **`ConvergenceDashboard.svelte:308`** — при 4-50 дивергенциях и максимальном прогреве: «Альтернативы:
  target_accept=0.99, упростить модель…» — снова первым пунктом называется параметр, которого нет в форме.
- Путь пользователя, который поверил совету: открывает Эксперт-режим `ConfigPanel` (`custom-mcmc-grid`,
  строки 736-764) → видит три поля — `Chains`, `Draws`, `Tune` → поля `target_accept` нет физически, ни
  под этим именем, ни под каким-либо другим (нет четвёртого числового инпута, нет ползунка, нет скрытого
  за «дополнительно»). Ему не на что нажать, чтобы выполнить совет.
- Откуда в принципе берётся `target_accept`, который дисплей показывает (`mcmcTargetAccept`,
  `ConvergenceDashboard.svelte:209`): читается из `diagnostics?.metrics?.mcmc?.target_accept` — то есть
  это значение, с которым бэкенд УЖЕ обучил модель (по умолчанию 0.95, судя по фолбэку), а не то, что
  можно задать заранее. Направление данных одностороннее: бэкенд → экран диагностики. Обратного пути
  экран → поле ввода → бэкенд для этого параметра нет.
- Значит, `target_accept` в интерфейсе — это read-only последствие уже завершённого расчёта, а текст
  подсказки написан так, будто это настраиваемый параметр, доступный «прямо сейчас, в этом Эксперт-режиме».
  Пользователь физически не может выполнить два из трёх советов на дивергенции ветки «средне-много»
  (строки 300 и 308) без редактирования файлов вне приложения.
