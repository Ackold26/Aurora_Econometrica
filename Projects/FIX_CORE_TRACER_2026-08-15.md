## 2. Как сделан реэкспорт в продукте — и почему остальной код не тронут

Ветка `core-tracer-econ` от `master`, коммит `4c32445` (не запушен).

**`src-tauri/src/errors.rs`** (было 180 строк → стало 5):
```rust
//! Коды ошибок продукта. Определения переехали в общий крейт `aurora_core` (трассирующий
//! срез 15.08.2026) — здесь остался реэкспорт, чтобы весь остальной код продукта, ссылающийся
//! на `crate::errors::…`, продолжал работать без единой правки.
pub use aurora_core::errors::*;
```
`pub use ... ::*` делает `crate::errors::ErrorCode`, `crate::errors::coded`, `crate::errors::coded_err`
видимыми по прежнему пути. Десятки мест в продукте, ссылающихся на `crate::errors::…`,
компилируются без единой правки — реэкспорт не переименовывает и не сужает набор имён.

**`src-tauri/src/commands/feedback.rs`** (было 143 строки → стало 15):
```rust
pub use aurora_core::feedback::{form_category, CATEGORY_MAP};

#[tauri::command]
pub async fn submit_feedback(
    category: String,
    message: String,
    contact: String,
) -> Result<String, String> {
    aurora_core::feedback::submit(category, message, contact).await
}
```
Именной (не `*`) реэкспорт — здесь он важен явно: сторож CPD-88 линкуется по точному пути
`aurora_econometrica_lib::commands::feedback::form_category`, и `pub use ... {form_category, ...}`
гарантирует, что этот путь останется разрешимым. Обёртка команды — три содержательные строки,
сигнатура и порядок параметров не менялись, вызывающий код фронтенда (`invoke('submit_feedback', …)`)
не тронут.

## 4. Собрался ли сторож CPD-88 — главный признак верного реэкспорта

**Да.** `guard_cpd88_feedback_category_map.rs` линкуется с
`aurora_econometrica_lib::commands::feedback::form_category` — реальной живой таблицей, а не
текстовой копией. С временно раскомментированной path-зависимостью на `aurora_core` продукт собрался,
и сторож прошёл **5 passed / 0 failed** — тот же счёт, что был до переноса. Это и есть проверка, что
реэкспорт полон: если бы `pub use` потерял `form_category` или его сигнатуру, сторож перестал бы
компилироваться, а не просто упал бы — по правилу задания в этом случае чинить реэкспорт, а не
сторож. До такой ситуации не дошло.

Отдельно прогнан `guard_no_regressed_cpd77_cpd79.rs` — **7 passed / 0 failed**, без изменений (эти
файлы данный срез не касался, прогон — проверка, что перенос ничего рядом не задел).

## 6. Что мешает подключить крейт по-настоящему

Сейчас в `src-tauri/Cargo.toml` (продукт) зависимость закомментирована:
```toml
# 🔴 Трассирующий срез общего ядра (15.08.2026, CRATE_DESIGN_2026-08-15.md). Временное подключение
# путём — только для проверки сборки на этой машине, боевое будет git-зависимостью по метке:
#   aurora_core = { git = "https://github.com/Ackold26/aurora-platform-core.git", tag = "aurora_core-v0.1.0" }
# aurora_core = { path = "D:/Docs/Aurora_Ai/_wt_core_tracer/aurora_core" }
```
**Ветка `core-tracer-econ` в этом виде не собирается** — так и оставлено намеренно, обходов не
придумывалось (прямое указание задания). Боевая строка манифеста будет ровно такой:
```toml
aurora_core = { git = "https://github.com/Ackold26/aurora-platform-core.git", tag = "aurora_core-v0.1.0" }
```
Что для этого нужно и чего у меня нет:
1. **Коммит `35d8345` в `_wt_core_tracer` должен уйти в `Ackold26/aurora-platform-core`** —
   я не пушила (прямой запрет задания). Без пуша тега `aurora_core-v0.1.0` не существует нигде,
   кроме локальной ветки.
2. **Метка `aurora_core-v0.1.0`** — заводится после ревью владельцем, тем же приёмом, что и
   `aurora_gateway-v0.6.5` (видно в `Cargo.cloud.fragment.toml` Эконометрики).
3. **Доступ к приватному репозиторию `aurora-platform-core` с чистой машины** — сама
   `CRATE_DESIGN_2026-08-15.md` называет это непроверенным (раздел «Чего я не проверяла», п.1);
   мой перенос этого тоже не проверял — только сам факт, что path-зависимость на локальной машине
   собирается.
4. **Раскомментировать строку и заменить `path` на `git+tag`** в манифесте продукта — механическая
   правка на одну строку, но делать её раньше пункта 1–2 бессмысленно: метки ещё нет.
