### 4. Долги, оставшиеся от правок

- **CPD-80: развилка требует внешнего знания.** `legacy_cleanup_once` у Docs Lab и Smart Analytica не
  вызывается ниоткуда. Либо вернуть вызов в `setup()`, либо удалить миграционный путь вместе с
  последним `netstat` (тогда признак (Б) там закрыт полностью). Зависит от того, остались ли у
  клиентов установки v0.8.6 — из кода не выводится.
- **Перенос `wait_or_kill` в общий модуль** (`proc.rs`) у Docs Lab: вместе с убранным вызовом ушла
  защита от зависания внешней утилиты, а оставшийся `netstat` вызывается блокирующим `.output()`
  без срока. Если пойдёте по пути «удалить миграционный путь» (см. выше) — задача отпадает сама.
- **Обфускация строк `obfstr`** — по 6 вызовов в каждом продукте кроме Эконометрики, замерено.
  Статический признак того же семейства. Снимать с побайтовой сверкой значений строк (как в
  Эконометрике: sha256 ключа до и после совпал).
- **Состояние шага при частичной потере выгрузок.** Сейчас шаг рапортует `done`, даже если часть
  файлов не сохранилась (есть только громкая запись в журнал). Нужно отдельное состояние в
  `emit_wf_status` — это меняет договор с интерфейсом, решение за владельцем.
- **`forward_exports_to_inbox`** — тот же образец `let _ = fs::copy`, что и в CPD-81, но вне
  периметра той задачи. Проверить и закрыть.
- **`create_dir_all` внутри `persist_step_exports`** по-прежнему глотает свою ошибку (другой класс
  отказа, не закрыт).

## 🎯 Приёмы под ЭТИ задачи (добыты боем 14.08, не общие принципы)

1. **Меняя источник данных для опасного действия — выпиши гарантии прежнего источника и проверь
   каждую у нового.** Признак пропущенного регресса: правка ничего не удалила из защиты и потому
   выглядит безопасной. Ровно так CPD-79 прошёл ревью и выпуск.
2. **Выпускная ветка определяется меткой версии — и только с `--sort=-creatordate`.** Голое
   `git tag --list | tail` сортирует по алфавиту и врёт: у Docs Lab при живой 0.12.1 выдавало метку
   0.9.0 из посторонней ветки. Дальше — `git branch --contains <метка>`.
3. **Прогон по фильтру, который ничего не выбрал, неотличим от успешного.** `cargo test should_kill`
   дал код возврата 0 при нуле выполненных (436 отфильтровано): имя функции не совпало с именами
   тестов. Приём — считать выполненное в самой команде:
   `PASSED=$(grep -oE "^test result: ok\. [0-9]+" лог | head -1 | grep -oE "[0-9]+")`, и вердикт
   выносить кодом, а не глазами: `ok. 0 passed` глаз принимает за успех.
4. **Изолированная копия Tauri-продукта не собирается без неверсионируемых ресурсов** (`python`
   354 МБ у CH и Oracle, `brand-hub/dist/aurora-parser` у CH). Падает build-script ДО компиляции
   Rust — легко принять за поломку правки. Связывать ссылкой (junction) на основное дерево, не
   копировать. Отдельно: `LNK1104` на свежесозданном `.exe` — занятый файл, лечится повторным
   прогоном.
5. **Правило «правки только в своей копии» не защищает от столкновения сессий.** Продукт,
   закрываемый по кросс-продуктовому реестру, может взять любая сессия, у которой он в работе по
   своим задачам. Перед правкой И перед слиянием: `git log -S '<признак>' <выпускная ветка>` на
   свежем `fetch`.
6. **Правя общий ресурс с молчаливым пределом, меряй ИТОГ, а не свой вклад.** Дважды за блок зона
   памяти вставала впритык (8 871 из 9 000) — следующая чужая строка вытолкнула бы хвост фактуры
   молча. Мерить после вставки, а не на глаз.
