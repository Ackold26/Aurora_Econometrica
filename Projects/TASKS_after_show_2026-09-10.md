## З-1. 🔴 Два режима вместо трёх. Убрать работу через Claude Code клиента

### Итоговая постановка (слова владельца)

> В программе есть только два режима. Полностью локальный, без работы с данными на уровне
> ассистента Авроры. И работа через шлюз, где Аврора-ассистент доступен и отвечает.
> В настройках есть выключатель: слева полностью локальный, справа облачный режим.
> Облачный режим работает исключительно через шлюз Авроры. Варианты работы через локальный
> Claude Code из настроек убираем.

### Что меняется

| Маршрут | Было | Станет |
|---|---|---|
| Ассистент выключен, материалы не покидают машину | тумблер «Только локально» | **левое положение переключателя** |
| Работа через **Claude Code, установленный у клиента** | выбирался САМ автоопределением | 🔴 **убирается полностью** |
| Работа через **шлюз Авроры** | признак `thin`, выбирался редко | **правое положение, единственный путь ассистента** |

```
Полностью локально  ●———○  Через шлюз Авроры
```

Третьего, промежуточного и «автоматического» состояния нет.

### Определение левого положения (владелец, дословно по смыслу)

**Офлайн-работа: никаких обращений в интернет, кроме подтверждения лицензии и обновлений.**
Ассистент выключен, материалы, вопросы и файлы не покидают машину. Расчёт медиасплита работает
как обычно.

🔴 **Лицензия и обновления работают в ОБОИХ режимах, и офлайн и онлайн** — отдельное уточнение
владельца. Это единственные допустимые исходящие обращения в левом положении.

### Замер: что ходит в сеть сегодня

| Обращение | Гейт «только локально» | По итоговому определению |
|---|---|---|
| Проверка лицензии (`online_auth.rs`) | нет | ✅ разрешено |
| Проверка обновлений (`updater.rs`) | нет | ✅ разрешено |
| Библиотека методологии (`rag_client.rs`) | **есть**, 3 места (`ensure_not_local_only`) | ✅ уже соблюдено |
| Ассистент (`claude.rs` → локальный CLI **или** шлюз) | согласие + автоопределение | 🔴 переделывается |

То есть по сетевым обращениям левое положение уже почти соответствует определению — переделки
требует только маршрут ассистента.

### Требования к реализации

1. **Убрать автоопределение маршрута** — `execution_mode::resolve` и правило приоритета
   `decide_with_history`. Выбирать больше не из чего: режим всегда явный.
2. **Убрать из пути ассистента ветку локального Claude CLI** (`run_claude_inner` и всё, что ведёт
   к спавну чужой программы на машине клиента). 🔴 Не трогая ветку
   `#[cfg(not(feature = "cloud_advisors"))]` — см. «Что нельзя сломать».
3. **Один переключатель вместо двух тумблеров.** Нынешняя пара «Облачная обработка» +
   «Только локально» означала одно решение двумя органами управления — это и породило путаницу,
   стоившую отказа на показе.
4. **Строка фактического положения под переключателем, всегда видимая:**
   «Сейчас: материалы не покидают эту машину. Наружу уходит только проверка лицензии и
   обновлений» либо «Сейчас: запросы ассистента идут через шлюз Авроры».
5. **Сообщение при обращении к ассистенту в левом положении — ДО отправки, а не после отказа.**
   🔴 Решение владельца: показывается **постоянно**, не только в переходный период.
   > «Сейчас включён полностью локальный режим: ИИ-ассистент отключён, материалы не покидают эту
   > машину. Чтобы задать вопрос Авроре, переключите режим в Настройках.»
   В правом положении ассистент просто отвечает, без каких-либо предупреждений.
6. **Отказ шлюза не уводит никуда молча** — честное сообщение с причиной и кодом. Уходить теперь
   некуда, но правило записать явно.
7. **Проверки обязаны уметь покраснеть.** Тесты: (а) в левом положении ни один запрос с
   материалами не уходит наружу, разрешены только лицензия и обновления; (б) в правом ни один
   запрос не идёт в локальный CLI. Мутация: вернуть локальную ветку в путь ассистента — тест
   обязан упасть.
   🔴 Сторож обязан брать список обращений **из исходников**, а не из заранее выписанного
   перечня: перечень по построению слеп к обращению, которого в нём нет, — а именно такие потом
   и заводятся.

### 🔴 Что нельзя сломать — редакция для 152-ФЗ

У продукта есть **вторая редакция сборки**: `npm run tauri:build:local`, признак `cloud_advisors`
выключен, ассистента нет физически. Это НЕ тот маршрут, который убирается.

- **Убираем:** работу через Claude Code клиента — «мимо нашего шлюза, но наружу».
- **Сохраняем:** редакцию, где путь наружу отсутствует в коде вовсе.

🔴 **Отдельно решить:** «полностью локально» — это положение переключателя внутри обычной сборки,
отдельная редакция, или обе сущности сразу. Сегодня существуют обе и означают почти одно и то же.
Свести стоит сейчас, пока не расползлось по линейке.

### Решения владельца (приняты 10.09.2026, вопросов не осталось)

1. **Значение по умолчанию — «Через шлюз Авроры»** (правое положение). Продукт продаётся как
   готовый инструмент; полностью локальный режим — осознанный выбор клиента с требованиями по
   персональным данным, а не состояние по умолчанию.
2. **Область — только Эконометрика.** Остальные продукты линейки не трогаем.
3. **Согласие на облачную обработку — часть выбора режима.** Отдельной настройки больше нет:
   согласие спрашивается один раз, при первом переводе переключателя вправо. Отказ = переключатель
   остаётся слева.

### 🔴 Следствие решения №2, которое нужно принять сознательно

Механизм выбора маршрута — **файл продукта** (`src-tauri/src/commands/execution_mode.rs`,
41 760 б), а не общий крейт. Правка Эконометрики соседей физически не заденет — но у трёх из них
лежат СВОИ копии того же механизма, и они уже разошлись между собой:

| Продукт | Размер копии |
|---|---|
| Эконометрика | 41 760 б |
| Smart Analytica (Media) | 40 740 б |
| Creative Hub | 40 746 б |
| Docs Lab (DocMaster) | 70 568 б |

После этой правки Эконометрика разойдётся с ними ещё сильнее: у неё будет два режима и явный
выбор, у остальных — три маршрута с автоопределением. **Это сознательное расхождение по решению
владельца, а не недосмотр.** Записано здесь, чтобы следующая сессия не «выравнивала» продукты
обратно, приняв разницу за дефект.

Цена решения проявится, когда тот же дефект вылезет у соседа: разбирать его придётся заново, и
готовой правки из Эконометрики там не будет — файлы уже разной длины, механическое перенесение
не сработает.

### Почему это правильно (обоснование фактом)

10.09 средний маршрут сломал показ покупателю. Владелец включил «Облачную обработку» и
обоснованно считал, что работа идёт через наш сервер. Фактически сработало автоопределение:
Claude Code на машине нашёлся, маршрут стал локальным, запрос ушёл в него и вернул
`Failed to authenticate. API error 403`. Узел этого запроса не видел вовсе — соседняя линия
проверила базой заданий, журналом входа и журналом шлюза.

Средний маршрут вреден трижды: выбирался молча; требовал от клиента установленного и
авторизованного Claude Code, которого у покупателя-агентства не будет никогда; давал чужую
поверхность отказов — английскую диагностику поставщика вместо наших человеческих сообщений.
