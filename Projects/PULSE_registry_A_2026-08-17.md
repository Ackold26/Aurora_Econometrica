## Подтверждённые блокирующие дефекты (что увидит клиент + лечение)

1. **CPD-39, вторая половина** (🚫, НОВАЯ находка для EC). Клиент: если эконометрист-советник перегенерирует файл с тем же детерминированным именем в папке результатов (`Desktop\...\exports`), а клиент успел открыть/отредактировать вчерашний файл вручную и сохранить — новая генерация молча затрёт его без следа. Лечение по эталону линейки (CH `2305ebf`, LG/EC `copy_dir_into` уже есть как каркас): добавить побайтовую сверку (не трогать совпадающее) + `unique_export_path` для расходящегося содержимого, атомарную запись (tmp+rename).
2. **CPD-11** (🚫, безопасность). Клиент не увидит ничего сам — риск в том, что 125 мест `pd.read_excel` открывают клиентские XLSX без защиты от UNC-link/SMB-зонда. Требует архитектурного решения (openpyxl-first слой перед pandas либо accepted-risk с обоснованием), не разовой правки параметра.
3. **CPD-16, вторая половина** (переходное состояние, сейчас пересборка идёт). `dist/` 939 МБ — дубль PyInstaller-сборки, рантайм его не резолвит, но глоб бандла его заберёт, если не снести перед упаковкой. Это ровно то, для чего в aurora-fix существует V69 — предсборочный чек-лист обязан поймать это перед запуском реальной сборки.

## Записи, где формулировка реестра для EC неверна или устарела

- **CPD-05**: клетка «⚪ нет кабинетов-промптов этой модели» — ФАКТИЧЕСКИ НЕВЕРНА, у EC есть кабинет `econometrist` с 17 командами. Механизм дефекта (модель придумывает demo-данные) к нему не относится по другой причине — входные команды честно называют источник, а советующие команды работают с уже готовым блоком данных, не с файлами.
