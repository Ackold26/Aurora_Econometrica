# PULSE — очистка длинных тире в клиентском тексте

## Задача (своими словами)
Команда-лид нашёл 6 длинных тире (—) в клиентском HTML-отчёте (все текстовые, не в коде):
1 в тексте вывода бэктеста + 5 в разделителях дат. Оба источника — `sidecar/econometrica/engines/backtest.py`.
Правило продукта: клиентский текст — только короткое тире «–» (U+2013). Задача: (1) починить найденные 2 места,
(2) пройти по ВСЕМУ клиентскому слою (engines/, aurora_html/, aurora_pptx/, utils/) и найти остальные строковые
литералы с em-dash, которые реально долетают до клиента (не комментарии, не служебные строки, не dist/).

## План
1. Замерить baseline: сколько — в исходниках по директориям (grep).
2. Починить 2 известных места в backtest.py.
3. Прогнать grep по всему клиентскому слою на \u2014 в .py файлах (исключая dist/), классифицировать каждое совпадение:
   комментарий / докстрока (не трогать) vs строковый литерал, идущий в вывод (чинить, если это не термин/код).
4. Для каждого найденного места — проверить путь до клиента (grep по имени переменной/функции в aurora_html/aurora_pptx/report generators).
5. Починить всё, что доказанно клиентское.
6. Замер после: 0 em-dash в тексте отчёта (тот же метод, что в задаче) + 0 в клиентских строковых литералах исходников.
7. Отчёт таблицей.
