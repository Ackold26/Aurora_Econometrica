# Пульс — задача 2а: гонка обновления содержимого и осиротевший резерв

## Задача своими словами
Механизм обновления зашифрованных файлов содержимого (vault) по сети имеет три дыры. Главная – путь
«скачал → сверил сумму → записал с откатом» защищён блокировкой только на участке скачивания, а сама
запись (переименование рабочего файла в `*.vault.bak` и запись нового) идёт вне блокировки. Два
одновременных вызова `download_updates` для одного файла топчут друг друга: второй видит уже
переименованный файл, считает «резерва не было» и пишет без страховки. Восстановления осиротевшего
резерва при старте нет – значит клиент может остаться без рабочего файла навсегда. Плюс мелочь: срез
приставки `sha256:` идёт до приведения к нижнему регистру, поэтому `SHA256:` не срежется.
