# Облачная Аврора — проектная рамка (ассистент + RAG + серверный движок)

> Дата: 2026-07-11. Статус: черновик на решение Антона.
> Контекст: трек 3 (восстановление ассистента «Аврора») + решение Антона «RAG-слой проектировать вместе сразу».
> Связан с треком 4 (серверная версия на узле Б) — проектируются согласованно, строятся раздельно.
> Источники: разведка ветки `feat/ai-insights-tier2` (карта порта), выжимка памяти узла Б
> (project_regulatory_rag_node_b, project_thin_clients_*, reference_thin_client_license_sync_contract,
> ADR-027/029/030/034/037), project_aurora_assistant_cross_product_direction.

## 1. Два решающих факта (упрощают всё проектирование)

**Ф-1. Ассистент stateless.** `econ_ask_insight` шлёт запрос с `resume=None` — каждый вопрос
самодостаточен, grounding-контекст пересобирается фронтом заново. Следствие: ограничение движка
узла Б «one-shot, не диалоговый» (открытый вопрос тонких клиентов) для ассистента — НЕ блокер.
Диалоговый прокси нужен полному тонкому клиенту кабинетов (трек 4), не Авроре.

**Ф-2. Промпт целиком строится на фронте.** `tier2-context.js` собирает всё: системные правила
(TIER2_SYSTEM_RULES, 10 правил INV-50 + методология), факты шага, honesty-вердикт дословно,
справку программы. Кабинет `econometrist` используется только как транспортная сессия `run_claude`.
Следствие: кабинетный CLAUDE.md ассистенту не нужен → транспорт взаимозаменяем (локальный CLI /
текстовый шлюз / движок узла Б) без изменения поведения ассистента.

## 2. Целевая архитектура (три слоя, стабильный интерфейс)

```
InsightsPanel («Спросить Аврору», «Что если»)
        │  buildTier2Prompt(context, question)         ← фронт, БЕЗ изменений между фазами
        ▼
econ_ask_insight(prompt) → text                        ← стабильный интерфейс Tauri-команды
        │
        ├── Фаза 1 (порт, сейчас): claude::run_claude (локальный Claude CLI, кабинет econometrist)
        ├── Фаза 2 (+RAG):        тот же транспорт + retrieval-инъекция методологии в промпт
        └── Фаза 3 (трек 4):      транспорт → узел Б (движок engine_async / L2 gateway),
                                   локальный CLI не нужен (тонкий клиент)
        ▼
sanitize + findUngroundedNumbers (страж INV-50)        ← фронт, БЕЗ изменений между фазами
```

Инвариант: интерфейс `econ_ask_insight(prompt) → text` и grounding-контракт INV-50 (числа ответа ⊆
факты Tier1; RAG приносит МЕТОДОЛОГИЮ словами, не числа) не меняются ни в одной фазе. Меняется
только транспорт под командой — та же точка, где уже живут `ensure_cloud_consent` +
`ensure_not_local_only` + feature `cloud_advisors`.

## 3. Фазировка

### Фаза 1 — порт ассистента (идёт сейчас)
Ветка `feat/econ-avrora-assistant` от planning-mode. Транспорт — локальный `run_claude`, как на
доноре. Работает из коробки, зависимостей от узла Б ноль. Гейты + живой прогон.

### Фаза 2 — RAG-слой методологии MMM (узел Б)
**Решение Антона (2026-07-11): эконометрическая RAG-библиотека будет СЕРВЕРНОЙ, она почти
готова.** Аврора обращается к ней за уточнениями и поиском ответов на сложные вопросы; сложные
эконометрические ответы канона обязана переводить на простой пользовательский язык (правило 11
TIER2_SYSTEM_RULES — внесено в промпт вместе с портом).
- **Движок**: канонный `aurora_rag` (Platform Core, ADR-027: RoSBERTa 1024d + LanceDB + chunker
  1000/150, опц. reranker) — тот же, что уже стоит за юр-RAG на узле Б. Ничего не изобретаем.
- **Корпус**: серверная эконометрическая библиотека на базе Knowledge_Library (Gelman, McElreath,
  Davidson-Pilon, Binet&Field, Sharp, Robyn/Meridian-доки — корпус готов, переезд на сервер) +
  `AVRORA_METHODOLOGY_FINDINGS.md` (roadmap: OVB-caveat, «правдоподобный диапазон», takeaway
  titles, ложная точность). Отдельный индекс, НЕ смешивать с юр-корпусом. Двуязычная формулировка
  запросов (рус+англ термины) — боевой приём Knowledge_Library, перенести в retrieval-клиент.
- **Сервис**: рядом с `aurora-regulatory-rag` (127.0.0.1:8801) — второй индекс в том же сервисе или
  порт 8802; за тем же периметром, auth `AURORA_CLIENT_SECRET`-заголовком (fail-closed доказан боем).
- **Точка инъекции**: `buildTier2Context` на фронте получает опциональный блок «методология»
  (топ-K чанков по вопросу) → вставляется в промпт. Rust — тонкий HTTP-прокси к retrieval-endpoint
  (клиент не держит секрет в JS). Фича за флагом, деградация без сети — молчаливая (ассистент
  работает как в Фазе 1).
- **INV-50**: retrieval-чанки промаркированы как «канон методологии» — правило промпта: цифры из
  книг НЕ выдавать как цифры модели клиента.

### Фаза 3 — серверный транспорт (совместно с треком 4, отдельная стройка)
Подмена транспорта под `econ_ask_insight`: вместо локального CLI — запрос к движку узла Б
(`engine_async`, порт 8800; econometrist-кабинет уже залит; подписка Anthropic, $0 API).
Аутентификация — по контракту тонких клиентов: SSH-CA L2 gateway (ADR-034, key-id = licenses.id
uuid) либо HTTPS + лицензионный секрет; синк реестра лицензий — Вариант B (утверждён).
Кандидат-механизм переключения local→server per-лицензия: поле `model_policy` в licenses
(project_remote_license_model_targeting — идея, не реализовано).
При серверном транспорте RAG-инъекция переезжает на сервер (движок обогащает промпт сам) —
клиентский код Фазы 2 упрощается до флага.

## 5. Чего не хватает (реестр под Фазы 2-3, не блокирует Фазу 1)

1. MMM-корпус: отбор книг из Knowledge_Library, chunking, индекс, подписанный пакет (паттерн
   aurora-legal-corpus manifest v1 + Ed25519).
2. Retrieval-endpoint на узле Б (второй индекс/порт) + системный юнит.
3. HTTP-прокси в Rust (retrieval за секретом) + блок «методология» в buildTier2Context + флаг.
4. Для Фазы 3: доработка engine_async (маршрут ассистента), синк лицензий Вариант B (отложен «до
   первого внешнего клиента»), model_policy.
5. Кандидат INV-NN «MMM causal caveats» (из AVRORA_METHODOLOGY_FINDINGS) — завести при Фазе 2.
