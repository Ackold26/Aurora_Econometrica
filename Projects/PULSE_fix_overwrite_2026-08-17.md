## Задача своими словами
Программа копирует свои результаты в папку выдачи клиента безусловно (`std::fs::copy` поверх
существующего файла). Если клиент правил вчерашний файл руками – правки исчезают молча, без следа.
Надо закрыть класс дефекта по всему обороту записи в выдачу: побайтовая сверка (совпало – не трогаем),
уникализация имени при расхождении, атомарная запись через временный файл, и видимое человеку
сообщение о развилке. Приём – тремя прогонами на настоящей файловой системе плюс автопроверки,
красные до правки и зелёные после.

## 4. Доказательство: три прогона на настоящей файловой системе
Временный каталог, живой вызов `sync_exports`, а не внутренняя функция копирования (иначе сторож
остался бы зелёным при возврате затирания в вызывающем месте – урок Ф-04).

```
[прогон а] файла не было → создан:
  ...\Рабочий стол\Aurora\econometrist\exports\разбор-модели.md
  сумма=8fe372f36949f3f9f60adad7084c4e575a5253b20704e18be9949d6c1240ae24
  время=1786953130535552100

[прогон б] содержимое совпало:
  было  время=1700000000000000000 сумма=ad13970e7dc0340b7c9e5560291cb9bbd9efda0eac3090bbb3d334eaed64c528
  стало время=1700000000000000000 сумма=ad13970e7dc0340b7c9e5560291cb9bbd9efda0eac3090bbb3d334eaed64c528
  → файла не касались вовсе; в папке остался ровно один документ

[прогон в] содержимое разошлось:
  файл клиента было  время=1786953130683323800 сумма=7d4f667fbebeb62d314118db5b7811a0d4ad882cc356957dcff09f94d8303e00
  файл клиента стало время=1786953130683323800 сумма=7d4f667fbebeb62d314118db5b7811a0d4ad882cc356957dcff09f94d8303e00
```

Тот же прогон (б) на коде ДО правки давал `стало время=1786932831313128500` при неизменной сумме –

содержимое файла клиента менялось с «вчерашний разбор С МОИМИ ПРАВКАМИ» на «сегодняшний разбор»,

## 6. Что осталось незакрытым и почему

1. 🔴 **В дереве красная чужая проверка** – `session/manager.rs:1722`
   `every_delivery_site_tells_the_person_about_renamed_files` падает паникой, а не утверждением:
   `end byte index 167859 is not a char boundary; it is inside 'б'`. Причина в строке 1744:
   `&src[at..(at + 3000).min(src.len())]` режет `lib.rs` по байтовому смещению, а файл содержит
   русский текст. Тот же риск в строке 1768. Правку в чужой файл-в-работе не вносила – передала
   владельцу через team-lead.
2. **Признак `thin` в приёмке.** `CLAUDE.md` обновился требованием гонять приёмку
   `cargo test --features thin` (CPD-112), но в этом дереве такого признака в `Cargo.toml` ещё нет:
   `cargo` отвечает «the package does not contain this feature». Приёмку прогнала в штатной
   конфигурации; в конфигурации поставки прогнать физически невозможно.
3. **Sidecar-выдача** (`.pptx`, `.html`, параметры модели) полагается на уникальность метки времени
   до секунды, а не на сверку содержимого. Дыры это не даёт (столкновение имён практически
   исключено), но и правила «совпало – не трогаем» там нет; файлы заморожены задачей.
4. **Дублирование проверок.** Мои сторожа и чужие частично пересекаются
   (`repeated_delivery_of_the_same_result_does_not_flood_the_folder` ↔
   `a_hand_edited_file_gets_one_neighbour_not_one_per_message`). Ничего не ломает, но при желании
   подчистить – решение владельца, сама чужое не трогала.
