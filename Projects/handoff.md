# Handoff — устойчивость облачной доставки тонкой редакции Econometrica (2026-07-26)

База аудита: `c8f1d91..a851001` (ветка `feat/econ-thin-client`, 7 коммитов). ⚠️ Файл `claude-session-base-sha` содержал `0e68944` — коммит, сделанный уже внутри блока, поэтому база определена вручную по первому коммиту блока (`b152b15^`). Diff кода — `Projects/audit.diff` (только `src-tauri/src` и `src/`, 1026 строк).

## 1. Цель блока

Клиент не мог открыть кабинет: файл рабочих материалов весом 34 КБ не докачивался с сервера ни разу за две недели, при этом сервер был исправен (внешний зонд с реальными параметрами клиента отдавал файл за 3 секунды). Блок делает загрузку устойчивой к обрывам канала: раздельные таймауты вместо общего дедлайна на запрос, повторы с нарастающей паузой, чтение тела порциями со сверкой длины. Те же гарантии распространены на пакет контента, бандл интерфейса, загрузчик установщика и авторизацию. Дополнительно добавлен запасной путь доставки материалов из файла и человеческий текст отказа вместо технической строки.

## 2. Ключевые инварианты

- **Общий дедлайн на запрос (`Client::builder().timeout`) на загрузках запрещён.** Только `connect_timeout` + `read_timeout` (таймаут тишины сокета): общий дедлайн рубит исправную медленную передачу и ничего не даёт против зависшего сокета.
- **Обрыв связи — повторяем; отказ по существу — нет.** 5xx, 429, 408, разрыв потока, таймаут → повтор с паузой 2/5/10/20 с, до 5 попыток. Прочие 4xx (403 «нет лицензии», 404 «нет файла») → выход сразу.
- **Усечённое тело не считается успехом.** Тело читается порциями; если сервер объявил `Content-Length`, итог обязан совпасть. В сообщение об ошибке всегда входит число полученных байт.
- **Импорт файла кабинета не доверяет источнику:** имя берётся только из последнего сегмента пути (защита от `..` и абсолютных путей), проверяется маска `[a-z0-9-]{1,40}.vault`, размер ограничен 200 МБ, содержимое обязано быть читаемым архивом, и лишь затем шифруется ключом машины.
- **Загрузчик установщика:** проверка доверенного хоста на КАЖДОМ переходе по перенаправлению (сохранено, SEC-04); частичный файл привязан к хешу адреса, чтобы новая версия не дописалась поверх байтов предыдущей; ответ 206 без внятного полного размера отвергается.
- **Клиентское сообщение об отказе** содержит причину, что делать и техническую подробность отдельной строкой; кода вида `001]` и путей к файлам в нём быть не должно.

## 3. Осознанные компромиссы

- **Докачки по частям для материалов кабинета нет** → функция `/content` на запрос части отвечает файлом целиком (200 вместо 206), проверено зондом. Пока сервер не поддержит `Range`, докачка на клиенте невозможна. Записано комментарием в коде, вынесено в следующую сессию.
- **Тело читается целиком в память** → файлы кабинетов весят единицы–десятки КБ; потоковая запись на диск усложнила бы код без выигрыша. Для установщика (245 МБ) применён другой путь — запись в `.part`.
- **Повторов у авторизации три, а не пять** → ответ крошечный, а пользователь ждёт открытия окна; пять попыток затянули бы старт на минуты.
- **Ручной импорт материалов сделан кнопкой в настройках, без автоматизации** → запасной путь для закрытых сетей; владелец отдельно отверг его как системное решение.
- **Константа `DOWNLOAD_TIMEOUT_SECS` удалена, а не оставлена** → после перевода всех загрузок стала недостижимой; мусор, порождённый самой правкой.

## 4. Зоны неуверенности

1. **Классификация повторяемых кодов.** 408 и 429 отнесены к повторяемым, 403/404 — к фатальным. Если сервер начнёт отвечать 403 на временную перегрузку (а не на отсутствие лицензии), клиент замолчит навсегда вместо повтора.
2. **Чтение тела при отсутствующем `Content-Length`.** Функция отдаёт порционный ответ без длины, поэтому сверка не срабатывает вовсе — усечение поймается только по ошибке сокета. Если посредник закроет соединение «чисто» на середине, клиент примет обрезанный файл за полный. Ниже по течению это ловит контрольная сумма, но в `open_cabinet` контрольные суммы передаются пустым объектом.
3. **Особый случай 404 у бандла интерфейса** различается сравнением текста ошибки (`contains("HTTP 404")`). Хрупко: изменится формулировка — потеряется различение «бандла нет» и «ошибка загрузки».
4. **Импорт файла кабинета не проверяет, что содержимое соответствует ИМЕННО этому кабинету** — только что это читаемый архив. Можно импортировать материалы одного кабинета под именем другого; последствия не проверялись.
5. **Тесты устойчивости поднимают локальный сервер на случайном порту** и чувствительны к загрузке машины: при семи параллельных сборках один из четырёх изредка падал (изолированный прогон — 22 из 22 трижды). Возможен флак в нагруженном CI.
6. **Дребезг вызовов не устранён:** в журнале клиента по 4–6 одновременных запросов авторизации и по 4 параллельные загрузки одного файла при старте. Защита от параллельных загрузок есть только у установщика (`in_flight_downloads`).

## 5. Затронутые файлы

- `src-tauri/src/commands/content_updater.rs` — транспорт загрузок: константы устойчивости, `resilient_client`, `read_body_counted`, `fetch_vault_once`, `download_vault_file`, `download_url_resilient`, четыре теста на обрыв потока и локальный тестовый сервер.
- `src-tauri/src/commands/updater.rs` — anon-ключ в вызове `/app-update`; загрузчик установщика переписан на докачку по частям (`download_attempt`, `validate_resume_total`, `InFlightGuard`), два теста.
- `src-tauri/src/commands/online_auth.rs` — три попытки запроса авторизации при обрыве, до возврата ошибки наружу.
- `src-tauri/src/lib.rs` — человеческий текст отказа при недоставленных материалах в `open_cabinet`; новая команда `import_cabinet_vault` и её регистрация.
- `src/routes/settings/+page.svelte` — кнопка «Загрузить материалы из файла» и вывод результата импорта.

# Handoff — блок 2: докачка по частям (26.07.2026, вечер)

База аудита: `07e560b..f257e15` (ветка `feat/econ-thin-client`, 7 коммитов). Затронуты серверная функция доставки, транспорт клиента, авторизация, текст отказа и импорт материалов.

## 1. Цель блока

Живая приёмка 2.4.1 показала: правки блока 1 работают и клиента не разблокировали. Посредник в его сети обрывает любой ответ длиннее примерно 4 КБ (10 обрывов из 10 на 3251…5649 байт при файлах 2,0–2,9 КБ, доходящих всегда). Повторы против порога бессильны — каждая попытка упирается заново. Блок делает так, чтобы через порог просто не приходилось ходить: сервер объявляет длину и отдаёт файл по частям, клиент просит куски по 2 КБ и склеивает.

## 2. Ключевые инварианты

- **Своя функция доставки объявляет `Content-Length` и поддерживает `Range`.** Порционная передача лишает клиента и сверки объёма, и возможности докачки; ответ 200 на запрос части не оставляет обходного пути.
- **Непонятый `Range` — файл целиком, а не отказ.** Сборки клиентов, выпущенные до этой правки, заголовок не шлют; отвечать им отказом значило бы сломать работающее.
- **Кусок заведомо ниже наблюдённого порога** (2 КБ при пороге около 4 КБ, минимальный обрыв 3251 байт).
- **206 без внятного полного размера не заслуживает доверия** — собрать по нему файл нельзя, усечение прошло бы незамеченным.
- **Бюджет попытки — на кусок, а не на файл.** Общий бюджет рубил бы исправную медленную сборку из 17 кусков ровно так же, как это делал общий дедлайн на запрос.
- **Журнал доставки — на начальный запрос.** Запись на каждый кусок раздула бы его в двадцать раз и сделала бы непригодным для разбора отказов.
- **Замок по адресу файла, а не общий на транспорт.** С общим замком файлы ждут чужих повторов (в прогоне тестов это дало 153 с вместо 37).
- **Гейт обязан уметь падать** — проверено внесением дефекта и откатом для каждого из трёх новых.

## 3. Осознанные компромиссы

- **Объект читается в память целиком даже ради одного куска.** Через `/content` ходят файлы кабинетов в десятки килобайт, и хранилище всё равно отдаёт объект целиком — нарезка в памяти ничего не удорожает. Для файлов в мегабайты понадобился бы проброс `Range` в хранилище; сейчас таких там нет.
- **401 и 403 остаются фатальными.** 403 — отказ по существу (лицензия), 401 — платформенный гейт при неверном ключе проекта; ключ статический, не сессионный.
- **Подлинность импортированного файла кабинета не сверяется** — эталона у клиента нет, контрольные суммы в `open_cabinet` передаются пустым объектом.
- **Экранированные строки сообщений развёрнуты в обычный русский текст** при переписывании функции. Задача этого не требовала; кодировка проверена зондом на проде (403 возвращает читаемый русский текст).
- **Память о скачанном живёт 30 секунд.** Покрывает всплеск вызовов при старте, но не переживает его надолго: обновление, вышедшее через минуту, клиент увидит.

## 4. Зоны неуверенности

1. **Порог посредника у клиента измерен, но не подтверждён вторично.** Если он окажется ниже 2 КБ, размер куска придётся снижать; приёмка на PC204 это покажет.
2. **Стоимость открытия кабинета выросла:** 17 обращений вместо одного, каждое с проверкой лицензии в базе. На боевом сервере это 16 секунд; на канале клиента может быть заметно дольше. Замеров у клиента нет.
3. **Дребезг вылечен на транспорте, а не в причине.** Команда за списком кабинетов по-прежнему дёргается с шести экранов, хотя правило 16 в `CLAUDE.md` это запрещает. Замок скрывает симптом; фронтовую причину никто не трогал.
4. **Классификация причин отказа опирается на текст ошибки** (`contains("403")`, `contains("недоступен")`). Изменится формулировка — классификация тихо съедет в нейтральную ветку. Тест это поймает только для нынешних формулировок.
5. **Находка M-4 закрыта объяснением, а не тестом:** сценария «длина объявлена, байт меньше, обрыв чистый» протокол HTTP не допускает.
6. **Тест на пустой кусок и тесты устойчивости чувствительны к загрузке машины** — сторож поднят до трёх минут, но на очень загруженной машине флак не исключён.

## 5. Затронутые файлы

- `supabase/functions/content/index.ts` — **новый в репозитории**: выгружен с сервера, версионируется впервые. Разбор `Range`, ответы 200/206/416, явный `Content-Length`, журнал на начальный запрос.
- `tools/check_content_range.mjs` — гейт границ диапазонов (17 проверок на тексте самого `index.ts`).
- `tools/probe_content_delivery.sh` — зонд приёмки снаружи (13 проверок, включая склейку по контрольной сумме).
- `src-tauri/src/commands/content_updater.rs` — `RANGE_CHUNK_BYTES`, `MAX_PREALLOC_BYTES`, `MAX_BODY_BYTES`, `RangeReply`, `parse_content_range_total`, `request_range`, переписанный `fetch_vault_once`, `download_with_retries` (две функции загрузки сведены в одну), замок `lock_for`/`take_recent`, `forget_vault_version`, восемь новых тестов и живая проверка против прода.
- `src-tauri/src/commands/online_auth.rs` — `read_fresh_cache`/`has_fresh_cache`, число попыток зависит от наличия годного кэша.
- `src-tauri/src/lib.rs` — `delivery_failure_explanation` и её применение, снятие отметки версии при импорте, сообщение о замене материалов, два теста.
- `package.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`, `Cargo.lock` — версия 2.4.2.

# Handoff — блок 3: порог на соединение и текст шлюза (27.07.2026)

База аудита блока целиком: `07e560b..HEAD` (10 коммитов, 1168 строк добавлено). ⚠️ Файл `claude-session-base-sha` содержал `a5c18b1` — HEAD, потому что сессия перезапускалась после обрыва и hook записал текущий коммит. База определена вручную по первому коммиту работы.

## 1. Цель блока

Живая приёмка показала, что докачка кусками по 2 КБ клиента не разблокировала. Замер вскрыл причину: посредник считает объём **на соединение**, а клиент переиспользовал одно соединение для всех кусков — два куска плюс заголовки складывались в те же 4166 байт, на которых зависала загрузка целиком. Блок запрещает переиспользование соединений и заодно чинит текст, отправлявший пользователя искать файлы доступа не в ту папку.

## 2. Ключевые инварианты

- **Соединения при докачке не переиспользуются** (`pool_max_idle_per_host(0)`). Порог считается на соединение; с общим пулом дробление обесценивается полностью и выглядит как «не сработало».
- **Зависание отличается от разрыва.** Время ответа, равное таймауту, при живом сокете — это зависание; в журнал обязано попадать число полученных байт.
- **Текст ошибки называет действие и верный путь.** Файлы доступа читаются из каталога данных программы, а не из папки рядом с исполняемым файлом; сообщение обязано вести туда, куда программа смотрит.
- **Тесты продукта гоняются с признаками сборки релиза.** Модуль шлюза живёт под признаком `thin`; без него семь тестов не запускаются вовсе.

## 3. Осознанные компромиссы

- **Размер куска оставлен 2 КБ**, хотя порог измерен около 4166 байт. Запас намеренный: порог у другого посредника может быть ниже, а цена лишних обращений на файлах в десятки килобайт мала (17 обращений, около 15 секунд).
- **Отказ от пула соединений применён ко всем загрузкам продукта**, а не только к файлам кабинетов. Разделять пути ради экономии рукопожатий не стал: у тонкого клиента все загрузки мелкие и редкие.
- **Дробление признано непригодным для больших материалов** и оставлено как есть. При пороге 4 КБ на соединение пакет в 20 МБ потребовал бы пяти тысяч соединений; архитектурное решение (перенос доставки) вынесено за пределы блока.
- **Гипотеза `IPQoS=throughput` из нашей же памяти проверена и отброшена** — на этом канале не помогает. Правка в код не вносилась.

## 4. Зоны неуверенности

1. **Все замеры порога сделаны поздним вечером и ночью.** Владелец предположил регуляторные ночные ограничения связи. Вечером накануне тот же шлюз отвечал, ночью — нет. Если гипотеза верна, число 4166 описывает ночное состояние канала, а не постоянное свойство сети, и выбор размера куска сделан по нерепрезентативным данным.
2. **Отказ от пула соединений не измерен по стоимости.** Каждый кусок теперь несёт полное TLS-рукопожатие; на медленном канале семнадцать рукопожатий могут занять заметно больше пятнадцати секунд, замеров у клиента нет.
3. **Классификация причин отказа опирается на текст ошибки** (`contains("403")`, `contains("оборван")`). Изменится формулировка ниже по стеку — классификация тихо съедет в нейтральную ветку.
4. **Память о скачанном (30 секунд) и замок по адресу** проверены только тестами на локальном сервере; поведение при одновременном старте нескольких окон программы у клиента не наблюдалось.
5. **Помощник не проверен вовсе.** Файлы доступа встали, но соединение до шлюза не проходит; работает ли остальная цепочка (лицензия в реестре узла, кабинет, движок) — неизвестно.

## 5. Затронутые файлы

- `src-tauri/src/commands/content_updater.rs` — запрет переиспользования соединений; ранее в этой же сессии: докачка по частям, замок по адресу и память о полученном, живая проверка против прода.
- `src-tauri/src/commands/gateway_executor.rs` — текст об отсутствии файлов доступа и тест на него (модуль под признаком `thin`).
- `package.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`, `Cargo.lock` — версия 2.4.3.
