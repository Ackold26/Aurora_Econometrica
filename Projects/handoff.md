воспроизводимым (одно зерно → одни числа, с паспортом среды), устранить противоречие

## 2. Ключевые инварианты

1. **Зерно передаётся ЯВНЫМ `random_seed=` в `pm.sample`.** Глобальное состояние numpy
   (`np.random.seed`) не трогается никогда: в движке есть независимо засеянные пути
   (`utils/reliability_a4.py` — проверка приоров, `utils/conformal.py`,
   `utils/ols_bootstrap.py`, все на `np.random.default_rng(42)`), глобальный засев
   сдвинул бы уже выпущенные клиентам интервалы. Закреплено сторожем обхода дерева.
2. **Раскладка цепей передаётся ТОЛЬКО через `nuts_sampler_kwargs`.** PyMC 5.28
   пробрасывает во внешний сэмплер лишь это поле; прямой аргумент `chain_method=`
   молча проглатывается. Закреплено сторожем.
3. **Паспорт воспроизводимости не выдаёт запрошенное за применённое.** Поле
   `chain_method_delivered` отражает факт доставки; на ярусе PyTensor цепи так не
   раскладываются вовсе, там оно честно `False`.
4. **Ярус сэмплера в паспорте — фактический.** Записывается ПОСЛЕ успешного возврата
   сэмплера, а не при входе в ветку: откат Tier-1 → Tier-2 идёт молча и даёт другие
   числа при том же зерне.
5. **Запас данных считается по ЭФФЕКТИВНОМУ числу параметров, единым источником**
   (`ratio-classifier.effectiveParamCount` / `effectiveRatio`). Состав приходит из
   движка; собирать его на фронте нельзя — это завело бы второй источник истины.
6. **Знаменателей два, по режиму моделирования.** Байесовский заводит авто-праздники
   РФ, OLS не заводит ни одного (в `ols_modeler.py` генератора праздников нет).
7. **Пороги валидатора гейтят по САМОМУ МЯГКОМУ знаменателю (OLS).** Валидация идёт
   до выбора режима; гейтить по байесовскому значило бы объявить «критически мало
   данных» проекту, который в OLS считается нормально, и отнять у него режим,
   созданный для коротких рядов.
8. **Число назначенных столбцов берётся живое (из текущих ролей), авто-часть — из
   ответа движка.** Пользователь меняет роли на том же экране, значение из ответа
   успевает устареть; авто-часть от ролей не зависит.
9. **Правка глоссария идёт по маршруту §18:** источник `docs/GLOSSARY_v2_1_0.md` →
   генератор `tools/build_glossary.py` → три выхода (`glossary.json`, `glossary.html`,
   `glossary.js`). Правка выходов напрямую — красный CI.

## 3. Осознанные компромиссы

1. **`detected.ratio` остаётся байесовским, а `issues` гейтят по OLS-знаменателю.**
   Решение → валидатор не знает режим (в контракте `/compute/validate` его нет), и
   расширять контракт ради этого значило бы трогать проводку через Rust. Цена: два
   числа с разными ролями в одном ответе, различие описано комментарием в коде.
2. **Историческое имя поля `n_params_effective_pretrain` сохранено** и несёт
   байесовскую оценку. Причина → уже сохранённые проекты и внешние читатели; рядом
   добавлены явные `n_params_effective_bayesian` / `n_params_effective_ols`.
3. **Запасной путь `effectiveParamCount` для проектов до P0.3 берёт 12 праздников
   без семантического дедупа.** Причина → воспроизвести дедуп без списка колонок
   нельзя; оценка сознательно консервативная (знаменатель не меньше фактического).
4. **Функция `exportToPptx` оставлена в `scenario-export.js`**, убраны только кнопка,
   обработчик и импорт. Причина → на функцию есть отдельный тест, она читается как
   заготовка API; удаление вышло бы за рамки задачи «снять обещание пользователю».
5. **Торнадо считается at-fit-time, а не по запросу.** Причина → `model_data` уже в
   памяти, переобучение не требуется, отдельный эндпоинт и его проводка через Rust —
   лишняя поверхность. Цена: у моделей, обученных до этой правки, поля не будет.
6. **Пять `WARN` линтера справки про версии в тексте не тронуты** — исторические
   пометки фич, вне задачи блока.

## 4. Зоны неуверенности

1. **Порог блокировки обучения остался на сыром знаменателе, а показ — на
   эффективном.** `ValidateStepV13:822` делает кнопку «Подтвердить роли» неактивной
   при сыром ratio < 2. Перенос на эффективный ужесточил бы блокировку действующим
   пилотам, поэтому сделан осознанный рассинхрон двух чисел на одном экране.
   Не уверена, что комментарий в коде достаточно защищает это от «починки»
   следующим разработчиком — вернуть скачок легко.
2. **`ratio_gate` по OLS может оказаться слишком мягким для байесовских проектов.**
   Проект с 30 наблюдениями и 10 столбцами получит `ratio_gate = 30/11 = 2.7` (нет
   critical), тогда как фактический байесовский запас — `30/23 = 1.3`. Предупреждение
   он увидит на фронте, но `issues` движка промолчат. Не проверяла, читает ли эти
   `issues` кто-то ещё (отчёт, honesty-гейт), кому мягкость навредит.
3. **Семантический дедуп праздников в валидаторе не учитывает `disabled_holidays`.**
   Список приходит только в конфиге обучения; на этапе валидации знаменатель будет
   завышен для пользователя, отключившего часть праздников. Величину расхождения на
   реальных проектах не мерила.
4. **Торнадо считается на КАЖДОМ обучении, его стоимость не измерена.** Внутри —
   перебор кандидатов с пересчётом вклада каналов. На синтетике 40×2 незаметно; на
   реальном проекте с 10+ каналами и длинной историей время обучения могло вырасти.
   Замера нет, порога отключения не предусмотрено.
5. **Изменение `validationHeaderMetrics` с `derived(validateData)` на
   `derived([validateData, modelEngine])`** потребовало перенести объявление
   `modelEngine` выше по файлу (мёртвая зона инициализации). Проверено типами и
   тестами, но порядок объявлений в модуле хранилищ — место, где легко получить
   тонкую поломку загрузки, невидимую в юнит-тестах.
