## 3. Осознанные компромиссы
- **`_norm_dash` в генераторе покрывает только поля терминов** (term/en/short/what/example/where), НЕ section-заголовки и статичные строки шаблона (`<title>`, докстринги). Причина: минимальное вмешательство; дыру закрывает `check_glossary_sync.py` (гейт 0×U+2014 на самих выходах ловит протечку откуда угодно). Источник сейчас 0×U+2014, так что дыра латентна.
- **`check_glossary_sync.py` сравнивает нормализованно по переносам** (`\r\n`→`\n` через `splitlines()`) — потому что `core.autocrlf=true` кладёт CRLF в рабочие файлы, а Python пишет LF; без нормализации — ложный FAIL после каждого `git checkout`.
- **CPD-15 helper копирует `.credentials.json` через copy+rename** с mtime-гейтом (`src_newer`) — вербатим-порт эталона; не «улучшать» (упрочнения #1 атомарность / #2 home_dir Err→None / #4 env_remove уже в коде, доказаны).
- **MMM «6→7 шагов»**: рабочий `glossary.html` нёс актуальное «7 шагов» (ручная правка под шаг Планирования), а источник + `glossary.js` — устаревшее «6»; поймано личной проверкой git diff всех выходов после перегенерации (сверка по одному js регресс не увидела); фактура «7 шагов» подтверждена 6 страницами справки + program-help.js.

## 4. Зоны неуверенности (прицельно для аудитора)
1. **CPD-15 атомарная замена credentials под конкурентностью** (`claude.rs::isolated_claude_config_dir`): copy в `.tmp` + `rename`; при параллельных кабинетах (несколько `run_claude_inner` одновременно) — не гонятся ли два процесса за один общий `.credentials.json.tmp` (фикс. имя, не per-process)? mtime-гейт `src_newer` при равных/недоступных mtime даёт `!dst.exists()` — корректно ли ветвление? Утечка креденшелов оператора в кабинет клиента исключена (иначе исходный дефект Oracle 0.3.9)?
2. **`check_glossary_sync.py` autocrlf-нормализация** — `splitlines()` нормализует `\r\n`/`\r`/`\n`, но построчное сравнение может пропустить различие в trailing-переводе или смешанных окончаниях внутри файла. Возможен ли ложный PASS (выход правлен вручную, но линтер не заметил → дрейф проезжает мимо гейта) или ложный FAIL на легитимном состоянии?
3. **`check_help_pdf_consistency.py` INV-50 regex** (`DOVERIT_RE`/`DI_ABBR_RE`/`CI_ABBR_RE` + `_strip_html_comments_keep_lines`): границы слова для «ДИ»/«CI» — ложные срабатывания на легитимном тексте (напр. «CI» в URL/атрибуте) или пропуски? Вырезание `<!-- -->` regex с `DOTALL` — краевые случаи (незакрытый комментарий, `-->` внутри JS-строки, сохранение номеров строк)?
4. **`build_glossary.py` парсер `parse_md`** после правок источника (новый термин OVB, изменённый заголовок posterior_ci): en-экстрактор берёт первую скобку `re.search(r"\(([^)]+)\)")` — не ломается ли en на многоскобочных заголовках/телах? Смена ключа ID_MAP на «Правдоподобный диапазон» (без скобки-en в заголовке) — резолвится ли related-якорь у ссылающихся терминов?
