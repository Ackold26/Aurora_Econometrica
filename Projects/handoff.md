# Handoff: правки после внешнего аудита сведения веток (2026-08-04)

## 1. Цель блока

Свести 22 ветки продукта в одну универсальную линию, ничего не потеряв, затем исправить дефекты,
найденные внешним аудитом этой работы. Диапазон этого handoff — **семь записей ПОСЛЕ аудита**
(`31114a3..HEAD`): они самим аудитом не проверялись. Правки закрывают четыре дефекта (два из них
существовали в продукте до сессии), ставят четыре сторожа и убирают устаревшее, воскрешённое
слиянием.

## 2. Ключевые инварианты

- **Гейт полноты:** `git log <ветка> ^HEAD` пуст по всем ссылкам `origin`; `master` идентичен
  рабочей линии. Ни одна запись истории не потеряна.
- **Единый источник глоссария:** `docs/GLOSSARY_v2_1_0.md` → генератор `tools/build_glossary.py` →
  три выхода (`src/lib/glossary.js`, `docs/glossary.json`,
  `src-tauri/help-econometrica/glossary.html`) + PDF. Правка выхода вручную запрещена — крючок
  `glossary-sync` краснеет.
- **Зеркало формулировок:** оговорка о тонких данных живёт в
  `sidecar/econometrica/utils/diagnostics.py::format_thinness_caveat` и зеркалится в
  `src-tauri/src/commands/report.rs` ДОСЛОВНО (Rust не импортирует Python).
- **Клиентский текст:** короткое тире «–», без англицизмов, **без имён клиентов и их показателей**.
- **Структурный сторож ищет только в коде продукта:** тестовый модуль отрезается по `#[cfg(test)]`,
  комментарии вырезаются; окно исходника берётся по строкам, не байтовым срезом (кириллица).
- **Удаление файлов — только в корзину** (`Microsoft.VisualBasic.FileIO.FileSystem`).

## 3. Осознанные компромиссы

- **Сторож зеркала сравнивает СМЫСЛОВЫЕ ЯДРА, а не байты** (пересечение значимых слов ≥70 %).
  Причина: побайтовое сравнение ломалось бы от любой правки пунктуации, и его бы отключили —
  а отключённый сторож хуже мягкого.
- **`PPCScatter.svelte` (382 строки) оставлен неподключённым.** Причина: он не устарел и аналога
  нет, это неподключённая ценность; удалять — терять, подключать — выходить за рамки задания.
  Вынесен владельцу отдельным вопросом.
- **Два независимых пути надёжности модели не сведены.** Причина: выбор источника — архитектурное
  решение, требующее сторожа паритета; отложено владельцем в следующий заход.
- **Три декоративных теста не починены.** Причина: один из них тянет за собой ту же архитектуру
  надёжности — чинить отдельно значит делать работу дважды. Отложено вместе с предыдущим пунктом.
- **Отброшенные обороты («результаты ненадёжны») запрещены только в КОДЕ, не в комментариях.**
  Причина: в пояснении они нужны, чтобы правку не откатили по незнанию.

## 4. Зоны неуверенности

1. 🔴 **Обезличивание глоссария правилось в источнике, но проверено только поиском имени.**
   Заменены пять примеров («Кагоцел», конкурент «Анаферон», SOV 23 %, SOM 14 %, R² 0,87).
   Не проверено: не потерял ли пример смысл после замены на «ваш бренд» / «в категории»; не
   осталось ли в глоссарии ДРУГИХ узнаваемых данных клиента, которые я не искала (я искала два
   конкретных имени). Стоит перепроверить весь корпус на признаки реальных проектов: названия
   препаратов, конкретные доли, суммы, даты флайтов.
2. 🔴 **Плашка надёжности добавлена в XLSX на строку 12 листа Executive Summary.** Не проверено
   живой сборкой отчёта: занята ли эта строка чем-то ещё при других входных данных, не наезжает ли
   на блок ниже, виден ли текст при узкой колонке (ширина A:C = 26,43).
3. 🔴 **Сторож проводки требует вызова функции из `build_markdown` и `build_xlsx` по имени.**
   Он не отличает живой вызов от вызова внутри мёртвой ветки `if false` и не проверяет, что
   результат используется. То есть проводку можно формально удовлетворить, оставив функцию
   бесполезной.
4. **Порог 70 % в стороже зеркала выбран без калибровки** — на текущих двух формулировках
   пересечение около 85 %, но насколько он устойчив к законной правке текста, не измерено.
5. **Удаление шести файлов проверено отсутствием ссылок по имени.** Динамический импорт
   (`import(...)` со склеенным путём) такой поиск не увидит.
