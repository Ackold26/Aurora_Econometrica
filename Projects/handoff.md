## 1. Цель блока

Клиент не мог открыть кабинет: файл рабочих материалов весом 34 КБ не докачивался с сервера ни разу за две недели, при этом сервер был исправен (внешний зонд с реальными параметрами клиента отдавал файл за 3 секунды). Блок делает загрузку устойчивой к обрывам канала: раздельные таймауты вместо общего дедлайна на запрос, повторы с нарастающей паузой, чтение тела порциями со сверкой длины. Те же гарантии распространены на пакет контента, бандл интерфейса, загрузчик установщика и авторизацию. Дополнительно добавлен запасной путь доставки материалов из файла и человеческий текст отказа вместо технической строки.

## 2. Ключевые инварианты

- **Общий дедлайн на запрос (`Client::builder().timeout`) на загрузках запрещён.** Только `connect_timeout` + `read_timeout` (таймаут тишины сокета): общий дедлайн рубит исправную медленную передачу и ничего не даёт против зависшего сокета.
- **Обрыв связи — повторяем; отказ по существу — нет.** 5xx, 429, 408, разрыв потока, таймаут → повтор с паузой 2/5/10/20 с, до 5 попыток. Прочие 4xx (403 «нет лицензии», 404 «нет файла») → выход сразу.
- **Усечённое тело не считается успехом.** Тело читается порциями; если сервер объявил `Content-Length`, итог обязан совпасть. В сообщение об ошибке всегда входит число полученных байт.
- **Импорт файла кабинета не доверяет источнику:** имя берётся только из последнего сегмента пути (защита от `..` и абсолютных путей), проверяется маска `[a-z0-9-]{1,40}.vault`, размер ограничен 200 МБ, содержимое обязано быть читаемым архивом, и лишь затем шифруется ключом машины.
- **Загрузчик установщика:** проверка доверенного хоста на КАЖДОМ переходе по перенаправлению (сохранено, SEC-04); частичный файл привязан к хешу адреса, чтобы новая версия не дописалась поверх байтов предыдущей; ответ 206 без внятного полного размера отвергается.
- **Клиентское сообщение об отказе** содержит причину, что делать и техническую подробность отдельной строкой; кода вида `001]` и путей к файлам в нём быть не должно.

## 3. Осознанные компромиссы

- **Докачки по частям для материалов кабинета нет** → функция `/content` на запрос части отвечает файлом целиком (200 вместо 206), проверено зондом. Пока сервер не поддержит `Range`, докачка на клиенте невозможна. Записано комментарием в коде, вынесено в следующую сессию.
- **Тело читается целиком в память** → файлы кабинетов весят единицы–десятки КБ; потоковая запись на диск усложнила бы код без выигрыша. Для установщика (245 МБ) применён другой путь — запись в `.part`.
- **Повторов у авторизации три, а не пять** → ответ крошечный, а пользователь ждёт открытия окна; пять попыток затянули бы старт на минуты.
- **Ручной импорт материалов сделан кнопкой в настройках, без автоматизации** → запасной путь для закрытых сетей; владелец отдельно отверг его как системное решение.
- **Константа `DOWNLOAD_TIMEOUT_SECS` удалена, а не оставлена** → после перевода всех загрузок стала недостижимой; мусор, порождённый самой правкой.

## 4. Зоны неуверенности

1. **Классификация повторяемых кодов.** 408 и 429 отнесены к повторяемым, 403/404 — к фатальным. Если сервер начнёт отвечать 403 на временную перегрузку (а не на отсутствие лицензии), клиент замолчит навсегда вместо повтора.
2. **Чтение тела при отсутствующем `Content-Length`.** Функция отдаёт порционный ответ без длины, поэтому сверка не срабатывает вовсе — усечение поймается только по ошибке сокета. Если посредник закроет соединение «чисто» на середине, клиент примет обрезанный файл за полный. Ниже по течению это ловит контрольная сумма, но в `open_cabinet` контрольные суммы передаются пустым объектом.
3. **Особый случай 404 у бандла интерфейса** различается сравнением текста ошибки (`contains("HTTP 404")`). Хрупко: изменится формулировка — потеряется различение «бандла нет» и «ошибка загрузки».
4. **Импорт файла кабинета не проверяет, что содержимое соответствует ИМЕННО этому кабинету** — только что это читаемый архив. Можно импортировать материалы одного кабинета под именем другого; последствия не проверялись.
5. **Тесты устойчивости поднимают локальный сервер на случайном порту** и чувствительны к загрузке машины: при семи параллельных сборках один из четырёх изредка падал (изолированный прогон — 22 из 22 трижды). Возможен флак в нагруженном CI.
6. **Дребезг вызовов не устранён:** в журнале клиента по 4–6 одновременных запросов авторизации и по 4 параллельные загрузки одного файла при старте. Защита от параллельных загрузок есть только у установщика (`in_flight_downloads`).
