## 1. Цель блока

Перед сборкой 2.5.7 закрыть находки внешнего аудита. (а) Распознать строку «итого» в хвосте входного файла во всех
формах, где она иначе попадает в обучение или в медиаплан, и не давать ложного отказа на строках-примечаниях.

## 2. Ключевые инварианты

- Итог = строка БЕЗ распознаваемой даты в ХВОСТЕ таблицы, в которой есть числа И (слово-признак ИЛИ совпадение с
  суммами столбцов). Строки без даты в середине данных – не итог (другая ошибка, прежнее поведение).
- Итог не попадает в модель никаким путём: проверка данных выдаёт критическую проблему с номером строки файла,
  байесовское и OLS-обучение отказывают тем же текстом (`planning.total_rows_message`).
- Колонки даты и KPI для детектора определяются тем же способом, что в проверке данных
  (`detect_column_role_with_confidence`), а не параметром по умолчанию `date_column='date'`.
- Хук: «бить узко, смотреть широко» – снятие только своих процессов (фильтр учётной записи в `tasklist` снятия),
  проверка живости без фильтра учётной записи. Утилиты без полных путей, кроме `$SYSDIR\find.exe` (правило файла).
- На 38 реальных файлах данных дерева – 0 срабатываний детектора итога.

## 3. Осознанные компромиссы

- Итог → отказ, а не тихое отбрасывание строки: файл читают ~40 мест движка, выброс только в обучении разводит модель
  с декомпозицией/сценариями. Человек удаляет строку по номеру.
- Совпадение с суммой неотрицательного KPI – самостоятельное доказательство итога (одного совпадения достаточно);
  при KPI со знаком решает большинство совпадений – чтобы не принять за итог случайное совпадение.
- Столбцы, где выше меньше двух ненулевых значений, в сверке сумм не участвуют – иначе столбец из одного числа
  «совпадает с суммой» сам с собой.
- Сторож хука: исполняемые пробы требуют Windows + `makensis` из комплекта Tauri; в среде без них помечены пропуском,
  статическая часть сторожа работает всегда.
- M-5: при отсутствии каналов с mROAS > 0 вместо диаграммы – надпись; сама диаграмма не перерисовывается.

## 4. Зоны неуверенности

1. **Ложные срабатывания детектора на данных, которых в дереве нет:** хвостовая строка «прогноз» с числами без даты,
   строки-подытоги по годам в середине файла, KPI со знаком (прибыль), где сумма случайно совпала по большинству.
   Стресс 30 файлов × 6 хвостовых строк дал 0 ложных, но это синтетика.
2. **Номер строки файла в сообщении** при пропущенных пустых строках, многострочном заголовке, листе xlsx с данными не
   с первой строки – верен ли он для человека, открывающего файл в Excel.
3. **Хук `/FO CSV` + `find /I """${IMAGE}"""`:** экранирование тройных кавычек в NSIS-строке внутри `cmd /c`, поведение
   при локализованном выводе `tasklist` с запятыми и при имени пользователя со спецсимволами `& ( )` (известный остаток
   эталона SA); стандартный пользователь (не администратор) живьём не проверен – только пониженный токен администратора.
4. **M-5:** не задевает ли условие соседние ветки слайда (OLS-модель, один канал, все каналы с mROAS = 0 ровно).
