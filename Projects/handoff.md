# Handoff блока: P0.7 сертификат методологии + P0.8 термины (сессия 2026-08-03)

Ветка `feat/econ-canon-p0`, дерево `Dev/Aurora_Econometrica_canon`.
Вход аудита — `Projects/audit.diff` (446 строк): часть блока, ещё не проходившая внешний
аудит. Два предыдущих прохода уже сделаны и разобраны: по блоку целиком
(`Projects/audit_findings_p07.md`, 10 находок) и по починке этих находок
(`Projects/audit_findings_fix_p07.md`, 9 находок). Текущий diff — правки, закрывшие второй
набор находок, плюс пометка долга.

## 1. Цель блока

Подключить сертификат методологии: криптографический отпечаток (SHA-256 над JCS RFC 8785)
расчёта MMM, который проверяющая сторона (`verify.auroraai.pro`, отдельный продукт) может
сверить независимо. До этой сессии модуль существовал 360 строк и не вызывался ниоткуда —
сертификатов у клиентов не было. Теперь сертификат считается при декомпозиции, кладётся в
результат, доезжает в отчёт и на слайд методологии. Параллельно закрыт P0.8: расшифрованы
сокращения в шапке шага и заведены три отсутствовавших термина глоссария.

## 2. Ключевые инварианты

1. **Схема хеша заморожена на v1.3 — ровно пять полей** (`bundle_manifest_hash`, `model_spec`,
   `decomposition_summary`, `channel_roi`, `certificate_version`). Ответа проверяющей стороны
   на запрос от 2026-08-03 нет; поле сверх схемы выпадает у неё при десериализации и ломает
   сверку отпечатка. Всё остальное (паспорт воспроизводимости, статусы проверок) лежит РЯДОМ
   с payload, не внутри.
2. **Ноль и умолчание не подставляются никогда.** Величины нет — либо ключ отсутствует, либо
   отказ с названной причиной. Правило нарушалось дважды и оба раза ловилось аудитом:
   подстановка типа KPI загрузчиком (Critical) и достройка карты адстоков умолчанием (High).
3. **Расчёт важнее заверения:** любая неудача сертификата превращается в статус
   (`unavailable`), а не в исключение наружу — разбивка обязана дойти до клиента.
4. **Клиенту не уходит техническое имя исключения** и не обещается больше, чем проверено.
5. **Числовые пороги не дублируются в `src/`** — единый источник, сторож паритета краснеет.
6. **Правка глоссария — маршрут §18:** источник → генератор → три выхода в одной записи,
   плюс пересборка PDF-манифеста справки.

## 3. Осознанные компромиссы

- **`bundle_manifest_hash` наполняется манифестом файла модели**, хотя имя поля унаследовано
  от «бандла» — директории выгрузки данных, которой в продукте не существует (свип даёт ноль
  упоминаний вне самого модуля). Решение владельца 2026-08-03; клиентский текст прямо говорит,
  что отпечаток покрывает файл модели, а не выгрузку данных.
- **Ветка расширенной схемы v2.0.0 не тронута**, хотя в ней найден дефект написания ключа
  (`analysisMode` против `analysis_mode` у проверяющего): правка внешнего контракта без
  ответа второй стороны запрещена. Ветка при этом недостижима — версия модели до неё не
  доходит.
- **`certificate_version` остаётся внутри хешируемого payload**, хотя нормативный раздел
  контракта перечисляет в v1.3 четыре поля. Не чинится по той же причине — внешний контракт.
  Смягчение: внешняя проверка клиенту нигде не обещана.
- **Фактически применённый тип адстока не выводится** из косвенных признаков. Модель хранит
  настройку `'auto'`, а не результат её применения; вывести «геометрический» из пустоты
  весовых параметров означало бы вернуть ту самую подстановку. Помечено как долг продукта.
- **Каналы с маркером неприменимости выброшены только из раздела окупаемости**, во вкладах
  остаются: нулевой вклад — факт, нулевая окупаемость — нет.

## 4. Зоны неуверенности

1. **Переменный набор ключей `model_spec`.** После правок он зависит от ветки расчёта: у
   режима малых данных нет `kpi_likelihood`, при отсутствии источника нет `adstock_types`.
   Прошлый аудитор счёл это безопасным (поле объявлено свободной формой у проверяющего), но
   разные модели теперь дают структурно разные описания — не создаёт ли это трудностей для
   стороны, которая захочет сравнивать два сертификата между собой.
2. **Условие «карта адстоков собирается только целиком»** (`len(восстановленные) ==
   len(параметры)`). Если у части каналов тип известен, а у части нет, ключ не кладётся вовсе.
   Не уверена, что это лучше частичной карты с явным пропуском.
3. **Порядок источников описания модели**: конфигурация → запись обучения → отказ, причём
   для режима малых данных запись обучения источником не считается. Логика выведена из того,
   какая ветка что записывает; стоит проверить, не существует ли ветки, которая пишет верхний
   уровень, но не пишет конфигурацию.
4. **Подвал блока в отчёте печатается по наличию отпечатка**, а список строк — по наличию
   строк. Два разных условия для соседних кусков одного блока: возможна комбинация, где
   список есть, а подвала нет, и текст читается оборванным.
5. **Тексты вердиктов проверки базы** переписаны в терминах вероятности («ниже 20 %», «от 20
   до 80 %»). Числа взяты из констант движка, но продублированы в клиентском тексте словами —
   это тот же класс, за который сторож паритета уже краснел на порогах качества.
