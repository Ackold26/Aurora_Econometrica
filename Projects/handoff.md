# Handoff — блок «кабинет эконометриста + петля Авроры» (diff 1f76a14..HEAD)

> База аудита: `1f76a14` (последний внешний diff-аудит блока ассистента Авроры,
> уже пройден и починен в этой же сессии). Здесь — код ПОСЛЕ него: прокачка
> кабинета эконометриста (S1-S4) + петля улучшения ассистента (тематизация RAG +
> атрибуция) + доводки по эвал-прогону. Ветка `feat/econ-avrora-assistant`.

## 1. Цель блока
Кабинет-советник «эконометрист» пережил редизайн роли («консультант ПОВЕРХ
детерминированного pipeline», не «Claude сам считает MMM»), но системный промпт и
контракты команд остались от прошлой эпохи. Блок выпрямляет роль (промпт под 6
живых UI-команд, legacy отдельно), чинит сломанный контракт данных
(консультационные команды получают JSON-артефакты движка ВЛОЖЕНИЕМ в сообщение по
правилу №10, а не чтением `%APPDATA%`, что запрещал runtime), ставит SSOT-страж
дрейфа 11 копий кабинета и эвал-харнес (детерминированные фикстуры + автогрейдеры).
Плюс петля ассистента: RAG-запрос тематизируется домен-терминами шага двуязычно,
источник рендерится читаемым именем.

## 2. Ключевые инварианты
- **INV-50 (страж чисел):** числа в ответе LLM ⊆ числам приложенных фактов. Вырезка
  телеметрии (`stripOptTelemetry`/`stripModelTelemetry`/`stripDecompTelemetry`) НЕ
  должна убирать содержательные числа, которые ассистент цитирует (агрегаты каналов,
  метрики) — только служебную поточечную графику.
- **Контракт данных = только через сообщение.** Консультационные команды не читают
  файлы (`%APPDATA%`/workspace) — runtime дописывает запрет env-путей в CLAUDE.md
  сессии. Данные приходят блоком «=== Данные проекта ===». Отсутствующий шаг → строка
  «нет – шаг «…» не пройден», не пустой объект.
- **Один источник INV-50-стража:** `graders.mjs` эвал-харнеса ИМПОРТИРУЕТ прод
  `src/lib/insights-grounding.js`, не копирует. Аналогично `build_message.mjs`
  импортирует прод `buildProjectDataBlock` (единый контракт).
- **SSOT-страж дрейфа:** строгая проверка пары продукта (`--strict-pair`) активна
  ТОЛЬКО в основном дереве; в linked worktree откладывается до мержа.
- **Тематизация RAG двуязычна** (рус+англ) — иначе англоязычные MMM-статьи тонут.
- Клиентский/промптовый текст: короткое тире «–», русский без англицизмов.
- JS+JSDoc, НЕ TypeScript. Гейты: vitest 1142 · svelte-check 0 · cargo обе редакции.

## 3. Осознанные компромиссы
- **Легаси 9 расчётных команд не удалены, вынесены в `LEGACY_COMMANDS.md`** — скрыты
  из UI, но доступны ручным вводом (backward compat); удалять = ломать путь.
- **Вырезка телеметрии по фиксированному списку ключей** (slsqp_diagnostics,
  response_curves, ols_quality, actual_vs_predicted, time_series, waterfall), не по
  эвристике «тяжёлый массив» — явный список предсказуем; цена — новый графический
  ключ движка потребует ручного добавления.
- **`humanizeSource` — эвристика по формату имён файлов корпуса**, fallback = `_`→` `.
  Имена не стандартизованы; экзотический формат даст сырое имя (не падение).
- **validation в блоке данных — компактная выжимка** (ratio/колонки по ролям), не
  сырой `validateData.result` — сырые статистики колонок раздувают промпт.
- **Живой RAG в рантайме не прогнан** (туннель заблокирован ssh-агентом машины);
  гипотеза тематизации доказана отдельной живой пробой узла Б (adstock→Jin 2017).

## 4. Зоны неуверенности
1. **`stripModelTelemetry` на ОБЕ формы** — обёртку стора `{diagnostics}` и плоскую
   фикстуру. Проверить: при обёртке вырезается `diagnostics.ols_quality`, а не
   теряется весь diagnostics; плоская форма (харнес) не проскакивает мимо вырезки.
2. **`buildRagQuery` лимит ~400 символов** — обрезка длинного вопроса + термины.
   Проверить: обрезка не рвёт по середине терма; двуязычные термины всегда попадают
   (не вытесняются длинным вопросом за лимит).
3. **`humanizeSource` регексы** — фикс `\b`→без границы для года в `Jin_2017`. Края:
   имя без года и без «- Автор», несколько годов, пустая строка/undefined.
4. **inject данных в `ChatPanel.sendMessage`** — блок аппендится к сообщению для
   Claude, но отображаемый/сохраняемый текст чата должен остаться ОРИГИНАЛЬНЫМ.
   Проверить: `messageToSend` идёт только в invoke, а `text` — в историю/UI.
5. **Гейт продукта для inject** — блок при `$isEconometrica &&
   ECON_DATA_COMMANDS.includes(...)`. Проверить: для не-econometrica и
   не-консультационных команд блок НЕ протекает.
