# Живые пробы пути отказа обновления – s46, 13.09.2026

Два сценария отказа обновления прогнаны на работающей программе (режим разработки,
мост MCP), текст на экране снят дословно из DOM. Третий сценарий снят попутно –
он лежит на том же пути и стоил двух минут.

Проба 2 (отказ в правах администратора) намеренно НЕ проводилась: честно она
проверяется только на настоящем установщике, имитация дала бы ложное «проверено».

## Как добивалась сценариев (дословно)

1. Временно переведены оба адреса проверки обновления на локальный сервер
   (оригинал файла сохранён отдельно, откат доказан ниже):

   ```
   src-tauri/src/commands/updater.rs:52  → "http://127.0.0.1:8765".to_string()
   src-tauri/src/commands/updater.rs:56  → "http://127.0.0.1:8765/app-update".to_string()
   ```

2. Поднят локальный сервер манифеста во временной папке:

   ```
   cd <скратчпад>/upsrv && python -m http.server 8765 --bind 127.0.0.1
   ```

   Манифест `upsrv/aurora-econometrica-gui/latest.json`:

   ```json
   {
     "version": "99.0.0",
     "download_url": "https://ackold26.github.io/rosst-updates/aurora-econometrica-gui/latest.json",
     "checksum": "",
     "release_notes": "Проба отказа обновления s46 – манифест без контрольной суммы",
     "mandatory": false,
     "min_version": ""
   }
   ```

   Адрес загрузки выбран настоящий и доверенный (`.github.io`, 613 байт) намеренно:
   иначе загрузка отсеялась бы раньше на проверке доверенного хоста (UP-002) и до
   проверки суммы дело не дошло бы. Проверка POST на локальный сервер даёт 501 –
   значит основной канал отказывает и работает запасной, как в бою.

3. Подъём программы: `npm run tauri:dev`; подключение через `mcp__tauri__driver_session`
   (порт 9223). Путь человека по экрану: баннер «Доступна версия 99.0.0» → кнопка
   **«Обновить сейчас»** → блокирующее окно «Требуется обновление» → кнопка
   **«Скачать и установить»**.

4. Для пробы 1 локальный сервер погашен (`taskkill`), в уже открытом окне нажата
   кнопка **«Повторить»**. Так воспроизводится обращение к недоступному адресу
   обновления – ровно тот вызов, который отказывает и при отсутствии сети.

## Проба 1 – адрес обновления недоступен

Снимок: `Projects/probe_s46/proba1_net_seti.png`

Заголовок окна: **Требуется обновление**
Под ним: «Версия 99.0.0», примечания к версии из манифеста.

Дословный текст на экране:

> Сервер обновлений сейчас недоступен, и запросить новую версию не удалось. Без обновления продолжить работу не получится – проверьте подключение к интернету и нажмите «Повторить» через несколько минут.

Подпись раскрытия: **Подробности · UP-001**
Под раскрытием (сырая строка для поддержки):

> [UP-001] Update request failed: error sending request for url (http://127.0.0.1:8765/aurora-econometrica-gui/latest.json)

Кнопка на экране одна: **Повторить**.

**Вердикт: сходится с ожидаемым.** Человек читает про проверку подключения к сети.
Слова «напишите в поддержку» в этом сценарии нет вовсе; адрес поддержки на экране
не появляется. Английская служебная строка спрятана под раскрытие, первым её человек
не видит.

Оговорка, чтобы не выдавать большего, чем проверено: имитирована недоступность
адреса обновления (соединение отвергнуто), а не выключенная сетевая карта –
отключать сеть на этой машине было запрещено, там шла другая работа. Путь в коде
при этом ровно тот же: отказ рождается на `client.send()` в `check_supabase` и затем
в `check_github_pages`, оба помечены кодом UP-001 (`updater.rs:117–172`), а отказ
разрешения имени даёт тот же класс отказа `reqwest`. Различий в тексте на экране
между «имя не разрешилось» и «соединение отвергнуто» путь не делает: текст выбирается
по коду UP-001, а не по деталям.

## Находки

### Н-1. Совет «перезапустите программу» – а единственная кнопка «Повторить» (не чинила)

Важность: средняя. Класс: тупик в блокирующем окне.

В ветке «сервер не предлагает новой версии» текст честно говорит: повторять
бессмысленно, перезапустите программу. Но в окне ровно одна кнопка – **«Повторить»**
(`src/lib/components/UpdateBlockingOverlay.svelte:127–129`), а окно блокирует работу
целиком. Человек, который делает то, что написано на кнопке, будет получать один
и тот же текст сколько угодно раз; чтобы выйти, надо догадаться закрыть программу
крестиком окна.

Сторож это поймать не мог по устройству: он проверяет ТЕКСТ (и даже требует, чтобы
в нём не было слова «Повторить», `updateErrorText.guard.test.js:208–209`), но не проверяет,
какие кнопки при этом предложены.

Что предлагаю (не вносила – это правка поведения окна, а не текста, и решение за
владельцем): в состоянии отказа показывать вторую кнопку **«Закрыть программу»**.
Она уместна во всех отказах без исключения – окно и так блокирует работу, а в двух
ветках из трёх («без контрольной суммы», «нет новой версии») повтор заведомо не
поможет. Текст менять не нужно, он верный.

### Н-2. Под «Подробностями» иногда лежит дословная копия того же текста (косметика)

Важность: низкая. Для помеченных `[клиенту]` отказов (UP-003 без суммы, «нет новой
версии») сырая строка отличается от видимого текста только префиксом `[UP-003] [клиенту]`.
Поддержке она не добавляет ничего, человеку показывает одно и то же дважды. Не дефект
– следствие того, что деталь и есть клиентский текст. Трогать не советую: выкидывать
раскрытие по признаку «совпало с видимым» дороже пользы.

### Чего НЕ нашла (проверяла целенаправленно)

- Совета «освободить место на диске» ни в одном из трёх сценариев нет.
- Обещания «повтор поможет» там, где он не поможет, нет.
- Адрес поддержки в сетевом сценарии не всплывает (это была находка H-2 аудита s43 –
  она закрыта и держится).
- Английские служебные строки первыми на экран не выходят ни в одном сценарии.

## Чего проверить не удалось

1. **Проба 2 – отказ в правах администратора.** Не моя по заданию и честно
   воспроизводится только на настоящем установщике: ветка живёт в
   `updater.rs:697–712` и срабатывает по коду возврата PowerShell при незакрытом
   запросе повышения прав. В режиме разработки ветвь выбора (`needs_elevation`)
   решается пробой записи в каталог сборки, который записываем, – повышение не
   запрашивается вовсе.
2. **Физическое отсутствие сети** (выключенная карта, отказ разрешения имени).
   Запрещено условиями задачи – на машине шла другая работа. Проверена
   недоступность адреса; путь в коде и текст на экране от этого не зависят
   (обоснование в разделе пробы 1).
3. **Ветка «не удалось получить ссылку на обновление»**
   (`UpdateBlockingOverlay.svelte:97`) – она включается, когда окно обязательного
   обновления открыто, а адрес загрузки в манифесте пуст. Отдельного прогона не
   делала: сценарий требует третьего вида подделки манифеста и лежит вне двух
   заказанных проб.
4. **Настоящая установка после успешной проверки суммы** – не трогала намеренно:
   это перезапись работающей программы установщиком.
