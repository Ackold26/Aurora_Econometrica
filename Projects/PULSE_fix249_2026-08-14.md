# Пульс работы: правки High-1..High-4 (аудит 2.4.9)

## Задача своими словами

Надо закрыть четыре серьёзные находки внешнего аудита в блоке Aurora Econometrica.
Три из них — про снятие процессов-спутников: сейчас проверка «свой ли это процесс» слишком
доверчивая (сравнивает только имя файла, держит широкое окно по времени и работает по номеру
процесса, который между проверкой и снятием может достаться чужому). Четвёртая — про потерю
данных клиента: при сохранении выгрузок кампании три пути отказа проглатываются молча, журнал
рапортует успех, а следом рабочий каталог удаляется вместе с единственной копией.

## План

1. Прочитать разделы High-1..High-4 отчёта аудита целиком.
2. Изучить `sidecar_runtime.rs`, `econ_sidecar.rs`, `campaign.rs`, `lib.rs`; установить,
   есть ли у движка дочерние процессы (решает судьбу `/T` в High-3).
3. High-1 + High-2 (одно место): полный путь образа в файле состояния + обратная совместимость;
   асимметричное окно допуска (+5 с / −300 с). Тесты, включая новый на асимметрию.
4. High-3: держать дескриптор процесса от наблюдения до снятия, снимать `TerminateProcess`;
   решение по потомкам обосновать явно.
5. High-4: `fatal` в `PersistExportsResult`, заполнение на всех трёх путях, печать в `lib.rs`
   перед удалением; та же проверка для `forward_exports_to_inbox`. Тест на подменённый каталог.
6. `cargo check` → `cargo test` (один раз, в конце) → запись изменений → отчёт.
