## Что изменено

Обе функции пары приведены к эталону Эконометрики (`5c34d7a` плюс High-4 аудита 2.4.9):
структура итога со списком сохранённого, поимённым списком отказов и признаком фатального
отказа; закрыты четыре прежде проглоченных пути — `create_dir_all`, `read_dir`, определение типа
записи и сам `fs::copy`. Намеренная перезапись во входящих при совпадении имени сохранена
(входящие — рабочая папка одного запуска, а не архив кампании).

`copy_brief_files` — по эталону `79e3fad`, включая закрытый тихий путь: несуществующий исходный
путь раньше пропускался вообще без следа, теперь виден поимённо в отказах.

Оба вызывающих в `lib.rs` обновлены под новый договор; других вызывающих в кодовой базе нет.

## Грабли среды, стоившие исполнителю трёх прогонов

1. Часть бинарных файлов не в git (`src-tauri/bin/`, `src-tauri/python/` — ~380 МБ суммарно),
   поэтому свежая рабочая копия их не получает; пришлось копировать из основного дерева.
2. `robocopy` через оболочку Bash копирует ноль файлов: MSYS принимает флаг `/E` за путь и
   подставляет `E:/`. Лечится запуском через PowerShell.
3. Две сетевые пробы подвисли на ~10 минут при 2,2 с процессорного времени — то есть подвис
   под нагрузкой, а не долгая работа.

## Чего правка НЕ закрывает

* Доказательство мутацией проведено для одного носителя из трёх. Для двух других тесты написаны
  по эталону, но их способность краснеть на этом дереве не проверялась.
* Полный прогон одним заходом не выполнен (см. CPD-86).
* Интерфейс сигнала о частичной потере не получает — только журнал. У Эконометрики этот долг
  закрыт отдельно (`ea4d31d`), сюда не переносился.
* Ветка не слита и не отправлена на сервер.
