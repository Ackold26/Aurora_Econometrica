Быстрый старт

1

Подготовь данные

XLSX/CSV: date + KPI + медиа-столбцы. Минимум 20 строк на 5 каналов. подробнее

2

Импорт + Валидация

Перетащи файл. Светофор покажет готов ли датасет, автоопределит роли столбцов.

3

Стоимость юнитов

Если есть TRP / impressions — укажи ₽/юнит. Без этого ROAS будет в native-единицах и несопоставим.

4

Обучение модели

MCMC (3–15 мин). Результат — MQS, R², декомпозиция вкладов каналов.

5

Оптимизация

Блоки A–E: текущий бюджет, найти оптимум, what-if, прогноз с инфляцией, сценарный анализ.

6

Отчёт

PPTX + XLSX с графиками и комментариями. Готово к отправке руководству.

Советы

  • Данные помесячные по умолчанию, но недельные тоже работают — система сама распознает частоту.
  • Соотношение периоды / каналы ≥ 4 — рекомендуемое. < 2 — критически мало, MQS будет ограничен.
  • Смешивать TRP и рубли в одной модели можно, но тогда обязательно укажи стоимость юнита — иначе ROAS не сопоставим между каналами.
  • Если видишь ROI 500× — это сигнал переобучения. Проверь Ratio и unit_costs.
  • MCMC чувствителен к данным — при R-hat > 1.1 модели доверять нельзя, увеличь warmup или сократи каналы.
  • Отчёт в Report — не статичный текст, а живая выборка из твоей модели. Настрой Стоимость юнита и пересобери.
  • Любая кнопка «?» в интерфейсе → откроет нужный раздел справки в браузере.

Изменения v1.0.16 (math-fix v1.4 Section C, 2026-04-29)

  • Three-way alignment декомпозиции, оптимизации и финального отчёта — единый источник правды для mROAS, action labels, channel-level рекомендаций. Customer не видит противоречий между tab'ами.
  • Money-axis mROAS — все каналы (TRPs/clicks + рубли) сравниваются в единой денежной шкале. Закрыт mixed-units bug (TRPs показывал 110×, money — 0.03×).
  • Auto-apply optimal — после расчёта оптимизации слайдеры автоматически переходят на оптимальные позиции с animation 800ms. KPI прогноз обновляется live.
  • Response Curves markers — текущая (○ серый) и оптимальная (★ цвет канала) точки на каждой кривой.
  • Edge-case banners на странице Оптимизации: baseline_zero (медиа-вклад=0), binding_constraints (все каналы упёрлись в Min/Max), converged_at_current (близко к оптимуму). Customer понимает почему +0%.
  • Per-channel override warning — банер при changes к global Min/Max если есть индивидуальные overrides.
  • Унифицированные action labels — Scale / Hold / Watch / Reduce / Cut / Uncertain (см. Methodology, глоссарий).
  • SCQAR honest narrative — budget_dominator отделён от leader: «{TRPs} занимает 92% бюджета, но даёт 10% эффекта». Reallocation использует cut_source / scale_destination от optimizer signal.
  • Validate state sync (L1) — единый source of truth для excluded columns, persistence к project.json для cross-session restore.
  • Settings cleanup — упрощённый блок Лицензии, удалены legacy блоки.
  • Grammar fixes — правильное склонение «1 период / 2-4 периода / 5+ периодов».
  • MQS labels alignment — единая 5-tier шкала между frontend и backend (Отличное / Хорошее / Приемлемое / Слабое / Ненадёжное).
  • Verdict CI suffix — wide-CI каналы получают «(низкая уверенность)» suffix вместо подавления informative verdict.
  • Единая кнопка «Создать отчёт» — выбор формата (PPTX / XLSX / HTML) через radio + одна кнопка генерации. Один файл за нажатие — экономия CPU/времени по сравнению с «выпуском всех форматов про запас».
