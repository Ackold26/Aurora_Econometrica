## Шероховатости (заполняется по ходу)

1. **UX (исправлено в live)** — в группе «В рублях» было 3 карточки KPI: Выручка / Доход / Прибыль. Доход — дубликат Выручки (само описание гласило «Аналог выручки»). Убрано в `KPISelector.svelte`, теперь 2 карточки. Старые проекты с `kpi_type='revenue'` продолжают читаться через kpi_registry (backward compat).
2. **UX (исправлено в live)** — двойной scrollbar (внешний `.pipeline-main` + внутренний `.validate-v13`/`.validate-step`). Убран `overflow-y: auto` с обоих компонентов шага Валидация — родительский layout уже владеет scroll. Теперь один scroll слева и один справа в инсайтах.
3. **UX (исправлено в live)** — на карточке «ROI режим» добавлен badge **«90% моделей»** (anchoring для бренд-менеджера) + унифицирована подпись «KPI любой» на обеих карточках (раньше на ROI было «KPI любой (продажи / лиды / упаковки)», на Эффективности — «KPI любой»; теперь одинаково).
4. **UX (исправлено в live)** — на ROI карточке добавлен badge «**90% моделей**» (anchoring); унифицирована подпись «KPI любой» на обеих карточках режима.
5. **UX (исправлено в live)** — текст «Зачем этот шаг?» в KPISelector переписан без англицизмов: «CPU (cost per unit)» -> «стоимость одной единицы», «Custom counted metric» -> «Своя метрика», убрана упоминание «выручки» (это был дубликат Дохода). 
6. **UX (исправлено в live)** — карточка «Выданные карты»: подпись и описание расширены — «карты лояльности, банковские карты» вместо «loyalty cards».
7. **UX (исправлено в live)** — массовая замена длинных тире (—) на короткие (-) во всех Svelte/JS файлах src/ (472 замены, 0 регрессий, 570/570 vitest passed). Правило сохранено в memory: больше длинных тире не использовать.
8. **UX (исправлено в live)** — Импорт: компактная dropzone когда файл загружен (was 120px воздуха), сокращены padding/gap, превью таблицы данных ограничено 290px с внутренним scroll (примерно 8 строк видны сразу). Кнопка «Далее: Валидация» теперь помещается на первый экран без скролла. Двойной scroll убран (как на Валидации).
9. **UX (откладывается в rc2)** — инсайты на под-шаге **«1. Целевая метрика»** не контекстные: показывают анализ каналов и ролей (релевантно под-шагу 2). Идеально на этом под-шаге показывать:
   - **(A) Подсказку режима из данных:** «У вас N каналов в ₽ и M в физических метриках → ROI работает» / «Все каналы в рублях — идеальный кейс ROI»
   - **(B) Подсказку выбора KPI:** «KPI определён автоматически: 'Продажи в руб.', 31 наблюдение, без пропусков»
   - **(C) Якорь на типичный выбор:** «90% наших пилотных проектов используют ROI режим» (через badge на карточке + текстовый инсайт)
   - **(D) Риски выбора:** «Если ТВ шёл по бартеру — выбирайте Эффективность, иначе ROI там будет фантомным»

   **Главное отличие:** инсайты должны **направлять решение** (что выбрать), а не констатировать качество данных (это для под-шага «Роли колонок»).

   **План реализации в rc2 (~2-3 часа):** разбить `validateInsights()` на четыре функции по под-шагам (`validateKpiInsights`, `validateRolesInsights`, `validateMetricsInsights`, `validateConfirmInsights`); в `InsightsPanel.svelte` маршрутизировать по `currentSubStep`.
