# Сценарий пилотной проверки — Кагоцел РФ+ (v2.1.0)

> **Цикл:** v2.1.0, Партия 1 п.1.2
> **Цель:** Полный проход помощника от загрузки файла до результата + сценария «что если».
> **Время:** 30-40 минут активной работы + 1-2 часа фоновой работы модели.
> **Кто выполняет:** Антон, с записью наблюдений по чеклисту ниже.

---

## Перед началом

- [ ] Aurora MMM Optimizer запущен (через `npm run tauri dev` или установленная сборка)
- [ ] Файл данных под рукой:
  `sidecar/econometrica/кагоцел-рф--данные-для-эконометрики---на-ммх-1505-26--4/`
  (актуальный snapshot 15 мая)
- [ ] Открыт блокнот / заметки для записи находок
- [ ] Засёк время старта

---

## Шаг 1 — Загрузка файла (ожидание: 30 сек)

**Действия:**
1. На главном экране нажать «Новый проект»
2. Ввести название проекта: `Кагоцел РФ+ пилот 2026-05-16`
3. Выбрать отрасль из выпадающего списка (новое поле v2.0.2):
   - В списке должна быть «Фарма (OTC)»
4. Нажать «Создать»
5. На втором экране перетащить или выбрать `.xlsx` файл из папки Кагоцел

**Проверки:**
- [ ] Прогресс-бар показывает «Чтение файла»
- [ ] Файл прочитан без ошибок (нет красного баннера)
- [ ] Если файл большой (>10 МБ) — есть лоадер
- [ ] Открывается экран автоопределения колонок

**Если что-то не так:**
- Записать точное сообщение об ошибке
- Сохранить файл `aurora.log` из `%APPDATA%\aurora-econometrica-gui\logs\`

---

## Шаг 2 — Подтверждение целевой колонки

**Ожидание:** Aurora сама подсветит колонку «Продажи Кагоцел РФ+» или похожую.

**Действия:**
1. Проверить, что подсветка падает на правильную колонку (продажи)
2. Если нет — выбрать вручную из списка
3. Нажать «Подтвердить»

**Проверки:**
- [ ] Анимация подтверждения сработала (зелёный pulse + check-icon) — это новая фишка v2.1.0
- [ ] Переход на следующий шаг плавный, не дёрганый
- [ ] Над прогресс-баром показано «Шаг 2 из 6» (или 3 из 6)

---

## Шаг 3 — Подтверждение каналов

**Ожидание:** Aurora найдёт 4-7 медиа-каналов и предложит их.

**Действия:**
1. Просмотреть список найденных каналов
2. Для каждого канала — подтвердить роль (бренд / перформанс / контроль):
   - ТВ → бренд (ожидаемая подсветка зелёным)
   - Digital / OLV → перформанс
   - Цена / промо → контроль (controls)
3. Если что-то неправильно классифицировано — поправить вручную
4. Нажать «Применить ко всем каналам этого типа» — должна сработать анимация stagger (v2.1.0 фишка)
5. Нажать «Подтвердить»

**Проверки:**
- [ ] Все каналы определены (ничего не пропущено)
- [ ] Роли по умолчанию совпадают с ожидаемыми
- [ ] Анимация копирования настроек проигралась (последовательное мигание)
- [ ] Tooltip при наведении на «бренд / перформанс / контроль» — даёт пояснение (v2.1.0 фишка)
- [ ] WhyThisStep панель открывается и закрывается плавно

---

## Шаг 4 — Настройка плана (KPI + бюджет)

**Действия:**
1. Выбрать тип задачи: «Оптимизация бюджета» (или «Прогноз», или «Сценарий»)
2. Указать диапазон периода (последние 12 месяцев + горизонт прогноза 3-6 месяцев)
3. Если выбран бюджет — указать общий бюджет (тот же что в файле или + 20%)
4. Указать unit_cost для каналов где Aurora не подсмотрела (см. UnitCostEditor)
5. Нажать «Дальше»

**Проверки:**
- [ ] Tooltip при наведении на KPI selector работает
- [ ] Подсветка обязательных полей если что-то не заполнено
- [ ] Поле «отрасль» (Industry) подгрузило CPP defaults — есть подсказка

---

## Шаг 5 — Контекстные факторы

**Действия:**
1. Просмотреть автоопределённые сезонные факторы и праздники
2. Если что-то лишнее — снять флажок
3. Если что-то не учтено (например запуск нового SKU) — добавить
4. Нажать «Подтвердить»

**Проверки:**
- [ ] Праздники РФ инжектированы (новогодние, 23 февраля, 8 марта, 9 мая)
- [ ] Сезонность определена корректно (для Кагоцел — высокая зимой)

---

## Шаг 6 — Запуск модели + результаты

**Действия:**
1. Нажать «Запустить модель»
2. **Ждать 30-90 минут** — это нормально, идёт байесовская оценка (PyMC)
3. По завершении — посмотреть результаты:
   - Декомпозиция продаж по каналам
   - ROAS / ROI / эффективность по каждому каналу
   - Прогноз на горизонт
   - Sensitivity tornado (если задан диапазон бюджета)

**Проверки:**
- [ ] Прогресс-бар показывает осмысленные стадии (sampling, finalization)
- [ ] Если падает — записать stage где упало + сообщение
- [ ] Результаты разумные (нет каналов с ROAS 1000% или отрицательным)
- [ ] R² модели > 0.5 (для Кагоцел обычно 0.7-0.85)
- [ ] R-hat макс < 1.05 (сходимость MCMC)
- [ ] Tooltip при наведении на R² / R-hat / ESS даёт пояснение (v2.1.0 фишка)

---

## Шаг 7 — Сценарий «что если»

**Действия:**
1. Открыть вкладку «Сценарии»
2. Создать сценарий: «+20% бюджет на ТВ»
3. Запустить пересчёт (быстро — посчитанная модель в кэше)
4. Сравнить с базовым

**Проверки:**
- [ ] Пересчёт быстрый (< 30 сек)
- [ ] Дельты в продажах разумные (5-15% при +20% бюджета на бренд-канал)
- [ ] Графики обновляются

---

## Шаг 8 — Сохранение и закрытие

**Действия:**
1. Нажать «Сохранить проект»
2. Закрыть приложение
3. Снова открыть Aurora
4. Открыть сохранённый проект

**Проверки:**
- [ ] Проект сохранён в `%APPDATA%\aurora-econometrica-gui\projects\<id>\`
- [ ] Внутри проекта есть `latest.pkl` (в новом формате aurora-model, см. `docs/AURORAMODEL_FORMAT.md`)
- [ ] При повторном открытии — модель загружается из кеша, не запускается re-train
- [ ] Все диагностики и результаты на месте
