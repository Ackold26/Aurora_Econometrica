## Итог одной строкой

Продукт научился жить с клиентом кварталами: при переобучении прежняя версия
уходит в архив, «Что изменилось с прошлого квартала» отвечается сравнением
поколений **с интервалами** (вердикты по перекрытию CI, Jin 2017), дрейф

живым прогоном двух bayesian-поколений реального Kagocel.

## Как устроено (для следующего читателя)

- **Сравнение** переиспользует канонический ROI/CI-путь целиком: `decompose`
  получил additive-параметры `model_path` (архивное поколение) и
  `save_results=False` (расчёт по архиву не перетирает результаты текущей —
  под сторожевым тестом). Семантика: обе версии модели пересчитаны на
  СЕГОДНЯШНИХ данных (общая база долей); параметры — из своих поколений.
- **Дрейф** переиспользует E1-механику: прогноз хвоста (точек новее окна
  обучения поколения) `predict_scenario` архивной моделью + MAPE против
  train-MAPE поколения (пороги ×1.5 / +10 пп) и наивных бенчмарков.
- **Хранение:** `models/generation_compare.json` (atomic, fsync); PPTX-слайд
  и read_only-чтение UI живут от него; без файла слайд не рисуется.

## Находки этапа

- **F-E3-1 (закрыта):** `/compute/model_history` существовал с v2.0 и не был
  доставлен (Rust/UI отсутствовали) — предсказано ROADMAP'ом, класс
  «вычислено — не доставлено».
- **F-E3-2 (закрыта):** OLS-тренер архивировал только pkl без params-снимка →
  история и дрейф слепы для OLS-проектов. Паритет восстановлен + чистка при
  ротации.
- **F-E3-3 (семантика, задокументирована):** persistence-repair подменяет
  y_actual архивного pickle полным текущим рядом → сравнение = «обе модели
  на сегодняшних данных» (желательная семантика для сравнения долей).
