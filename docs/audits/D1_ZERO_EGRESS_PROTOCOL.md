# Протокол «0 egress» — локальная редакция MMM Optimizer

> Аудит D1 коммерческой готовности, 2026-07-03. Продажное обещание для фармы
> (152-ФЗ): **данные клиента не покидают машину**. Ниже — что именно доказано,
> каким способом, и как воспроизвести.

## Вывод (для сейлов, честная формулировка)

1. **Данные клиента (xlsx, модель, результаты) обрабатываются только локально.**
   Вычислительный движок (sidecar) не содержит ни одного внешнего адреса —
   подтверждено статическим разбором кода и динамическим замером: за полный
   клиентский цикл (валидация → обучение → декомпозиция → оптимизация →
   подбор бюджета под цель → сценарий → выгрузка PPTX и HTML) зафиксировано
   **46 TCP-соединений, все — 127.0.0.1, внешних — 0**.
2. **Канал облачных советников (Claude) в локальной редакции вырезан на этапе
   сборки** — функции запуска статически недостижимы (`--no-default-features`,
   cfg-гейт `cloud_advisors` в `claude.rs`), их нельзя включить настройкой.
3. **Служебные соединения приложения** (не данные клиента): проверка лицензии
   и проверка обновлений могут обращаться к серверам Aurora (Supabase /
   GitHub Pages) — передаются только метаданные (отпечаток машины, версия
   приложения, имя хоста). В контрольном замере старта локальной редакции
   (150 секунд) внешних соединений не зафиксировано. Для сред с полным
   запретом внешнего трафика: приложение штатно работает **полностью офлайн**
   по локальной Ed25519-лицензии (офлайн-путь доказан боем: подпись + привязка
   к машине + срок — тест `offline_smoke_real_license_ed25519_roundtrip`).

## Слои доказательства

### 1. Статический: карта всех внешних адресов кода

| Точка | Адрес | Локальная редакция | Данные клиента? |
|---|---|---|---|
| Claude CLI (советники) | api.anthropic.com (через CLI) | ✂ вырезано сборкой (cfg-гейт) | — |
| Вычислительный движок (sidecar) | 127.0.0.1:75XX | локально | да — только локально |
| RAG/Parser (Creative Hub) | 127.0.0.1:7420 | локально | — |
| Авторизация/heartbeat | Supabase (functions/v1) | живо; офлайн-фолбэк Ed25519 | нет — метаданные |
| Проверка обновлений | Supabase + ackold26.github.io | живо; отказ ≠ блокировка работы | нет |
| Форма обратной связи | docs.google.com | по явному действию пользователя | нет |

Python-движок: `grep https:// sidecar/**/*.py` → **0 внешних адресов**.

### 2. Динамический: TCP-мониторинг процессов

Замер А — старт и простой GUI локальной редакции, 150 с
(`tmp/d1_egress_local.txt`): все соединения 127.0.0.1 (gui → sidecar :7529,
внутренние воркеры python). Внешних: **0**.

Замер Б — полный клиентский пайплайн через API движка, 200 с
(`tmp/d1_egress_sidecar_pipeline.txt`): validate → preflight → train
(байесовское обучение JAX-NUTS) → decompose → optimize → «бюджет под
вероятность 80%» → сценарий → экспорт PPTX + HTML. Соединений 46, все
127.0.0.1. Внешних: **0**.

### 3. Сборочный: гейт локальной редакции

```
cargo build --no-default-features        # feature cloud_advisors выключена
```
`src-tauri/src/commands/claude.rs`: `#[cfg(feature = "cloud_advisors")]` —
без фичи spawn-функции не компилируются (недостижимы), UI скрывает
кабинет-советник (`filter_by_product`). INV-52: `withGlobalTauri` живёт
только в dev-оверлее `tauri.dev.conf.json`, в прод-сборку не попадает.

## Воспроизведение (15 минут)

1. Сборка локальной редакции:
   `CARGO_TARGET_DIR=... npm run tauri build -- --no-default-features`.
2. Монитор соединений (PowerShell, от имени администратора не требуется):
   `tmp/probe_d1_egress_monitor.ps1 -Seconds 300` — пишет уникальные
   удалённые адреса процессов приложения.
3. Прогнать в приложении полный цикл на любом xlsx (или headless-скриптом
   `tmp/probe_d1_full_pipeline_api.py` против standalone-движка).
4. Проверить лог: `grep -v 127.0.0.1` → пусто (кроме служебных строк
   start/stop).
5. Для строгого «нулевого трафика»: импортировать офлайн-лицензию
   (Ed25519) и/или закрыть внешний трафик правилом брандмауэра — приложение
   продолжает полный цикл работы (офлайн-путь лицензии покрыт тестом).

## Границы доказательства (честно)

- Замеры сняты на машине разработки (Windows 11), не в стерильной среде;
  методика воспроизводима на чистой машине по шагам выше.
- TCP-монитор фиксирует установленные соединения (Established/SynSent) с
  шагом 0.4 с; DNS-запросы как таковые не логируются (при отсутствии
  TCP-соединений наружу утечка данных этим каналом невозможна, но для
  формального pen-теста рекомендуем зеркалирование трафика).
- Служебные пинги (лицензия/обновления) — часть облачной функциональности
  приложения, а не канала данных; их полное отключение = офлайн-режим.
