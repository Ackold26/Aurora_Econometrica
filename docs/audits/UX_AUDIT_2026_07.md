# UX-аудит: «эконометрика не для эконометристов» — сводный отчёт волны

> 2026-07-03 · ветка `feat/econ-e1-backtest` · задание Антона (волна UX)
> Реестр: `AUTONOMOUS_WORK_STATE_E1_BACKTEST.md` · Карта пути: `UX_JOURNEY_MAP.md`
> Рамка: упростить путь и понимание БЕЗ потери профессионализма и точности.

## Итог одной строкой

Путь «файл → бюджетная рекомендация» на реальном Kagocel занимает **≈17 минут
(из них машинных — 12 секунд)** против цели ≤30: узкое место — не расчёты,
а чтение и решения; поэтому волна чинила язык, дефолты и живучесть экранов
(9 хирургических правок + 2 дефекта боем), а крупное — перестройку Валидации
и онбординга — выносит планом на утверждение.

## UX-4. Замер времени-до-инсайта (headless, реальный Kagocel 31×32)

| Этап | Машинное время |
|---|---|
| Валидация (34 колонки с ролями) | 0.2 с |
| Обучение bayesian (канон) | 11.0 с |
| Декомпозиция (первый бизнес-инсайт) | 0.4 с |
| Оптимизация (бюджетная рекомендация) | 0.4 с |
| **Машинное итого** | **11.9 с** |

Человеческое время (консервативно по карте UX-0: импорт 1 мин + 5 под-шагов
Валидации × 1.5 мин + запуск 0.5 + чтение вердикта 2 + декомпозиции 3 +
оптимизации 3) ≈ **17 минут. Цель E5 ≤ 30 мин — двукратный запас.**
Даже на слабом CPU (машинное ×5–10) итог ~18–19 мин.

**Вывод:** каждая минута выигрыша теперь лежит в понимании, не в скорости
вычислений. Это подтверждает приоритеты плана ниже (Валидация и онбординг).

## Внедрено в волне (хирургически, всё под гейтами)

| Батч | Что сделано |
|---|---|
| UX-1 Язык | Adstock-варианты по-русски со смыслом («Геометрический — эффект быстро затухает»); статусы обучения без «сэмплирования цепей»; «интервал 90%» вместо «90% HDI»; «режим эксперта» вместо «Expert mode» |
| UX-2 Дефолты | **F-UX-2 (дефект):** дефолт KPI 'sales' проходил «Далее» даже когда детект его исключил (B2B-данные без денежной целевой) → невалидный monetary-режим. Теперь невалидный выбор автозаменяется первым доступным, кнопка сверяется с доступностью |
| UX-3 Статусы | Исторические противоречия T4 (SEV-1 «Ошибка vs приемлемо», MQS-1 «только 98%», MQS-2 «надёжно vs ненадёжно») — проверены: закрыты ранее SSOT-классификатором ratio (5 коридоров). Полировка тона: «ты»→«вы» во всех турах и инструктажах, Bayesian MCMC/optimizer/lift/юнит → русские эквиваленты |
| UX-5 Живучесть | **F-UX-1 (дефект, боем):** шаг 6 сценарного мастера крашился на легитимном diagnostics=null; тесты маскировали заглушкой. Починен (null-safe + честное скрытие блока), **мок снят — 28/28 тестов через реальный компонент**. Wireframe-ряд «Backtest (4 месяца holdout)» заменён честным «Проверка на истории» только при живых данных |
| UX-6 Ошибки | Горячие пути проверены: optimizer/scenario/decomposer уже «что случилось + что делать». Дочинен modeler: 4 ошибки обучения получили действие («повторите; если повторится — меньше каналов / режим OLS / код для поддержки»); «pip install» заменён клиентским «переустановите программу» |

## План крупных изменений — ВНЕДРЁН (одобрен Антоном «go» 2026-07-03)

> Статус внедрения: **все 7 пунктов закрыты в тот же день** (журнал UXP в
> реестре). П2/П3 оказались реализованы ранее — верифицированы кодом.
> П1 — в объёме безопасного ядра: экспресс-подтверждение happy-path
> (1 клик вместо 5 под-шагов, гейты в express-validate.js); полная
> перестройка «всё в одном экране» — после живой GUI-сессии (уроки C3).
> П6 — без отдельного поля action: действие внутри message (потребителя
> отдельного поля нет). Гейты: vitest 771/771 · svelte-check 0 · verify 43/43.

Приоритет = эффект для «не-эконометриста» ÷ цена.

### П1 ⭐ Валидация одним экраном (T5 · эффект максимальный · цена M-L)
Сейчас 5 под-шагов подряд (KPI → роли → цена единицы → метрики каналов →
режим), большинство — подтверждение авто-детекта. Предложение: один экран
«Сводка авто-решений»: «Мы определили KPI, роли 34 колонок и режим —
проверьте и нажмите Продолжить»; правки — точечным кликом в зону (раскрытие
текущих под-шагов как секций). Основа готова: детект надёжен (ловит грязь
208×), «Применить все рекомендации» реактивна. Ожидаемый эффект: −5…−6 минут
пути и главная «стена» исчезает.

### П2 ⭐ Онбординг одним потоком (T1 · эффект высокий · цена S-M)
Сейчас на первый запуск наслаиваются 4 механизма (~20 модальных шагов:
образовательные слайды + продукт-интро + welcome-тур + per-step подсказки).
Предложение: дефолт — ТОЛЬКО welcome-тур (6 шагов, уже переведён на «вы»);
образовательный блок «Что такое MMM» и per-step подсказки — по кнопке
«Обучающий режим» (существует в Настройках). Один координатор показа:
не больше одного оверлея за сессию шага.

### П3 Навигация под-шагов (T2 · цена S · сначала перепроверить живьём)
Исторически (06-02): футерная «Далее» не работала на под-шагах, номера
①②③④ некликабельны, контентная кнопка ниже сгиба. Код с июня менялся —
проверить на живом окне; если живо: номера кликабельны назад, одна «Далее».

### П4 Переименование «Ratio» → «Запас данных» (цена M)
Термин без перевода на бейджах/карточке/сводке. Координированная правка:
UI + справка + glossary + PPTX/HTML-отчёты + тесты. Смысловой ярлык:
«Запас данных: 2.4 наблюдения на переменную».

### П5 Слайд витрины E1 в секцию «Главное» деки (цена S)
Сейчас «Проверка на истории» — слайд №10 (секция «Методология»). Для
продления подписки это самый убедительный слайд — кандидат на позицию 4-5
(после at-a-glance). Решение подачи — за Антоном.

### П6 Error-конверт с полем action (цена M, системное)
Generic-обработчики сервера отдают `message: str(e)` — сырой технотекст
доезжает до клиента при неожиданных сбоях. Предложение: единый конверт
{message, action, error_code} + фронт-обёртка, показывающая action-строку.
(Горячие пути уже чистые — это страховка «последней мили».)

### П7 Гигиена (цена XS)
- `StepSummaryStub.svelte` осиротел после снятия мока — удалить.
- `pipeline/DiagnosticsPanel.svelte` мёртв (не рендерится никем) — удалить
  или запитать от живой диагностики; сейчас вводит в заблуждение читателей кода.

## Не сломать (сильные стороны — фиксируются как инварианты UX)

Детект грязи в данных (ошибка единиц 208×, >50% нулей, две целевых) ·
«Применить все рекомендации (N)» · авто-детекты с правом правки (роли, KPI,
adstock BIC, движок по n, праздники РФ) · «Зачем шаг X?» на каждом шаге ·
честность неопределённости (preflight-гейт, MQS-caps, экстраполяция,
витрина E1) · один CTA на главной.
