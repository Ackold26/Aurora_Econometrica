> UX-0 (волна UX, задание Антона 2026-07-03) · реестр `AUTONOMOUS_WORK_STATE_E1_BACKTEST.md`
> Посыл продукта: **«эконометрика не для эконометристов»** — путь глазами маркетолога
> без статистического образования. Источники: headless-разбор кода UI (маршруты,
> шаги, gating, тексты) + исторические живые аудиты (TEST_FINDINGS 2026-06-02…07-01).
> Историческим находкам ниже ставится пометка [проверить] — код с июня менялся.

## Путь одной строкой

Импорт (1 действие) → Валидация (5 под-шагов подряд) → Модель (1 кнопка + ожидание) →
Декомпозиция (авто) → Оптимизация (1 кнопка) → Отчёт (1 кнопка). Первый содержательный
инсайт появляется на **Декомпозиции** (главная рекомендация «переложить N млн из X в Y»).

## Шаги и обязательные решения пользователя

| Шаг | Обязательные решения | Авто-решения программы | Первая ценность |
|---|---|---|---|
| 0 Импорт | 1 — выбрать файл | движок (OLS/Bayesian по n), имя проекта, превью | авто-инсайты о данных |
| 1 Валидация | 3–5 подтверждений: KPI → роли колонок → [цена единицы, если KPI в штуках] → метрики каналов → режим | роли всех колонок, KPI-кандидаты, исключение каналов >50% нулей, «Применить все рекомендации», детект грязи (ошибка единиц 208×) | Ratio/MQS-прогноз, чистка данных |
| 2 Модель | 1 — кнопка «Обучить» (+ выбор пресета точности опц.) | preflight-гейт ДО обучения, adstock per-канал (BIC), праздники РФ, оценка времени | вердикт качества модели (MQS, светофоры) |
| 3 Декомпозиция | 0 — авто-запуск | вклад каналов, вердикты, главная рекомендация | ⭐ первый бизнес-инсайт |
| 4 Оптимизация | 1 — «Найти оптимум» (коридор по умолчанию 20–200%) | категории каналов, надёжность вердикта, светофор насыщения | «как перераспределить бюджет» |
| 5 Отчёт | 1 — формат + «Создать отчёт» | сборка деки/таблиц/HTML, витрина E1 с диска | клиентский документ |

**Минимальный путь: ~7–9 обязательных действий** (без учёта чтения) — это хорошо.
Плотность решений сосредоточена в Валидации (5 под-шагов подряд) — главное место трения.

## Время до инсайта (E5-рамка, ориентиры)

- Механика: импорт+валидация ~3–7 мин (чтение под-шагов) → обучение 0.5–4 мин
  (bayesian, канон 34с на 31×5) → декомпозиция авто-секунды. **Технически ≤15 мин** —
  запас против цели ≤30 мин есть.
- Реальные тайм-киллеры (не механика, а понимание): (1) онбординг-перегруз first-run,
  (2) жаргон на экранах решений, (3) противоречивые сигналы о качестве модели
  [проверить актуальность каждого — см. трение ниже].

## Точки трения (приоритизировано: эффект для «не-эконометриста» × частота)

### T1. Онбординг-перегруз first-run [проверить; истор. ONBOARD-1 🟠]
4 несогласованных механизма подряд (обучающие слайды → продукт-интро → welcome-тур →
per-step подсказки) ≈ 20+ модальных шагов ДО первого действия. Сейчас в коде 5 туров
по шагам (3–6 слайдов каждый) + FirstRunTour главной. Дефолт — всё показывается.

### T2. Навигация под-шагов Валидации [проверить; истор. NAV-2 🟠 «главный UX-баг»]
Исторически: футерная «Далее» не работала на под-шагах, номера под-шагов некликабельны,
контентная кнопка ниже сгиба. Три механизма навигации с разным поведением.

### T3. Жаргон на экранах решений (UX-1)
На экранах, где пользователь ОБЯЗАН решать, встречаются без пояснения рядом:
R-hat, ESS, MAPE, R², HDI, «Geometric/Weibull» (adstock-селектор), «Сэмплирование
байесовских цепей», Ratio, MQS. Часть прикрыта тултипами/раскрывашками «Зачем шаг X?»
— но ярлыки метрик-чипов голые. Полная инвентаризация → UX-1.

### T4. Противоречивые сигналы о качестве [проверить; истор. SEV-1, MQS-1, MQS-2 🟠]
Одновременно на экране: «✕ Ошибка: слишком мало данных» и «приемлемо для пилота»;
«Модель рассчитана надёжно» рядом с «MQS 50 — результаты ненадёжны»; «объясняет
только 98%». Пользователь без статистики не может выбрать, какому сигналу верить.
→ UX-3 (смысловые статусы: один главный вердикт + детали в раскрытии).

### T5. Пять под-шагов Валидации как стена (UX-2)
Каждый под-шаг — отдельное «Далее», при этом бо́льшая часть контента — подтверждение
авто-детекта. Кандидат на прогрессивное раскрытие: «всё определено автоматически —
проверьте и нажмите Продолжить» одним экраном, правки — по клику в конкретную зону.
(База уже есть: «Применить все рекомендации (12)» работает и реактивна.)

### T6. Ошибки-констатации из бэкенда (UX-6)
Guard-тексты фронта хороши (говорят ЧТО ДЕЛАТЬ: «Сначала загрузите файл на шаге
Импорт»). Но часть ошибок — сырые backend-сообщения без действия. Инвентаризация → UX-6.

### T7. Мёртвые/односторонние элементы
- Ряд «Backtest (4 месяца holdout)» в StepSummary — wireframe, никогда не считался
  (F-E1-2; теперь есть живая витрина E1 — запитать или убрать).
- /causal — экспериментальный модуль, скрыт с главной (кнопка «На главную» есть) — ок.

## Сильные стороны (НЕ сломать при правках)

1. **Валидация ловит реальную грязь**: ошибка единиц (208× разрыв → «рубли/копейки?»),
   каналы >50% нулей, две целевых колонки — с конкретными советами.
2. **«Применить все рекомендации (N)»** — реактивный массовый фикс (ratio 1.2→2.2 живьём).
3. **Авто-детекты с правом правки**: роли, KPI, adstock (BIC), движок по n, праздники РФ.
4. **Контекстная помощь «Зачем шаг X?»** на каждом шаге (ЧТО/ЗАЧЕМ/НА ЧТО СМОТРЕТЬ/ЧТО ДАЛЬШЕ).
5. **Честность неопределённости**: preflight-гейт до обучения, MQS с caps, экстраполяция
   помечается, вердикты надёжности, витрина E1.
6. **Один чистый CTA на главной** («Новый проект»), статус «Python готов».
