## TL;DR

Кабинет — **сильное методологическое ядро в слабой обвязке**. Домен MMM
прописан на уровне канона (Chan & Perry, McElreath, Hernán & Robins, Vehtari;
антисикофантия; теги достоверности; запрет экстраполяции; MQS). Но продукт
пережил осознанный редизайн роли кабинета («консультант ПОВЕРХ pipeline»,
cabinet.rs:262-268), а системный промпт остался в прошлой эпохе: 44% файла
документирует 9 скрытых из UI расчётных команд, и НИ ОДНОЙ из 6 живых кнопок;
у 6 из 8 UI-команд контракт данных конфликтует с рантайм-запретом; в экосистеме
живут 5+ разошедшихся версий кабинета без механизма синхронизации.
**Зрелость 2.0/5 · Эффективность 3.0/5.**

### Итоговые оценки

- **Зрелость: 2.0 / 5.** Промпт-слой не последовал за эволюцией продукта; версии расползлись; контракты противоречивы; измеримости нет.
- **Эффективность: 3.0 / 5.** Там, где кабинет реально работает (Аврора-ассистент через TIER2-слой; консультационные команды при удачном срабатывании), выдаёт методологически честный результат заметно выше среднего благодаря ядру 4.0. Но 6/8 кнопок — лотерея контракта данных, «Opus-качество» не гарантируется, а часть силы промпта (44%) тратится на мёртвую роль.

## Топ-дефекты (сведены из 3 аудитов, по убыванию)

1. **[Критично] Конфликтный контракт данных 6/8 UI-команд** — инструкция команды требует %APPDATA%/…/results/*.json, рантайм дописывает запрет env-путей, кода-моста нет. Недетерминировано.
2. **[Высоко] Системный промпт не описывает живую роль** — 6 кнопок UI не упомянуты; 44% файла — legacy-эпоха «Claude сам гоняет MCMC».
3. **[Высоко] Двойной промпт-слой с Авророй** — теги/финальная фраза: требование в кабинете ↔ запрет в TIER2; лечится регэкспом на фронте.
4. **[Высоко] SSOT отсутствует** — 5+ версий, ручной регламент, дрейф с апреля; правка «одного файла» физически невозможна.
5. **[Средне] «Default: Opus» без enforcement** — и осознанный Sonnet в ветке ассистента: конфликт декларации и инженерного решения не разрешён.
6. **[Средне] Три шкалы Ratio без сведения**; «размытые priors» vs horseshoe/R2D2.
7. **[Средне] Auto-continue наоборот** (легаси покрыто, кнопки — нет); mmm-to-doc/mmm-to-slides — программные потребители со слабейшим контрактом; 2 APPDATA-корня; счёт «7 команд» (реально 9) в cabinet.rs:262.

## Вердикт по плану Антона (4 ступени) и корректировка

Каркас **принимаю**: находки одним проходом → SSOT-владелец → эвал-харнес →
линтеры CI → петля правка→эвал→фиксация. Отвержение «переписать руками
длиннее и умнее» — **подтверждаю** (42 КБ уже размывают внимание к критичным
правилам). Три корректировки под специфику эконометриста:

**(0) Шаг-0, которого нет в плане: «выпрямить роль» — ДО эвал-харнеса.**
Это не «переписать умнее», а структурная правка: сократить системный промпт
(~вдвое), выведя 9 расчётных legacy-команд в архивный файл, и описать
консультационную роль + 6 живых команд + контракт данных. Без шага-0
эвал-харнес будет мерить промпт мёртвой роли — бейзлайн ни о чём: у живых
команд сейчас недетерминированный вход (дефект №1), результаты несравнимы.
Одновременно — починить дефект №1 по правилу продукта №10 («Pipeline context —
inject в message, не файл»): Rust/фронт кладёт results/*.json в тело команды
(эталон уже есть — Аврора tier2-context делает ровно это), а не «разрешить env».

**(1) SSOT:** владелец контракта — `Aurora_Econometrica/New_AI_Agency/econometrist/`
(кластер A, самый полный/свежий); остальные 9 копий — потребители. Страж дрейфа —
по образцу KPI-units: contract-тест + lefthook `--check` на идентичность копий
(паттерн уже отработан в этом же репо). Резюме в CLAUDE.md кабинета + полные
файлы команд = ровно та структура «полный файл + короткое резюме», что Антон
описал по /crisis-analysis; де-факто эталоном контракта у эконометриста назначить
`interpret-model` (единственная с «источники + если файла нет — не выдумывай»).

**(2) Эвал-харнес эконометриста ДЕШЕВЛЕ медиа-аналитика — использовать это.**
У медиа-аналитика вход — живые презентации, грейдинг субъективен. У эконометриста:
- вход детерминирован: фикстуры results/*.json уже в репо (kagocel-load1,
  demo_probe2, tmp/kpi_fixtures — 4 KPI-режима);
- автогрейдеры бесплатные, без LLM-судьи: (а) числа ответа ⊆ фактам —
  готовый `insights-grounding.js` (уже отлажен на Авроре, включая позитивный
  контроль); (б) регэксп: теги/финальный маркер/слэш-команды; (в) языковой
  линт (англицизмы, тире); (г) структурный чек (вывод→действие);
- LLM-судья нужен только на качество интерпретации (последний слой).
Флагманы эвала: 6 UI-команд + путь Авроры (econ_ask_insight). Порядок петли
после этого — ровно по плану Антона.

**(3) Решение по модели — развилка Антона:** либо форсировать opus для
econometrist в коде (если критичность коэффициентов реальна), либо признать
Sonnet и переписать Model Configuration честно. Держать декларацию без
enforcement — худший из вариантов.

**Что отвергаю:** (а) «сначала эвал-бейзлайн на текущем промпте, потом чистка» —
наукообразно, но бейзлайн промпта мёртвой роли с недетерминированным входом
несравним и не нужен; (б) «слить кабинет с Авророй в один промпт-слой сейчас» —
рано: кабинет обслуживает чат+команды, Аврора — узкий inline-путь; унификация
осмысленна на Фазе 3 облачной Авроры (см. CLOUD_AVRORA_DESIGN_2026_07_11).

### Итог

- **Зрелость: 2.0 → 4.0 / 5.** Промпт приведён к живой роли, контракт данных больше
  не лотерея, дрейф под гейтом, измеримость с нуля. Не 5: живой E2E не прогнан,
  физический дрейф копий не свёрнут, эвал не в CI.
- **Эффективность: 3.0 → 4.3 / 5.** Ядро сильнее (сведённые шкалы, canon-правки),
  промпт чище (−25% шума, страж без ложных grounded), контракт детерминирован.
  Не 5 честно: **живой smoke сам показал, что промпту есть что чинить** —
  галлюцинация чисел и запретные производные в why-channel. Именно это и есть
  ценность харнеса: потолок теперь измеряется, а не декларируется.

## Что осталось (петля улучшения, следующие сессии)

1. **Живой E2E в окне** — прогнать 6 кнопок на реальном проекте, свериться с приложенным блоком данных (AVT-протокол, спросить состояние машины).
2. **Петля правка→эвал** на находках живого smoke: усилить запрет производных чисел (mROI/ROI), убрать класс галлюцинаций «выдуманный помесячный расход».
3. **Эвал в CI** (dry-гейт на каждый коммит команд; живой — по расписанию/квоте) + пороги регрессии.
4. **Свести теги достоверности** кабинет↔Аврора к одному источнику (убрать зависимость от `sanitizeAvroraText`).
5. **Синк hub-копий** (по решению Антона — унифицировать ли, или узаконить их SCOPE-редакции отдельным манифестом).
6. **Мерж worktree-ветки** в основное дерево → сработает строгий `--strict-pair` гейт SSOT-пары.
