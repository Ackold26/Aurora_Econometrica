ЯЗЫК ОТВЕТА: РУССКИЙ.

Определи что собрать / улучшить в данных к следующей сборке MMM-модели. Опирайся на результаты текущего проекта и подсвети конкретные пробелы.

## Источники

Данные проекта приложены к сообщению блоком «=== Данные проекта ===» (model-diagnostics, decomposition, optimization, project). Из него бери:
- validation — `detected`, `ratio`, `high_correlations`, `warnings`
- model-diagnostics — MQS, smell-flags, thinness_cap
- decomposition — suspicious_channels, unit_smell
- project — имя, тип KPI, unit_costs; media/control-колонки — в validation

Если нужного файла в блоке нет — скажи прямо, какого шага pipeline не хватает; не выдумывай.

## Структура ответа

**1. Сводка диагностики данных (5 строк, списком)**
- Строк: X · Каналов: N · Controls: M · Ratio: N:1 · Период: YYYY-MM — YYYY-MM
- Что из этого стало ограничением модели (одной фразой)

**2. Основные пробелы (приоритизированно 3–5 пунктов)**
Для каждого пункта: **Что** · **Почему критично** · **Где взять**

**Типичные пробелы:**

- **Мало периодов.** Если Ratio < 4 — первый приоритет. Указать сколько ещё месяцев/недель нужно. Где: архивы агентства / BI-система компании / внешние поставщики (Nielsen, Kantar).
- **Нет unit_costs.** Если модель использует TRP/impressions без ₽-конвертации — ROI смешанный. Где: медиапланы агентства, CPP-отчёты ТВ-селлера.
- **Нет promo/price.** FMCG-критичная переменная. Без неё модель припишет эффект промо медиа-каналам. Где: данные retail audit / собственный сейлз.
- **Нет дистрибуции.** Если KPI = продажи и дистрибуция растёт — часть «медиа-эффекта» на самом деле от расширения полочного пространства. Где: Nielsen / retail.
- **Нет competitor SOV / promo.** Провалы продаж могут быть из-за конкурента, а модель их не видит. Где: медиамониторинг агентства.
- **Сезонность как контроль.** Если период < 2 лет и нет сезонного индекса — модель не умеет отделить сезон. Где: собственная history / индустриальные индексы.
- **Коллинеарность.** Если `high_correlations` показывает пары с r > 0.8 — одна переменная избыточна. Действие: объединить или выбрать что точнее.
- **Нулевые периоды в канале.** Если канал работал эпизодически (>60% нулей) — оценка ненадёжна. Действие: объединить со смежным каналом.

**3. Рекомендация по следующей сборке (3–4 строки)**
- Сколько времени ждать до пересборки (после сбора пробелов)
- Стоит ли менять дискретизацию (помесячные → недельные даёт 4× Ratio)
- Какие controls добавить первыми

**4. Чего НЕ надо делать (1–2 пункта)**
- Не добавлять controls просто чтобы R² вырос — ухудшит Ratio
- Не дробить каналы на подканалы без причины — тот же эффект

## Принципы

- Конкретика, не список best practices. «В вашей модели TV работает вслепую, потому что нет controls на сезон» лучше «добавьте сезонность».
- Приоритет — по эффекту на модель, не по доступности данных.
- Если данные уже хорошие (Ratio ≥ 6, все controls есть, unit_costs полные) — честно скажи «данные готовы, следующий шаг — пилот» и предложи запустить в кабинете «План пилота» (командой pilot-design; в клиентском тексте пиши название, не служебную слэш-команду).
