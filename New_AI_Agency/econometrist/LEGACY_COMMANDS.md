# Legacy: расчётные команды кабинета «Эконометрист»

Расчётные команды эпохи, когда Claude сам выполнял MMM: читал данные, генерировал и запускал Python (PyMC-Marketing), считал MCMC, декомпозицию, оптимизацию, собирал отчёты. После редизайна тяжёлый расчёт делает детерминированный движок приложения, а кабинет стал консультантом поверх пайплайна (см. `CLAUDE.md`).

**Статус:** эти команды скрыты из UI (`cabinet.rs` не выводит их в grid), но промпты в `.claude/commands/*.md` остаются – ручной ввод в поле по-прежнему работает (backward compat). При таком ручном использовании модель: **Opus рекомендован** (Claude сам генерирует и запускает Python; ошибка в коэффициентах ведёт к неверному распределению бюджета).

Python-зависимости, Windows-режим MCMC и технологический стек ниже перенесены из прежнего `CLAUDE.md` без изменений по существу. Раздел «Slash-команды» сведён к указателям на файлы-владельцы (было – полное дублирование контракта с расхождениями).

## Python-зависимости

При первом запуске любой команды – проверить наличие Python и пакетов:
```bash
python --version 2>/dev/null || python3 --version 2>/dev/null
pip install pymc-marketing pandas scipy matplotlib plotly prophet openpyxl 2>/dev/null
```
Если Python не установлен – вывести: «Для работы кабинета Эконометрист требуется Python 3.10+. Установите с python.org и перезапустите приложение.»
Если установка пакетов не удаётся (ошибка компиляции PyTensor) – рекомендовать: `conda install -c conda-forge pymc-marketing`

## Windows: облегчённый MCMC

На Windows без C-компилятора (g++) PyTensor работает в Python-режиме – NUTS крайне медленный.

**Правило:** Всегда сначала проверять наличие компилятора:
```python
import pytensor
has_cxx = bool(pytensor.config.cxx)
```

- `cores=1` (multiprocessing не работает на Windows)
- Если нет компилятора: **2 chains, 1000 draws, Metropolis sampler**
- Если есть компилятор: 4 chains, 2000 draws, NUTS
- НЕ пытаться сначала NUTS и переключаться после ошибки – сразу выбирать правильный sampler

Все Python-скрипты сохраняются в `exports/scripts/` для воспроизводимости.

- **`/mmm-optimize`** – оптимальное распределение бюджета по каналам (Marginal ROI, SLSQP). Контракт: `.claude/commands/mmm-optimize.md`
- **`/mmm-scenarios`** – сценарное планирование (What-if) до реальных трат. Контракт: `.claude/commands/mmm-scenarios.md`
- **`/mmm-report`** – комплексный отчёт для руководства (One-Pager + Executive Summary + детальный отчёт). Контракт: `.claude/commands/mmm-report.md`
- **`/mmm-full`** – полный цикл от сырых данных до отчёта, все шаги подряд. Контракт: `.claude/commands/mmm-full.md`
- **`/mmm-to-doc`**, **`/mmm-to-slides`** – экспорт результатов в Markdown-документ / PPTX-презентацию. Контракты: `.claude/commands/mmm-to-doc.md`, `.claude/commands/mmm-to-slides.md`

Awareness-команды (`/awareness-forecast`, `/awareness-to-sales`) – АКТИВНЫЕ консультационные команды кабинета (видны в UI-гриде), не legacy. Их контракт – в `CLAUDE.md` (раздел «Консультационные команды») и `.claude/commands/awareness-*.md`; сюда не дублируются.

## Технологический стек

### Adstock (эффект переноса)
- **Geometric:** decay_rate × предыдущий эффект; пик эффекта – в неделю контакта. Для каналов с быстрым откликом (search, display). Параметр: θ (theta) ∈ [0, 1]
- **Weibull / delayed:** отложенный пик + затухание. Для охватных каналов (TV, OOH, brand video). Параметры: shape (k), scale (λ)
- **Длина окна carryover L:** для недельных данных дефолт ≈ 13 недель [ASSUMED, по Jin 2017: «L = 13 is a good approximation to infinity» для недельных рядов; для месячных – пересчитать]. Правильно выбранная L помогает оценивать веса adstock. Geometric предполагает пик в период контакта; если эффект отложен (TV/OOH) – использовать delayed/Weibull, иначе пик систематически смещён

### Saturation (насыщение)
- **Hill function:** S(x) = x^α / (x^α + γ^α)
  - α < 1 → C-shape (быстрое насыщение)
  - α > 1 → S-shape (разгон перед насыщением)
  - γ = точка перегиба (50% потенциала)
- **Идентифицируемость:** параметры Hill (α/slope, γ/half-saturation) статистически почти неразличимы – близкую по форме кривую дают очень разные тройки параметров (Jin 2017: «essentially unidentifiable in some scenarios»). Поэтому отчитывать форму кривой в наблюдаемом диапазоне как [MODELED] (на ней работает оптимизатор), а конкретные значения α/γ – как [ASSUMED], не выносить точечным выводом

### Priors (априорные распределения)
- **Медиа-коэффициенты β – неотрицательные (half-normal).** Эффект медиа считаем неотрицательным по построению, поэтому отрицательный ROI предотвращается структурой, а не ловится постфактумом (Jin 2017: «for the regression coefficients β, we usually use nonnegative priors such as half normal… since we believe the media effect is nonnegative»). Контрольные переменные (цена, дистрибуция) – БЕЗ ограничения знака (допускают отрицательный эффект).
- **Priors на параметры adstock/saturation – по носителю** (Jin 2017; РАМКА по INV-50: семейство на носителе обязательно, гиперпараметры подгоняются под данные):

  | Параметр | Семейство prior | Носитель |
  |----------|-----------------|----------|
  | α / retention (adstock decay) | Beta или Uniform | [0, 1) |
  | θ / delay (задержка пика) | Uniform или Beta | [0, L−1] |
  | Hill slope (крутизна насыщения) | Gamma (положительная мода) | > 0 |
  | Hill K / γ (half-saturation) | ограничить наблюдаемым диапазоном трат | диапазон x |

- half-normal на β исключает каннибализацию и отрицательную синергию – поэтому только для медиа, не для контролей; это обоснованный дефолт MMM, не универсальный закон.

### Оптимизация
- **SLSQP** (scipy.optimize) – для бюджетного аллокатора с ограничениями
- **Augmented Lagrangian** – для глобальной оптимизации
- **Nevergrad TwoPointsDE** – для поиска гиперпараметров модели
