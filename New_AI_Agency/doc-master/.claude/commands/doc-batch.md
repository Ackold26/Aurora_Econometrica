ЯЗЫК ОТВЕТА: РУССКИЙ. Все комментарии, выводы, рекомендации, статусы — на русском языке. НЕ использовать английский (кроме терминов ROI, CPM, GRP).

Сгенерируй комплекты документов для списка подрядчиков на основе шаблонов из inbox.

## КРИТИЧЕСКОЕ ПРАВИЛО: однопроходное выполнение

Каждый шаг выполняется ОДИН раз. Если чтение файла не удалось — попробуй альтернативный способ (другой инструмент, другую кодировку). Если и он не сработал — зафиксируй ошибку и переходи к следующему шагу. НИКОГДА не возвращайся к шагу 1 после его завершения.

## КРИТИЧЕСКОЕ ПРАВИЛО: генерация без блокировки

Генерируй документы ВСЕГДА, даже если данных не хватает. Недостающие поля заполняй плейсхолдером `[НЕ УКАЗАНО: описание]`. После генерации выведи предупреждение со списком незаполненных полей. НЕ останавливайся и НЕ жди ввода пользователя для генерации — заполняй что есть, помечай что нет.

## Алгоритм работы

### Шаг 1. Определи входные файлы и режим работы
В inbox должны быть:
- **Шаблоны документов** (.doc/.docx) — один или несколько шаблонов для заполнения
- **Источники реквизитов** — в одном из двух режимов:

**Режим A — Таблица подрядчиков** (.xlsx/.csv):
Структурированная таблица со всеми реквизитами и данными сделок. Один подрядчик — одна строка.

**Режим B — Разрозненные файлы реквизитов:**
Отдельные файлы на каждого подрядчика: .docx (карточки реквизитов), .pdf (выписки ЕГРИП, карточки ИП), .jpg/.png (фото/сканы уведомлений, свидетельств, карточек реквизитов). Система извлекает реквизиты из каждого файла автоматически, включая визуальное распознавание данных из изображений.

Определи режим по содержимому inbox:
- Если есть xlsx/csv с несколькими строками подрядчиков → Режим A
- Если есть набор разнородных файлов (pdf, docx, jpg) → Режим B
- Если есть и то, и другое — таблица как основа, файлы для дополнения недостающих данных

Если шаблонов нет совсем — спроси. Если есть хотя бы один шаблон и один источник данных — переходи к шагу 2.

### Шаг 2. Извлеки данные подрядчиков

**Режим A (таблица):**
Найди и извлеки колонки (названия могут варьироваться). Если колонки не найдены или названы нестандартно — покажи найденные заголовки и спроси маппинг.

**Режим B (разрозненные файлы):**
Для каждого файла определи, к какому подрядчику он относится (по ФИО, ОГРНИП, ИНН внутри файла), и извлеки реквизиты:
- Из .docx — текстовые реквизиты (ФИО, ОГРНИП, ИНН, банк, р/с, к/с, БИК, адрес, email)
- Из .pdf — реквизиты из карточек ИП, выписок ЕГРИП (используй skill `pdf` для чтения)
- Из .jpg/.png — визуальное извлечение реквизитов из фото/сканов документов (уведомления о постановке на учёт, свидетельства о регистрации, карточки реквизитов). Если изображение нечёткое или данные считываются неуверенно — подставляй лучший вариант и помечай его `[ПРОВЕРИТЬ: нечёткое фото]`. Не пропускай данные только из-за низкого качества — используй что удалось распознать
- Группируй данные из нескольких файлов одного подрядчика в единый профиль

**Данные для извлечения (по каждому подрядчику):**

Реквизиты исполнителя:
- ФИО полностью
- ОГРНИП
- ИНН
- Юридический адрес
- Email
- Банк, р/с, к/с, БИК
- Статус НДС

Данные сделки:
- Бренд и продукт
- Платформа, ссылка на аккаунт/канал
- Общая сумма вознаграждения
- Разбивка платежей (аванс / постоплата, суммы и даты)
- Сроки оказания услуг (старт — конец)

Данные заказчика (если не зафиксированы в шаблоне):
- Наименование ООО, ОГРН, ИНН, ФИО директора, банковские реквизиты

После извлечения — НЕ останавливайся. Сразу переходи к шагу 3.

### Шаг 3. Определи шаблоны и логику выбора
Для каждого подрядчика определи, какие шаблоны использовать:
- **НДС-статус** → выбор между шаблоном «с НДС» и «без НДС»
- Если шаблон один (универсальный) — заполняй его
- Если нужного варианта шаблона нет — используй имеющийся, пометь несоответствие

Типовой комплект на подрядчика:
1. Договор оказания услуг
2. Акт сдачи-приёмки
3. ДС о согласии на обработку ПД

Если какого-то шаблона нет в inbox — генерируй комплект из тех, что есть. Не блокируйся.

### Шаг 4. Для каждого подрядчика — заполни шаблоны

**Подстановка плейсхолдеров:**
- Плейсхолдеры в позиции ФИО → ФИО из извлечённых данных
- Плейсхолдеры ОГРНИП, ИНН, банковские реквизиты → из извлечённых данных
- Даты → из данных сделки
- Суммы → цифрами + прописью на русском языке, в рублях и копейках
- Платформы, ссылки → из извлечённых данных, оставить только нужное
- **Если данных для поля нет** → подставить `[НЕ УКАЗАНО: название поля]`
- **Если данные считаны неуверенно** (нечёткое фото, повреждённый PDF) → подставить лучший вариант + `[ПРОВЕРИТЬ: причина]`

**Расчёт сумм:**
- Если указана ставка НДС — рассчитать сумму НДС и сумму с НДС
- Разбивка на аванс/постоплату — по извлечённым данным сделки
- Если сумм нет — оставить `[НЕ УКАЗАНО: сумма вознаграждения]`

**Нумерация договоров:**
- Если в данных есть номера — использовать их
- Если нет — подставить `[НЕ УКАЗАНО: номер договора]`

### Шаг 5. Сохрани результат
Для каждого подрядчика создай подпапку в exports/:
```
exports/
├── Иванова_АА/
│   ├── Договор_Иванова_АА.docx
│   ├── Акт_Иванова_АА.docx
│   └── ДС_ПД_Иванова_АА.docx
├── Петров_ИС/

│   ├── Акт_Петров_ИС.docx
│   └── ДС_ПД_Петров_ИС.docx
└── ...
```

### Шаг 6. Верификация и отчёт
Выведи сводную таблицу:
| № | ФИО | НДС | Сумма | Документов | Заполненность | Статус |
|---|-----|-----|-------|------------|---------------|--------|

Для каждого комплекта проверь:
- Плейсхолдеры ХХХ / ___ заменены на данные или `[НЕ УКАЗАНО]`
- Суммы цифрами совпадают с суммами прописью (где суммы есть)
- Реквизиты корректны (длина ОГРНИП = 15, ИНН = 12 для ИП)
- НДС-ставка соответствует выбранному шаблону

**Блок «Документы заполнены частично»** (если есть `[НЕ УКАЗАНО]` или `[ПРОВЕРИТЬ]`):
```
⚠ ДОКУМЕНТЫ ЗАПОЛНЕНЫ ЧАСТИЧНО

Не указано (необходимо предоставить):
  Подрядчик: Иванова А.А.
    - Юридический адрес ИП
    - Номер и дата договора
    - Сумма вознаграждения

Требует проверки (данные подставлены, но могут быть неточны):
  Подрядчик: Иванова А.А.
    - Адрес регистрации [ПРОВЕРИТЬ: нечёткое фото] — подставлено: «г. Москва, ул. ...»
    - ИНН [ПРОВЕРИТЬ: нечёткий скан] — подставлено: 77048385ХХХХ

После получения/проверки данных запустите /doc-batch повторно.
```

При обнаружении ошибок в данных (расхождение ИНН, некорректный БИК) — пометь строку как `⚠ ТРЕБУЕТ ПРОВЕРКИ` с описанием.
