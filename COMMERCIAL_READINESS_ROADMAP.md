## Главная честность (антисикофантия)
**Код — уже НЕ главный барьер к продаже.** Математическое ядро доказано (~9/10), продукт функционально почти полон. Продажу открывает не следующая фича, а замкнутый цикл «прогноз → факт» на реальном клиенте. Опасность — бесконечно полировать код (он под рукой и приятен), откладывая пилот, который единственный на критическом пути к деньгам.

Оценка готовности (commercial-анализ 2026-07-05): качество ①~90% · стабильность ②~85% · **доказанная ценность на реальном клиенте ③~30-40% ← главный разрыв**.

## ★ ТРЕК: Возврат Авроры Tier 2 + RAG-слой (USP онлайн-редакции)

**Проблема (зонд 2026-07-11):** Аврора-ассистент («Спросить Аврору» + советчик «Что если») ФИЗИЧЕСКИ ОТСУТСТВУЕТ в текущей сборке. grep по фронту и Rust — 0 совпадений. Панель «ИНСАЙТЫ» справа = Tier 1 (детерминированный `insights-rules.js`). Сама Аврора (Tier 2, LLM) жива на ветке `feat/ai-insights-tier2` (44 коммита, локально + origin — не потеряна).

**Почему не доехала:** ветка ответвлена от master `7fbfd96` (15 июня, начало); основная линия ушла на **212 коммитов** вперёд, переписав те же файлы (InsightsPanel/OptimizeStep/project-state). Прямой merge = ад конфликтов.

**Решение — ПОРТ, не merge.** Перенести Аврору заново поверх текущей линии, взяв ветку как эталон. Компоненты малы:
- grounding-контекст (числа СТРОГО из фактов модели — INV-50 страж, `insights-grounding.js`);
- Rust-мост `econ_ask_insight(prompt)` → `run_claude` через кабинет `econometrist` = единый egress-чок-поинт (гейты `ensure_not_local_only` + `ensure_cloud_consent` + feature `cloud_advisors`);
- UI-блок «Спросить Аврору» + советчик «Что если» наверху InsightsPanel;
- методология из первоисточников в промпте (Binet&Field/Sharp/McElreath/Kahneman/Knaflic — уже была).
- Файлы-эталоны на ветке: `InsightsPanel.svelte`, `insights-grounding.js`, `scenario-advisor.js`, `tier2-context.js`, `src-tauri/src/lib.rs` (econ_ask_insight). Дни, не недели.

**RAG-слой (идея Антона 2026-07-11): Аврора как настоящий эконометрист рядом с планером.**
Фундамент ЧАСТИЧНО стоит:
- кабинет `econometrist` — мозг Авроры, egress через Claude, grounding-страж INV-50;
- **канон байес-MMM УЖЕ в промпте** (aurora-upgrade №11 + T3.10): Jin 2017, Chan&Perry, Gelman, McElreath, Pearl — из `Knowledge_Library`;
- RAG-инфраструктура есть (`Knowledge_Library` + `lib_vec.py`); Legal Center сделал рабочий RAG-механизм → паттерн переиспользовать.
Достроить: **живой RAG-слой** — планер спрашивает → Аврора подмешивает релевантный кусок из библиотеки эконометрики → отвечает как эксперт, ведёт за руку в обучении и использовании модели.
- 🔴 **RAG живёт на EGRESS-стороне (облако), НЕ в клиенте** — тащить индекс в sidecar (уже 970 МБ) нельзя. Клиент шлёт вопрос → облако (Маша Небесная/сервер) обогащает каноном → ответ.
- 🔴 **Честность чисел священна** — grounding-страж (числа только из модели) обязан пережить порт; RAG добавляет методологию, НЕ право выдумать метрику.
- 🔴 **Только облачная редакция.** В локальной M1 (152-ФЗ, 0 egress) Авроры быть НЕ должно — гейт по feature `cloud_advisors` + `ensure_not_local_only`.

**Порядок:** (1) текущая волна + релиз v2.3.0 БЕЗ Авроры; (2) отдельная сессия — порт Авроры Tier 2 поверх линии; (3) следом — живой RAG-слой на облачной стороне.

## АРХИТЕКТУРА РЕДАКЦИЙ: онлайн/офлайн (решение Антона 2026-07-11 + разбор Маши)

**Вопрос Антона:** одна программа с выключателем — онлайн (Аврора + серверы) / офлайн (тишина)?

**Ответ: ДА для основной редакции, НО держать вторую железобетонную сборку для 152-ФЗ.**

Уже есть ОБА механизма (зонд 2026-07-11):
1. **Runtime-выключатель** — согласие на облачную обработку + тумблер (`CloudConsentOverlay`). Облачная редакция: пользователь сам решает онлайн/офлайн. Ровно картина Антона.
2. **Compile-time вторая сборка** — «Optimizer MMM Local» (`--no-default-features`, `com.aurora.econometrica.local`): egress-код СТАТИЧЕСКИ НЕДОСТИЖИМ (`run_claude` ранний bail), не «выключен флагом», а физически отсутствует.

**Ключевая разница = обещание vs доказуемая гарантия.** Безопасник фарма-клиента спросит: «флаг в false — а гарантия, что не переключится (баг/обновление/реверс)? покажите, что отправки НЕТ». В версии-с-выключателем код отправки в бинаре присутствует (спит); в локальной сборке его НЕТ — это показуемо на аудите. Агентству выключателя хватит; фарме с ПДн — нет.

**Решение (не «или-или», два слоя одного продукта):**
- **Облачная (основная, коммерческая)** = одна программа с выключателем Авроры онлайн/офлайн. Доработать UX: «офлайн-режим» — явная понятная настройка одним кликом, не спрятанное согласие. «*Можешь* работать офлайн».
- **Локальная M1 (152-ФЗ)** = отдельная сборка без egress-кода. «*Физически не может* иначе как офлайн». Держать как есть.
- Цена: два канала обновлений (учтено, V52 — локальной отдельный манифест). НЕ схлопывать в один инсталлятор — убьёт продажу строгим клиентам.
- [ ] Доработать UX выключателя онлайн/офлайн в облачной редакции (явный режим, не только согласие).
