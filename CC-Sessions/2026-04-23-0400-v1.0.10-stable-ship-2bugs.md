## Learnings

### L1 — Slow downstream bug маскирует frontend bug

Пока train висел 5 минут (Bug #1), мы не заметили что декомпозиция тоже не вызывается (Bug #2). Оба bug'а стало видно только когда Bug #1 fix раскрыл Bug #2. **Урок:** фиксить slow pipeline в порядке от upstream к downstream — не предполагать что следующий stage работает пока предыдущий не быстр.

### L2 — Guard без trigger pathway = регрессия

Добавила onMount guard в DecomposeStep (rc1.4 commit `29fd0c6`) для защиты от spam `/compute/decompose` на Validate step. Существующий `$effect(modelData)` имел `if (firstFire) return` — skip первый fire потому что «onMount подхватит». Но если onMount УЖЕ ушёл в idle (guard сработал) — `$effect` тоже skip'ает → **runDecompose никогда не вызывается**.

**Урок:** когда добавляешь guard в одном pathway (onMount), проверь что второй pathway ($effect) retriggers когда guard сработал. Skip условие должно быть: `skip только если onMount успешно вызвал работу (stepState !== 'idle')`.

### L3 — Manual reconstruction === averaged posterior_predictive

`pm.sample_posterior_predictive(trace)` делает 8000 samples которые ты потом усредняешь `.mean(chain, draw)`. При линейной модели с deterministic transformations (Hill saturation) — это **математически эквивалент** manual reconstruction из posterior means: `intercept_mean + Σ β_i × Hill(x, α_i, γ_i) + control_mean @ X_control`. Разница — sigma-noise который усредняется к нулю.

**Урок:** если тебе нужно только `.mean(posterior_predictive)` для `y_pred vs actual` — reconstruct manually из posterior means. Экономит compile overhead PyTensor для каждого draw.

### L4 — Windows Defender scans installed bundle .pyd files

`pm.sample_posterior_predictive` создаёт .pyd temp compile files. В **installed** Aurora bundle (в отличие от dev-mode source) каждый такой файл «новый» для Defender'а → scan перед allow → overhead. Добавил exclusions: process `econometrica-sidecar.exe` + path `AppData\Local\PyTensor`.

**Урок:** installed bundle != dev-mode. Defender behavior разный. Добавлять process-exclusion для sidecar .exe в standard Defender exclusions list.

### L5 — Session B CI `actions/setup-python@v5` с `cache: 'pip'` требует requirements.txt

Если в repo нет `requirements.txt` или `pyproject.toml` — workflow падает с `No file matched`. В rosst-updates это **deployment-only** repo без Python deps. Fix: drop `cache: 'pip'` строку. check-jsonschema устанавливается за ~1 сек, кэш не нужен.

### L6 — lefthook multiline `run:` с bash heredoc плохо escape'ит

Мой первоначальный guard с `echo "❌ ..."` + quotes внутри multiline `run: |` ломал bash parser в Git-Bash. Fix: всё в одну строку через `||`:
```yaml
run: grep -q channelParams {staged_files} || (echo ERROR; exit 1)
```

### L7 — Plan audit перед execution экономит часы

Session 17 начали с plan'а v1, я провела audit и нашла 6 дефектов (F0 CI fail, aurora-tag repo confusion, CHANGELOG timing, PASHE_IT.MD missing, Defender exclusions, D1 refactor). Фиксы в v2 сэкономили ~40 мин работы в неправильном направлении.

## Decisions

### D1 — Manual reconstruction вместо sample_posterior_predictive
**Файл:** `sidecar/econometrica/engines/modeler.py:513-553`
**Причина:** PyTensor graph recompile для 8000 draws на Windows без g++ даёт 5+ мин. Manual reconstruction instant.
**Tradeoff:** теряем `trace.posterior_predictive` field, но downstream (decomposer/optimizer) его не читает — проверено grep'ом.

### D2 — Skip условие $effect учитывает idle
**Файл:** `src/lib/components/pipeline/DecomposeStep.svelte:241`
**Старый:** `if (firstFire && stepState !== 'error') return;`
**Новый:** `if (firstFire && stepState !== 'idle' && stepState !== 'error') return;`
**Причина:** если onMount guard ушёл в idle (channelParams пустой на mount), $effect должен подхватить после train.set.

### D3 — Supabase колонка `product`, не `product_key`
**Источник:** `memory/reference_econometrica_rollback.md:45` — `WHERE product IN ('aurora-econometrica-gui', 'econometrica')`.
**Причина:** моя первая попытка UPSERT упала с `column "product_key" does not exist`. Проверила memory перед повторной.

### D4 — NSIS installer host: GitHub Releases, НЕ Supabase Storage
**Причина:** Supabase 413 на .exe >117MB (memory `feedback_public_repo.md`). 178 MB installer → только GH.

### D5 — Defender exclusions admin UAC через `Start-Process powershell -Verb RunAs`
**Добавлены:** process `econometrica-sidecar.exe`, `python.exe`, `cl.exe` + path `AppData\Local\aurora-econometrica-gui`, `AppData\Local\PyTensor`.
**НЕ добавлено:** `C:\Program Files\Aurora AI Econometrica\` — Windows Security policy блокирует.

### D6 — v1.0.10 ship через `aurora-tag` + `release-notes.py` (dogfood Session B tooling)
**Причина:** Session B tooling была теорией. Этот ship первый раз использует aurora-tag (safety check passed) + release-notes.py (generated notes в `/tmp/release-notes-v1.0.10.md`). Оба работают.

### D7 — Pre-existing validator bug отложен до v1.0.11
**Файл:** `src-tauri/src/commands/econometrica.rs:84` — `econ_validate` не резолвит project_id → abs path. Существует с 18 апр. GUI работает через return value, только `.aurora` archive теряет validation. Не блокер ship.

## Errors & Workarounds

### E1 — Supabase UPSERT: `column "product_key" does not exist`
**Workaround:** memory имеет `product` (не `product_key`) — использовать `WHERE product IN (...)`. См. reference_econometrica_rollback.md.

### E2 — GitHub Actions `actions/setup-python@v5` с `cache: 'pip'` fails в deployment-only repo
**Workaround:** убрать `cache: 'pip'` строку. check-jsonschema 1s install, не нужен кэш.

### E3 — `aurora-tag v1.0.10-rc1.1` safety пропустил false-positive на version dots
**Workaround:** `grep -Fxq` (fixed string whole-line) вместо `grep -q "refs/tags/$TAG$"`.

### E4 — V40 linter bypass через `title="aurora-fix:safe"` в HTML attribute
**Workaround:** regex требует формат HTML-комментария `<!--.*?\baurora-fix:safe\b.*?-->`. `.*?` non-greedy для тела.

### E5 — lefthook multiline `run:` with bash heredoc parses incorrectly in Git-Bash
**Workaround:** одна строка через `||`: `grep -q X {staged_files} || (echo ERROR; exit 1)`.

### E6 — PyMC forward sampling 5 min hang on installed bundle
**Root cause:** PyTensor recompile × 8000 draws + Defender scans each .pyd.
**Workaround:** manual reconstruction + Defender process-exclusion + PyTensor path exclusion.

### E7 — DecomposeStep empty after successful train
**Root cause:** race между onMount guard (Session B 29fd0c6) и $effect firstFire skip.
**Workaround:** skip учитывает idle state.

### E8 — F12 DevTools недоступен в production build
**Workaround:** для Comparison dispose проверки — code review `EChartBase.svelte:53` достаточно (Svelte guarantees onMount cleanup on unmount).

### E9 — GitHub Pages cache задерживает latest.json на 1-5 мин после push
**Workaround:** не блокер, обновится автоматически. Supabase (основной канал updater) обновляется мгновенно.

### E10 — Windows cp866 консоль corrupts UTF-8 output from release-notes.py
**Workaround:** использовать `--out file.md` — Markdown artifact пишется UTF-8 корректно, только stdout кракозябры.
