Skill `aurora-release-update` точный регламент работает идеально для Econometrica:

1. **ШАГ 0 — Supabase pre-check** через `mcp__supabase__execute_sql` показал текущую 1.0.13 → safe upgrade к 1.0.16
2. **ШАГ 1 — codebase sync** уже done в предыдущем session (HEAD `90de35d` pushed)
3. **ШАГ 2 — version bumps** done в `5858844` (1.0.15 → 1.0.16 в package.json + Cargo.toml + tauri.conf.json)
4. **ШАГ 3 — sidecar rebuild + NSIS build** запустились последовательно in background, ~12 минут total
5. **ШАГ 4 — SHA256** через PowerShell `Get-FileHash`

9. **ШАГ 8 — rosst-updates** clone + edit `aurora-econometrica-gui/latest.json` + commit/push

### Sidecar build via PyInstaller --onedir
- Запуск: `python build_sidecar.py` в `sidecar/econometrica/`
- ~10 минут для full bundle (693 MB unpacked, includes NumPyro/JAX dependencies)
- Output: `sidecar/econometrica/dist/econometrica-sidecar/econometrica-sidecar.exe`
- Auto-syncs в Tauri resource path
- Auto-freshness check: «[OK] Freshness verified (exe newer than all .py sources)»
- Critical: ОБЯЗАТЕЛЕН перед `npm run tauri build` иначе NSIS пакует старый sidecar

### NSIS build via Tauri
- Запуск: `CARGO_TARGET_DIR="D:/cargo-targets/aurora-econometrica" npm run tauri build`
- ~5-7 минут для Rust release compile + makensis
- Output: `D:/cargo-targets/aurora-econometrica/release/bundle/nsis/Aurora AI Econometrica_1.0.16_x64-setup.exe`
- Vite frontend build (`@sveltejs/adapter-static`) → server-side compile → Rust release → NSIS

### GH Release URL pattern
- Customer-facing download URL заменяет spaces на dots: `Aurora.AI.Econometrica_1.0.16_x64-setup.exe`
- Original filename: `Aurora AI Econometrica_1.0.16_x64-setup.exe`
- Это normalization GitHub автомат, НЕ ошибка

### Edge Function (auto-update endpoint)
- `POST /functions/v1/app-update` body `{"product": "aurora-econometrica-gui"}`
- Returns: version + download_url + checksum + release_notes + mandatory + min_version
- Reads из Supabase `app_versions` table
- App startup сравнивает с локальной версией → показывает update banner если is_newer

### rosst-updates manifest
- Public repo: `github.com/Ackold26/rosst-updates`
- Path: `aurora-econometrica-gui/latest.json`
- Schema: version + download_url + checksum + release_notes + mandatory + min_version
- Используется как fallback / альтернатива Supabase Edge Function
- Customer apps polling это manifest для updates

### `is_newer()` semver requirement
- Новая версия **строго больше** текущей в Supabase
- 1.0.13 → 1.0.16 ✓ (skipped 1.0.14/15 — не были в Supabase, only direct GH)
- Если назначить версию ≤ текущей в Supabase, баннер update не появится

## Decisions

### v1.0.16 ship-time

1. **GitHub Releases as primary distribution channel** — files >117MB triggers Supabase Storage 413 limit. Per memory `project_econometrica_v110_ship_blocked.md`. NSIS 189.3 MB всегда uses GH path.

2. **Supabase app_versions stores GH download URL** — не Supabase Storage URL. Customer-facing URL остаётся в GitHub Releases CDN.

3. **PASHE_IT.MD remains local-only** — security-sanitized customer IT-doc. Не публикуется в repo (per memory `reference_it_docs_security_sanitization.md`). Передаётся Pasha out-of-band (email/Telegram).

4. **release_notes длинные = OK** — Supabase column принимает длинный текст; описание в release_notes показывается в auto-update banner. Customer-facing summary всё ключевое.

5. **Tag pushed FIRST, then GH Release** — pattern: `git tag v1.0.16 && git push origin v1.0.16` then `gh release create v1.0.16 --repo Ackold26/aurora-releases ...`. Tag в product repo (Aurora_Econometrica), Release в aurora-releases (separate public repo).
