## Learnings

### 1. ADR-015 retrospective — argument-from-authority pitfall

ADR-015 (Mode as Derived State) cited PyMC-Marketing / Robyn / LightweightMMM / Jin 2017 как «mode-free industry standard» — но это **analyst-driven tools** для эконометристов PhD, не self-service products. Aurora ICP — агентский аналитик / бренд-менеджер с догадочным unit_cost. ADR-015 misapplied auth-from-industry без context check. Cost: цикл рефакторинга, B4 audit finding в v1.3.2.

ADR-019 (this sprint) supersedes: Mode становится explicit Manager choice (ROI / Эффективность одним кликом), смешанный режим только Expert opt-in. Per-channel detail скрыто в Manager.

### 2. RD-1 critical finding — OTC competitor prior

Initial Aurora v2.0.0 prior был `N(μ=-0.3, σ=0.3)` based на Robyn/Nielsen FMCG default. Real pilot data (Кагоцел / Венарус / MMX Афала) показала competitor_coef **positive** (+0.09 до +0.45), не negative! Root cause: `corr(brand_TRP, competitor_TRP) = +0.93` для OTC — оба рекламодателя бьют в той же flu season → shared seasonal demand, не cannibalization. OTC market **expanding в season**, не zero-sum.

Fix: category-aware dispatch в `modeler.py`:
- OTC / count KPI → `μ=0` symmetric (let data drive sign)
- FMCG / monetary KPI → `μ=-0.3` (direct cannibalization)
- Customer override через `config.competitor_prior_mu`

### 3. Sub-agent integration loop pattern

Parallel sub-agents могут создать orchestrator + components отдельно, никто не закрывает integration loop. Aurora v2.0.0 case: Sub-agent #1 создал ScenarioWizard с placeholder stubs для Steps 4-6; Sub-agent #2 создал actual Step components. Wizard не мог завершиться end-to-end. Каught только в personal post-batch audit (`9aedcd6` fix).

Pattern для prevention: после parallel batch — grep для «placeholder»/«stub»/«TODO» в orchestrator files. Always verify integration loop closed.

### 4. Real data > synthetic для priors validation

Synthetic validation confirms «math works as designed» (ground truth = generation params). Real data confirms «design matches reality» (may reveal hidden assumptions).

Phase E2: я начала с synthetic data builder assuming real pilot data NDA-restricted. Антон provided path mid-validation. Synthetic-only passed 9/11 tests («priors reasonable»). Real data found **RD-1 fundamental misalignment** that synthetic could never catch.

Category-specific priors (signed factors per industry) **требуют real data** — synthetic ground truth is artificial. Always ask user upfront: «есть ли existing test datasets / pilot data files?»

### 5. Svelte 5 anti-patterns каталог

Sprint outed несколько Svelte 5 runes anti-patterns:

**`$state(prop_computation())` — captures prop ONCE at mount.** Stale if parent updates prop. Use `$state(default) + $effect(() => { x = compute(prop); })` или `$derived`.

**`<svelte:component this={X}>` deprecated в runes.** Use `{@const Comp = expr}<Comp />` где parent — structural tag (`{#if}`, `{#each}`, etc.). В `<span>`/`<div>` parent — `{@const}` blocked (`const_tag_invalid_placement`), accept warning до Svelte 6.

**`<svelte:boundary>` `onerror` получает `unknown`, не `Error`** — use `instanceof Error` narrowing + cast.

**Single `<style>` block per Svelte file** — adding second block silently fails.

### 6. 30% sub-agent audit false positive rate

3 parallel sub-agent audits returned 63 findings; ~23 (30%) были false positives (already guarded code, over-strict typing, perfectionism beyond scope). Personal verification обязательна перед apply per `feedback_verify_agent_findings_personally`. After verification: 40 real findings → ~20 action items.

Audit findings также mix «real BUGs» (need fix) с «PENDING work» (already в roadmap). Classification step мandatory: BUG / PENDING / PERFECTION / false positive.

### 7. ECharts (NOT Chart.js) — Aurora dep

Sub-agent caught my Chart.js assumption — Aurora uses `echarts: ^5.6.0` через `EChartBase.svelte` + `chartTooltipDark()`. Sub-agent corrected, saved adding new dep accidentally.

Pattern: перед prompt'ом sub-agent с library reference — `grep "library_name" package.json` или quick check existing components.

### 8. РФ-monthly default — methodological insight

В РФ MMM-практике стандартная единица времени = **месяц**, не неделя как в US/EU. Default Aurora UX = monthly grain; weekly — auto-adapt option. Adstock priors per Aurora уже calibrated monthly (verified pre-flight H5).

### 9. Industry parity reached

Aurora v2.0.0 — **competitive parity с Robyn в math depth**: signed factors / sensitivity tornado / backtest validation / MCMC diagnostics / holiday auto-inject. Premium UX поверх (Wizard, dual-mode, премиум tier-1 styling).
